## The one samen_core change (data-only, forced by the built substrate)

The design's DECISION AB assumed a **per-app** abbrev registry so Driftwood could keep the
scope-default abbrevs. The BUILT substrate reads a single GLOBAL registry
(`Samen.AbbrevRegistry.load/0` → `:code.priv_dir(:samen_core)/abbrev_registry.json`), in
which `cmp/per/pip/opp/act/att` are already owned by the demo mount. Two hosts mounting the
same scope with default abbrevs therefore COLLIDE at the compile-time
`Samen.Verifiers.AbbrevRegistry`. Resolution (no samen_core CODE touched):
1. Driftwood's mounted CRM resources take FRESH abbrevs `fcm/fpr/fpp/fop/fac/fat` via the
   blueprint's `abbrevs:` override (a documented design-§0 seam).
2. Those abbrevs + the vertical `drv/stl/dsp` were APPENDED (data-only) to
   `samen_core/priv/abbrev_registry.json`. This is the only edit under `samen_core/`; it is
   append-only, does not change any existing row, and samen_core's own 768-test suite stays
   green. **This is a real finding for the extraction retro (T6.1): the abbrev registry is
   global-to-samen_core, not per-host — DECISION AB does not match the substrate as built.**

## Substrate-forced adaptations (documented, honest)

- **`cdl_expiry` stored as ISO-8601 TEXT** (not `:date`). The substrate's `non_pii!` redaction
  arm writes a TEXT sentinel over the plaintext on erasure (only works against a text column).
  A DATE column cannot take the sentinel (Postgrex encode error). So the CDL validity date is
  stored as ISO text; the gate parses it via `Date.from_iso8601/1`. The crypto-shred test then
  erases it end-to-end. `medical_card_expiry` stays `:date` (not flagged, erased by row deletion).
- **`org_id` on the gated `:dispatch` action** is set from the actor (`set_attribute(:org_id, actor(:org_id))`) — the substrate does not auto-derive org_id from the actor on create.

## Scope decision (honest reduction vs the design's 5 deep scopes)

The design (§1) names Identity/CRM/Billing/Support/Primitives as deep. T5.2 mounts **CRM**
(required for Carrier/Shipper/Load aliases, the Driver→Company FK, and every red path) plus the
vertical Freight resources. **Billing/Identity/Support/Primitives mounting is deferred:** the
Settlement resource reuses Billing *idioms* (integer-cents money, currency, status enum, a
`belongs_to`-shaped carrier FK) but not the Billing *tables* (DECISION S authors a vertical
`Settlement`, not a reshape of kernel Invoice), and Identity/Support/Primitives are already
proven end-to-end in demo — re-mounting them adds migration surface but no NEW guarantee for
this task's red paths (settlement math, FMCSA gate, CDL vault, cross-org). This is a deliberate,
stated reduction (blocked/partial beats false green), not a silent drop; those mounts are a
follow-up for T5.3 when the tenant UI/operator plane needs them. Marketing/CMS stay declared-unused
per the design.

  proving the tests check the real netting arithmetic against an independent reference, not a
  tautology. Reverted; settlement suite green again (6 passed).
