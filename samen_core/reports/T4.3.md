## Design decisions (per ADR-002)

- **Chain scope: per-org** (§2.1). Rejected a single global chain for independence (one
  org's tamper must not fail another's verify), confidentiality (a global chain leaks
  other orgs' event existence/ordering/rate to any verifying tenant), and contention (one
  hot tip row serializes every platform write). Org-less operator/system events ride a
  reserved `"__global__"` partition — a distinguished chain, not a null, so no audit row
  is ever un-chained. Honest residue stated: no cross-org total order (the doc claims
  none).
- **Storage: linked table `aud_chain`** (§2.2), not columns on the RANGE-partitioned
  `aud_event` (whose partition is chosen by time, not chain position).
- **Hash covers a ciphertext DIGEST, not plaintext** (§2.3–2.4): `hash = SHA256(prior_hash
  <> canonical_json(tokens || ciphertext_sha256))`. So a shred (which destroys the DEK,
  leaving the ciphertext bytes) does not change any hashed input → the chain still
  verifies post-shred while `ach_subject_ciphertext` becomes undecryptable.

## Red paths (all must-fail, all confirmed failing-closed)

1. **Payload tamper** — editing `ach_detail` out-of-band → `verify_chain` →
   `{:error, {:hash_mismatch, seq}}`.
2. **Hash tamper** — editing `ach_hash` → detected.
3. **Delete** — deleting a middle entry → `{:error, {:seq_gap, n}}`.
4. **Append-only** — `UPDATE`/`DELETE` on `aud_chain` raise the trigger (`~r/append-only/`).
5. **Wholesale rewritten-history** — drop the chain, rebuild a doctored past from scratch;
   the rebuilt chain internally `verify_chain`s CLEAN, but `verify_against_anchor` →
   `{:error, :anchor_divergence}` (the sealed head in the WORM store the attacker does not
   control does not match). Also `:truncated_below_anchor` for rollback below a seal.
6. **Post-shred** — chain STILL verifies while `Kms.unwrap(subject) → {:error, :shredded}`
   (subject ciphertext undecryptable, the surviving event row proves "the event happened").
7. **LocalWorm in-file edit** — a tampered anchor line fails its content-hash check on read
   → skipped, `read_head → :none` (does not silently become the trusted head).
8. **Oracle red paths** — a seeded plaintext PII-named column (`ach_email`) and an
   unrecognised plaintext column (`ach_extra_note`) each FAIL the `aud_chain` tier.
9. **S3 skeleton** — `seal`/`read_head` raise (disabled AND enabled-unimplemented), never
   fake a pass.

## Anti-tautology probes (HARD RULE 2)

- **In-test known-bad-input probes** (`test/audit_chain_test.exs` §j/§k): `verify_entries`
  rejects a hand-built entry with a wrong stored hash and a broken-link entry; the anchor
  comparison flags a forged divergent sealed head (positive control: a matching head →
  `:verified`).
- **Code-sabotage probes** (project-local scratch dir `.t43_antitaut_scratch/`, since
  removed):
  - Sabotaged `do_verify/4` to always continue → **6 tests flipped to FAILING** (payload
    tamper, hash tamper, seq-gap, TenantView tamper detection, both §j probes); green-path
    + anchor-only tests stayed green. Reverted → `diff` identical, 0 `SABOTAGED` markers.
  - Sabotaged `verify_against_anchor/2`'s `cond` to always return `{:ok, :verified}` →
    **3 tests flipped to FAILING** (rewritten-history, truncation-below-anchor, §k
    divergence probe). Reverted → `diff` identical, 0 `SABOTAGED` markers.
  - **Result:** both `verify_chain` and the anchor comparison are non-vacuous
    discriminators, not always-passes. Scratch dir removed; both suites re-run green.

## WORM/S3 seam honesty (plan HARD rule)

No AWS/S3 in this environment. The anchor ships as: a **behaviour** + a **faithful local
adapter** (`LocalWorm`, fsync + verify-on-read, exercised by tests) + a **production
skeleton** (`S3ObjectLock`, Object Lock COMPLIANCE mode, config-flagged, raises operator
TODO, never exercised in CI). Never a faked pass. The honest window is documented (ADR-002
§3.3): events written after the last seal and before detection are anchored only at the
next seal; the `*/5` cadence bounds it.
