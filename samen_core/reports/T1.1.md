# T1.1 — Productionize `Samen.Resource` in `samen_core`

**Status:** GREEN. 35 tests (33 unit/integration + 2 property) pass under
`mix test --warnings-as-errors`. All red paths verified load-bearing via
anti-tautology probes.

## Scope delivered

Created the `samen_core` mix project (deps ash 3.29.3, ash_postgres 2.10.0,
spark 2.7.2, ecto_sql 3.14.0, postgrex 0.22.2, jason, stream_data — all pinned to
`spikes/s00_smoke/VERSIONS.md`; test-support repo `SamenCore.TestRepo`), and ported +
productionized from `spikes/s02_transformer` and `spikes/s03_fragments`:

- **(a) Abbrev storage transformer with the ordering fix** (`lib/samen/transformers/abbrev_storage.ex`)
  — `after?(BelongsToAttribute) -> true`, `before?(_) -> true`. Gate-0 fix #2.
  Synthesized FK columns are prefixed AND reference the composed table's prefixed
  PK (generated DDL: `com_company_id -> references(:cpy_company, column: :cpy_id)`,
  `pat_primary_provider_id -> references(:stf_staff, column: :stf_id)`).
- **(b) First-class `samen do abbrev "com" end` DSL section** (S0.2 note F4) —
  `lib/samen/extension.ex` defines the section; `lib/samen/info.ex` reads it back
  via `Samen.Info.abbrev/1` (introspectable, survives fragment folding — not a
  module attribute). `use Samen.Resource, abbrev: "com"` is sugar for the section.
  Opt-out convention F2 preserved in the transformer: prefix when
  `source in [nil, name]`, honor an explicit `source:` verbatim.
- **(c) Fragment `base:` composition + extension allow-list gate** (Gate-0 fix #3)
  — `lib/samen/resource.ex` `verify_fragment_extensions!/2` uses
  `Code.ensure_compiled/1` (not `ensure_loaded?/1`) to force the fragment to
  compile before reading `extensions/0`, then rejects any Samen-namespace
  extension outside `[Samen.Extension, Samen.Pii, Samen.Catalog]`. Red-path fixture
  `SamenCore.RedPathFixtures.RogueFragment` (declares un-provided `Samen.Audit`)
  fails compile.
- **(d) Abbrev REGISTRY** — committed `priv/abbrev_registry.json` +
  `lib/samen/abbrev_registry.ex` (pure `validate/3` decision fn + fail-closed
  loader) + compile-time enforcement. Abbrevs are permanent, 3-letter lowercase,
  collision-checked, never recycled. Two resources claiming the same abbrev, an
  unregistered abbrev, or a changed abbrev each fail compile.
  - **Design note (deviation from the plan's suggested "Spark verifier"):** a Spark
    verifier that raises during `Code.compile_string` does **not** reliably abort
    the compile in Ash 3.29.3 / Spark 2.7.2 (empirically confirmed — the DslError
    is logged but the module still compiles). So the hard fail-closed enforcement
    is done **caller-side in the `Samen.Resource` macro** (`validate_registry!/2`),
    which raises a `CompileError` at the resource's `use` line and reliably aborts.
    `Samen.Verifiers.AbbrevRegistry` is kept as defense-in-depth + introspection.
- **(e) Injected `id`/`org_id`/`inserted_at`/`updated_at`** on every resource
  (`lib/samen/transformers/core_attributes.ex`), each prefixed. Additive/idempotent
  (declare a column yourself to opt out). Timestamps are `:utc_datetime` to match
  the AshPostgres-generated column type.
- **Property test** (`test/abbrev_property_test.exs`): (1) ∀ arbitrary attribute
  names → `source == :"<abbrev>_<name>"` and logical name untouched, via the real
  `use Samen.Resource` path (fixed registered module `SamenCore.Support.PropGen`
  recompiled per run); (2) ∀ arbitrary string values → create/read round-trips via
  logical names through the prefixed physical columns (Postgres-backed).

## Anti-tautology probes (all reverted after)

1. **Registry** — sabotaged `AbbrevRegistry.validate/3` to always `:ok`: the 2
   registry red-path tests FAILED (1/3 passed, only the control). Reverted.
2. **Fragment extension gate** — neutered `verify_fragment_extensions!/2` to `:ok`:
   the "un-provided extension fails compile" red path FAILED (3/4 passed). Reverted.
3. **Abbrev prefixing** — no-oped the transformer's `prefix_attribute` for the
   `source in [nil, name]` clause: 7 tests + both properties FAILED (9/18 passed).
   Reverted.
4. **FK ordering fix** — flipped `after?`/`before?` so the transformer no longer
   runs after `BelongsToAttribute`: the generated FK column came out UNprefixed
   (`:company_id`, `com_contact_company_id_fkey`) and the 2 FK red-path tests
   FAILED. Reverted; migration regenerated correctly.

Every guarantee's red path is proven load-bearing.

## Caveats / carry-forwards

- The `prefixes` verifier (T1.8a) remains the required fail-closed backstop for the
  abbrev idiom — ordering alone cannot stop a hypothetical future attribute-adding
  transformer running after Samen (S0.2 caveat F1). Noted in the transformer doc.
- `Samen.Pii` / `Samen.Catalog` are T1.1 baselines (PII materializes to a plain
  `sensitive?: true` column; Catalog is a marker). The real vault (T1.4), composite
  types + mask-unknown-by-default (T1.3), and the generated `tam_table`/`fld_field`
  written in the migration tx (T1.2) are downstream tasks that extend these.
- The abbrev pattern is strict 3-letter lowercase (`^[a-z]{3}$`) to match the
  registry's permanence rule (the spikes allowed 2-5). All fixtures use 3-letter
  abbrevs.
