## Gate-0 fix task #6 — each clause, and its proof

**(a) Reveal-scope keys on the REAL Ash `:reveal` action, not the lexical prefix.**
Suppression happens ONLY inside `action :name do … end` where `:name` is a
**declared** reveal action, resolved via `Samen.PiiReads.Registry.reveal_action?/3`
← `Samen.Pii.Info.reveal_actions/1` (the persisted first-class
`Samen.Transformers.RevealActions` marker). No `def` and no name-prefix ever
suppresses. The spike's `reveal_report` evasion is now a **red-path corpus case**
(`closed_evasions.ex` E1) and is CAUGHT:
- E1 `def reveal_report(p), do: Logger.info("ssn=#{p.pii_pat_dob}")` → flagged.
- E2 `def reveal(s), do: IO.puts(s.emails)` (exact name `reveal`) → flagged.
- E3 `action :reveal_report do …` never declared `reveal :reveal_report` → flagged.
- The genuinely-declared `action :reveal_email` on the real `RevealPerson`
  resource IS suppressed (clean corpus, exit 0), including the exact on-disk
  `action :name, :return_type do` shape.

**(b) Aliased sink modules resolved from module context.** `alias Logger, as: L`
then `L.info(...)` resolves to `Logger.info` and is flagged (E4); same for
`alias OpenTelemetry.Span, as: S` (E5). Multi-segment head aliases
(`alias OpenTelemetry, as: O` then `O.Span`) resolve too. An aliased Logger
carrying a NON-pii token does not false-positive.

**(c) PII registry from `Samen.Pii.Info` (no stub).** The taint set is the union
of every configured resource's logical `pii_attribute` names AND their physical
storage names (`Samen.Pii.Info.pii_attributes/1` + `vault_routed_columns/1`), so a
composite field like `pat_full_name` (no `pii_` prefix) is caught — keying on the
DECLARATION, not a prefix. Resources are discovered from `:ash_domains` (same
source as `Samen.Catalog`); tests inject an explicit registry built from the
`Patient` + `RevealPerson` fixtures.

**(d) Laundered flows remain documented expected-misses; J2 cited when cheaply
detectable.** A pure AST match cannot see a pii read after a helper hop — the 3
`laundered/` cases are expected misses (exit 0, they never fail the build). When a
pii read is passed to a KNOWN local helper the walker emits an advisory
`:laundered_hint` whose diagnostic cites the J2 sink-schema allow-list (Phase 2,
T2.7). Hints NEVER affect the exit code.

**Kept from the spike:** fail-closed exit codes (`:erlang.halt/1` via
`Samen.Verifier.halt_if_violations`); parse errors are `:parse_error` findings
that fail closed (never silently skipped); `pii do … end` declaration sites are
structurally skipped and never flagged.

## Honest edges / carve-forwards

- **Laundered leaks are unprovable by the AST layer, by design.** The J2 sink-schema
  allow-list (T2.7, Phase 2) is the named backstop; the T1.8b "laundered leak"
  fixture is expected to be caught THERE, tested together in Phase 2 (per the plan
  row). This module emits `:laundered_hint` advisories citing J2 where the hop is
  cheaply detectable (call to a known local helper carrying a pii read); a hop
  through a truly opaque non-local call is not hinted and remains a silent expected
  miss.
- **Registry scope = configured `:ash_domains`.** The mix task's default registry
  covers exactly the host's declared domains. The `RevealDomain` fixture is
  deliberately NOT in `:ash_domains` (it has no migrated table, which would break
  `catalog_parity`), so the task-corpus subprocess tests use a
  RevealDomain-independent clean corpus; the reveal-suppression behavior against a
  real declared reveal action is proven in the unit suite with an injected registry.
- **`reveal_action?/3` with a nil module** (walker could not resolve the enclosing
  `defmodule`) falls back to the UNION of all declared reveal actions — a
  conservative allowance that still refuses undeclared names (so `reveal_report` is
  never suppressed), avoiding over-flagging a legitimately-declared reveal action in
  a file scanned without a resolvable module binding. In practice every corpus/real
  file resolves its module, so this path is not exercised by the leak/clean sets.
