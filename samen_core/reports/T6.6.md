## What is ENFORCED vs POSTURE (the honest line, stated exactly)

### ENFORCED today (real, opt-in)
1. **k-anonymity + l-diversity FLOORS** (T4.5, unchanged) — every single-query output is
   floored: count-of-one / sub-k cohorts and homogeneous (< l distinct) cohorts suppress.
2. **Query-budget ENFORCEMENT** (T6.6, NEW) — a configurable **per-cohort** (and
   **global**) read budget that DENIES (suppresses) further aggregate reads of a cohort
   once its budget is spent within the rolling window. Keyed per-COHORT, never per-actor
   (the doc names per-actor as the wrong unit vs collusion). **Opt-in** (`:query_budget_enforce`,
   default `false`) — off preserves the exact T4.5 accounting-only behaviour.
3. **DP noise MECHANISM** (T6.6, NEW) — a correctly-calibrated Laplace mechanism
   (`Samen.Aggregate.Dp`) adds noise to released aggregate counts. **Opt-in**
   (`:dp_enabled`, default `false`). The noise is genuine (distribution-tested), not a stub.

### POSTURE under construction (named, NOT claimed as solved)
- **Formal DP composition guarantee.** The enforcing budget is a coarse, deterministic
  read-COUNT budget ("N reads per cohort per window") — NOT an epsilon-budget with a
  proven composition bound. The DP noise layer degrades under composition (every noisy
  answer spends privacy; averaging many noisy reads recovers the true count). A running
  ε-budget that DENIES on formal exhaustion is NOT implemented. The deterministic count
  budget BLUNTS the noise-averaging attack in practice (it caps reads/cohort), but it is
  not the same object as a composed ε-budget. Both facts are in the `Dp` and `QueryBudget`
  moduledocs.
- **t-closeness** (bounding a cohort's sensitive-value distribution vs the overall) —
  NOT implemented; named on the same open track.

The moduledocs (`Samen.Aggregate.Dp`, `Samen.Aggregate.QueryBudget`) and the demo config
comments say this in the same words. There is deliberately no config flag that would let a
host flip on the FORMAL DP guarantee — the flags turn on a deterministic budget and a
noise mechanism, nothing more.

## Red paths (all fail closed / block, tested)

1. **Budget-exhausted cohort SUPPRESSES.** `query_budget_enforcement_test.exs`: with a
   per-cohort budget of 2, reads 1–2 serve, read 3 → `{:deny, %{scope: :per_cohort,
   observed: 3, limit: 2}}`; and STAYS denied. Demo end-to-end: a repeated read of an
   ABOVE-k cohort (Team, 3 tenants — the k-anon floor does NOT stop it) is SUPPRESSED with
   `%Suppressed{reason: :query_budget, limit: 1}` on the second read.
2. **Collusion hits the SAME cohort budget → SUPPRESSED.** `query_budget_enforcement_test.exs`
   + `aggregate_differencing_test.exs`: two DISTINCT actors reading the SAME cohort share
   ONE per-cohort budget — actor-2's read (past the shared budget of 1) is DENIED /
   SUPPRESSED, NOT served a fresh per-actor budget. Proves the doc's "per-actor is the
   wrong unit" claim as an ENFORCED outcome (T4.5 could only account it).
3. **DP noise present when enabled (distribution test).** `dp_test.exs`: with DP on,
   `noisy_count` produces a genuine spread (> 10 distinct values over 2000 draws, not all
   equal to the true count); the noise matches `Lap(b = Δq/ε)` (empirical mean ≈ 0,
   variance ≈ 2b² over 20k draws); smaller ε ⇒ measurably more noise; off by default =
   identity pass; clamps ≥ 0.
4. **Differencing BLOCKED (the clause-(c) test).** `aggregate_differencing_test.exs`
   category (5): the above-floor cohort that T4.5's differencing test could only RECORD is
   now BLOCKED by the enforcing budget — the repeated/overlapping read that isolates a
   subject is suppressed with `reason: :query_budget`. The complementary "enforcement OFF
   → residue unchanged" test proves the honest T4.5 behaviour is preserved when not opted in.
5. **Global budget denies past a cross-cohort cap.** `query_budget_enforcement_test.exs`:
   a global budget of 2 denies the 3rd read across ANY cohort (the doc's "global" arm),
   even when each per-cohort count is below its own budget.
6. **Fail-OPEN on ledger error.** `query_budget_enforcement_test.exs`: pointing the ledger
   repo at a raising module makes `check/2` rescue to `:ok` (the plane stays up; the floors,
   which fail closed, remain the single-query defence). Deliberate: the cross-query budget
   is layered on top of the floors, not the fail-closed keystone.

## Design notes / doc parity

- **Opt-in, off by default — the doc's honesty preserved either way.** Enforcement and DP
  are both OFF unless a host opts in. A host running the T4.5 config sees IDENTICAL
  behaviour (the enforcement path is a no-op `%{}` denied-set; DP is an identity pass).
  Flipping the flag does NOT let the moduledoc claim more than "a deterministic read-count
  budget" and "a single-release Laplace mechanism" — the FORMAL DP composition guarantee
  is never claimed.
- **Per-cohort, not per-actor — now ENFORCED, not just accounted.** T4.5 proved the
  ledger counts per-cohort. T6.6 proves the DENIAL is per-cohort: two colluding actors on
  one cohort share one budget and the second is suppressed. `check/2` takes no actor.
- **First suppression wins (budget → k-anon → l-div).** A budget-denied cohort is
  suppressed BEFORE the floors run; `Privacy.apply` leaves an already-`%Suppressed{}` value
  alone (it is no longer a releasable number). The reason on the sentinel reflects WHY
  (`:query_budget` vs `:k_anonymity` vs `:l_diversity`).
- **Fail-open budget vs fail-closed floors — deliberate and stated.** The budget is the
  CROSS-QUERY layer on top of the single-query floors. A ledger outage must not take down
  the aggregate plane, so `check/2` fails open; the floors (which fail closed, independent
  of the ledger) still protect every single query. This is NOT a weakening — it is the
  correct layering (the same reason a rate limiter failing open still leaves auth intact).
- **DP honesty (the sharpest edge).** `Samen.Aggregate.Dp`'s moduledoc spends more words
  on what a single ε-DP release does NOT guarantee (system-level composition) than on what
  it does. The averaging attack is named. The deterministic budget's role (blunting it in
  practice, not proving it) is named. t-closeness is named as unimplemented. We ship the
  mechanism, not the proof.

## Carries / open items (still posture under construction, T6.6+)

- **Formal ε-budget composition:** track cumulative ε spent per subject/dataset across
  queries; DENY on formal exhaustion (the DP analogue of the deterministic budget). Wire
  the DP layer's ε-spend into the same accounting as the read-count budget so the two
  cannot be alternated to dodge either. Requires a proven sensitivity bound per released
  query (not just plain counts).
- **t-closeness:** bound a cohort's sensitive-value distribution vs the overall
  distribution (the stronger distributional defence beyond l-diversity).
- **DB-level suppression (a T4.5 carry, still open):** a `WHERE cohort_count >= k` view or
  policy filter would harden the floor beyond the read-chokepoint convention. The
  enforcing budget shares the same chokepoint dependency (`Samen.Aggregate.read_all/2` is
  the sole operator-facing path; a caller holding the aggregate actor could `Ash.read`
  directly and bypass BOTH the floors and the budget — the same honest seam as
  `Samen.Vault.reveal` being the sole plaintext path). Stated, not hidden.
