## Scope delivered

### (a) One canonical wide event per request/action — `Samen.WideEvent`

`Samen.WideEvent` (`lib/samen/wide_event.ex`) carries the exact doc §runs-4b field set:
`request_id, trace_id, span_id, tenant_id, actor_id, action, op, table, row_count, duration_ms,
queue_depth`. The `operation summary` is decomposed into bounded fields — `op` (enum:
select/insert/update/delete/none), `table` (opaque_id — the abbrev-qualified catalog table name,
**never SQL text**), `duration_ms` (number) — "operation + table + duration, not SQL text", consistent
with `db_statement: :disabled`.

Emitted via `:telemetry.execute([:samen, :wide_event], measurements, metadata)`; sink adapters attach
as telemetry handlers. `new/1` validates every field against the schema at build time (runtime half of
J2) and REJECTS unknown fields + name-shaped values in bounded fields; `emit/1` re-validates
(defence-in-depth for a struct-smuggled value).

### Sink adapters (`lib/samen/wide_event/sinks/`) + TTL (d)

| Adapter | File | Retention / TTL |
|---|---|---|
| **InMemory** | `sinks/in_memory.ex` | `GenServer` **bounded ring buffer** (`max_events`, default 10k); oldest dropped — never grows unbounded |
| **File** | `sinks/file.ex` | JSONL; **prunes lines older than `ttl_seconds`** (default 7d) on every write — deterministic, background-free |
| **OTLP** | `sinks/otlp.ex` | Honeycomb-shaped flat-attr **skeleton**; TTL is the third-party backend's dataset retention (documented seam; see simulation seam below) |

Retention config: `Samen.WideEvent.Retention` (`lib/samen/wide_event/sink.ex`), reads
`config :samen_core, :wide_event_retention`.

### (b) THE J2 BUILD-TIME SCHEMA CHECK — `Samen.WideEvent.Schema` + `mix samen.verify.sink_schema`

`Samen.WideEvent.Schema` (`lib/samen/wide_event/schema.ex`) declares every wide-event/span field with a
**bounded type** (`:opaque_id | :token | :enum | :number`). `Schema.violations/1` is a pure function
that fails on any field typed `:string`/`:binary`/`:map`/`:any`/… (a name-carrier) or an `:enum` with no
closed `allowed:` set.

`mix samen.verify.sink_schema` (`lib/mix/tasks/samen.verify.sink_schema.ex`) runs it and exits 1 on any
violation (via `Samen.Verifier.halt_if_violations`). **Wired into `demo/ci.sh` as step 8/8.** The SAME
check is folded into the `no_plaintext_pii` oracle roster via
`Samen.NoPlaintextPii.Tiers.TraceSink` (`no_plaintext_pii/tiers/trace_sink.ex`) — one schema, two entry
points (the build check AND the destruction oracle, CI + T2.9 post-shred).

**Laundered-leak proof (the load-bearing requirement).** `test/wide_event_j2_laundered_test.exs` proves
the layered design against the T1.8b laundered fixture (`Corpus.Laundered` LA1–LA3):
- **STEP 1** — C3 `pii_reads` MISSES the laundered corpus (only a `:laundered_hint` advisory) — the
  documented expected miss C3 flagged.
- **STEP 2** — J2 has NO string field for a laundered name to land in, and fails the build if one is added.
- **STEP 3** — the exact laundered plaintext (`"Alice Anders"`, a name with a space) is REJECTED at every
  bounded wide-event field (opaque_id/token reject whitespace; number rejects non-numbers; unknown-field
  reject; `:action` requires an atom).
- **STEP 4** — `emit/1` re-validates a struct-smuggled name and refuses.

So J2 catches what C3 documented as an expected miss.

### (c) `actor_id = HMAC(psk_S, subject_id)`, `psk_S = HKDF(DEK_S, "samen/obs-pseudonym/v1")`

`Samen.WideEvent.for_subject/2` calls the configured `Samen.Kms` adapter's `pseudonym/2` (wired from
T1.4 — `Kms.pseudonym(subject_id, subject_id)`), which delegates to `Crypto.pseudonym/2`
(HKDF→HMAC over the subject's DEK, ADR-001 §2 RQ5). The actor_id is a `:token`-typed field, unlinkable
on key destruction.

**Red path (post-shred unlink), ported UP to the wide-event layer** —
`test/wide_event_pseudonym_test.exs`: pre-shred the actor_id is stable, opaque, contains no subject id,
and matches `Vault.pseudonym/1`; **post-shred `WideEvent.for_subject/2` returns `{:error, :shredded}`**
(recompute impossible — the DEK it is keyed on is gone). Distinct subjects get distinct pseudonyms.

### Anti-tautology probes (sabotage in a self-created subdir OUTSIDE /tmp root, confirm, revert)

Probe dir: `samen_core/_probes/t2_7_anti_tautology/` (created, used to hold `.bak` backups, cleaned up).
Backups restored the exact original bytes after each probe.

1. **(b) J2 schema check** — sabotaged `Schema.bounded_type?/1` to always return `true`. Result: **3
   red-path tests FAILED** (seeded string field, map/binary/any fields, the STEP-2 J2 backstop) — the
   check is discriminating. Reverted → 20 tests green.
2. **(c) pseudonym keying** — sabotaged `Crypto.pseudonym/2` variant A (ignore subject_id, return a
   constant). Result: the "distinct subjects → distinct pseudonyms" red path **FAILED** — keying is
   load-bearing. Reverted → 4 tests green.
   - Variant B (ignore the DEK, key on subject_id with a fixed HMAC key) did **not** fail the wide-event
     unlink test — an **honest finding**: the post-shred unlink at the ADAPTER path is enforced by the
     adapter's `unwrap()` gate (returns `:shredded` post-shred) independent of `Crypto`'s derivation. The
     DEK-derivation itself is red-path tested at the Crypto layer (T1.4 `kms_crypto_test.exs`). Variant A
     is the discriminating probe at the wide-event layer; the unlink guarantee is doubly enforced
     (adapter gate + DEK-keyed derivation).
3. **(e) F2 sink inventory** — removed the `:telemetry` sink from `@erlang_module_sinks`. Result: the C3
   corpus catch rate dropped to **94.1% (< 100%)** — the F2 corpus is load-bearing. Reverted → 21 tests
   green.

## Simulation seam (no live OTLP/Honeycomb in this environment)

The **OTLP sink is a skeleton**: `Sinks.Otlp.shape/1` produces the Honeycomb-style flat-attribute form
(`samen.request_id`, `samen.op`, … — bounded values only), then dispatches to a configured **export
function** (`config :samen_core, :wide_event_otlp, export: fn attrs -> … end`), defaulting to a no-op.
No network connection is opened.

**Operator TODO:** wire a real `opentelemetry_exporter` OTLP endpoint and set the export fn to ship to
Honeycomb/Tempo. OTLP-sink TTL is the third-party backend's dataset retention (Samen cannot prune
Honeycomb) — `Sinks.Otlp.retention_note/1` documents this. This is the doc's "one seam this sink has that
the in-Postgres tiers don't: it is third-party and append-only, so key-shred cannot reach it" — which is
exactly why `actor_id` is a KMS-keyed pseudonym that unlinks on shred (ingress-class, not
destruction-class).

Test seam: `mix samen.verify.sink_schema` honors `SAMEN_SINK_SCHEMA_INJECT_STRING_FIELD` (test-only) to
prove the subprocess exit-1 red path without mutating the schema source. Absent in every real invocation.
