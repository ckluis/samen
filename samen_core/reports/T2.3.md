## What shipped

### (a) Rollup framework
- `Samen.Rollup.Spec.from_config/1` (new): builds + **fail-closed validates** a
  `%Spec{}` from a plain config map (missing key, blank string, bad `rebuild_sql`
  shape, or a `subject_column`/`suppressed_column` not in `bounded_columns` all
  raise). Config registry moved to plain maps (`config :samen_core, :rollups`) in
  both `samen_core` and `demo` — this is the fix for the broken build.
- `Samen.Rollup.rebuild_all/1` / `refresh/2`: truncate + recompute each rollup from
  raw `aud_event` in one tx. Dashboards read the small `rol_daily_event_count`
  table, never scan raw events.
- `Samen.Jobs.RollupRefreshWorker` (rewritten): the `*/10 * * * *` cron worker now
  actually calls `rebuild_all/1` (was a heartbeat), resolves its repo from Oban
  config, fails closed (`{:error, :no_repo_configured}`) with a diagnostic when no
  repo is configured, and supports an `args["rollups"]` subset.

### (b) THE ERASURE POLICY (rebuild-or-exclude-on-erasure)
- `Samen.Rollup.erase_subject/3` chooses ONE arm per rollup via `raw_retained?/3`:
  - **REBUILD arm** (raw retained): delete the subject's raw `aud_event` rows
    (through the sanctioned erasure path — `SET LOCAL session_replication_role =
    replica` scoped to the tx, then restored), then recompute the rollup
    subject-free. The subject is *gone*, not masked.
  - **SUPPRESS arm** (window archived/detached): flip `rol_suppressed = TRUE` on
    the subject's derived rows (compared on `::text` so it is robust to the
    physical subject-column type). The cohort stat survives (doc: not retroactively
    scrubbed) but is flagged.
- **Wired into T1.7:** `Samen.Erasure.shred/2` now runs `erase_subject/3` as a Multi
  step INSIDE the erasure transaction (commits atomically with the vault sentinel /
  non_pii! redaction / audit / report), and folds the per-rollup arm report into the
  erasure report artifact under `tiers["rollups"]` — the artifact the T2.9 oracle
  consumes. Shred accepts `:raw_retained?` / `:specs` opts (forwarded to the policy).

### (c) Rollup as a no_plaintext_pii tier
- `Samen.NoPlaintextPii.Tiers.Rollup` added to `default_tiers/0` (it existed but was
  never in the roster). CI mode asserts every registered rollup table carries only
  token / bounded-ID / count / enum / timestamp columns — a plaintext PII-named
  column, an unrecognised plaintext column off the allow-list, a missing backing
  table, or no repo all FAIL closed.

### Demo dogfood

  `demo/test/rollup_dogfood_test.exs` (5 tests) exercises rebuild + suppress arms

## Simulation seams (documented, not faked)

- **Archived/detached window (suppress arm):** this environment has no detached
  partition, so the arm is forced via `raw_retained?: false` (a documented option
  on `Samen.Rollup.raw_retained?/3` and `Erasure.shred/2`). The production
  mechanism — a detached partition is invisible to `SELECT ... FROM aud_event`, so
  `raw_retained?` returns false automatically — is implemented and unit-tested via
  the auto path (`raw_retained?/3` returns true iff attached raw rows exist).
  **Operator TODO:** exercise the suppress arm against a physically detached
  partition in the T2.5/T5.x PITR game-day.
- **Rollup subject linkage type:** the demo/kernel `rol_subject_id` is `UUID`; the
  suppress arm compares on `::text` so a non-UUID subject simply matches 0 rollup
  rows (never a crash). The config rebuild INSERT casts `aud_subject_id::uuid`,
  which requires rollup subjects to be UUIDs — correct for the demo contract.
