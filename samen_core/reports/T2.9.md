## What shipped

The `mix samen.verify.no_plaintext_pii` task now has TWO modes on one command:

- **CI mode (unchanged):** the token-only-downstream invariant over every projected
  tier. Runs exactly as before; the vision §runs CI gate is untouched.
- **Post-shred mode (NEW):** `--subject <uuid> --tiers all` orchestrates the three
  checks the doc's oracle block mandates, plus the ingress-class trace-sink
  assertion and the inactive CDC-mirror stub.

### The three orchestrated checks (doc oracle block, line by line)

1. **DB-TIER CONTENT SCAN** — `PostShred.DbContent`
   (`samen_core/lib/samen/no_plaintext_pii/tiers/post_shred/db_content.ex`).
   Scans **live · replica · rollup · audit · registered_non_pii** for the erased
   subject. FAILs on decryptable plaintext OR **ciphertext that decrypts under any
   key other than the destroyed one** (the wrong-key probe). Uses
   `Samen.Vault.scan_no_plaintext/2` (own-key), `Samen.Vault.scan_no_wrong_key/2`
   (foreign live keys), `Samen.NonPii.unredacted_columns_for_subject/3` (redaction
   ran), and the erasure report's per-rollup rebuild-or-exclude arm (every
   registered rollup governed). The **replica is SIMULATED** (no physical replica
   in this env): pass `replica: RestoredSnapshotRepo` (a second DB restored from a
   live snapshot) or `replica: :none` to state there is none; an undeclared replica
   in a `--tiers all` run **fails closed** (silence is not an all-clear). Real
   streaming replica = operator TODO.

2. **BACKUP/PITR-HISTORY SCAN** — `PostShred.BackupPitr`
   (`.../post_shred/backup_pitr.ex`). Asserts the subject key is absent from every
   DB tier + PITR history (`Samen.Vault.scan_pitr_key_absent/2`: no
   key-material-shaped column on `pii_vault`; no ciphertext decrypts) AND
   `backups_disabled?/0 == true` on the store. The **PITR history is SIMULATED**
   with the pg_dump→restore snapshots from T2.5's drill machinery
   (`docs/runbooks/pitr-gameday-sim.sh`): pass them as `pitr_repos: […]`. With no
   `pitr_repos`, the live-tier key-absence assertion holds and the PITR-snapshot
   scan is a documented operator seam. Real Neon branch-and-restore = operator TODO
   (`docs/runbooks/pitr-gameday.md`).

3. **KMS DESTRUCTION ATTESTATION** — `PostShred.KmsAttestation`
   (`.../post_shred/kms_attestation.ex`). Reads the KMS as system of record via
   `attest/1` and **requires a positive `:shredded` tombstone**. `:absent == FAIL`
   (positive tombstone required, not mere absence); `:active == FAIL`. Plus
   defence-in-depth `key_material_present?/1 == false` (a tombstone over a surviving
   DEK is a false attestation) and `backups_disabled?/0 == true` (ADR-001 CI
   check 2).

### Plus

- **trace_sink INGRESS-class** — `PostShred.TraceSinkIngress`
  (`.../post_shred/trace_sink_ingress.ex`). A **schema assertion, not a content
  scan** (per the doc): `Samen.WideEvent.Schema.violations/0` admits only bounded
  ID / token / enum / number fields — a smuggled `:string` field is a violation.
  Also asserts the `actor_id` pseudonym unlinks on shred (`Vault.pseudonym/1`
  fails `:shredded`, riding oracle check 3, RQ5).
- **cdc_mirror STUB** — `PostShred.CdcMirror` (`.../post_shred/cdc_mirror.ex`).
  Registered so the tier map matches the doc; inactive (Phase-6 H4 / T6.5). If a
  `:cdc_mirror_repo` is ever configured but unscanned, it **fails closed** (a
  configured-but-unscanned mirror is a gap, not a pass).

### Supporting changes

- `Finding` gains a `:pass` severity — positive post-shred attestations (the
  "what you show an auditor" evidence). Listed, never fails the build. Post-shred
  tiers NEVER return an empty list (fail-closed discipline: a tier must speak).
- `Context` gains `subject_id`, `replica_repo`, `pitr_repos`,
  `replica_declared_absent?`.
- `Samen.Kms` gains an OPTIONAL `list_active_subjects/0` callback (InMemory +
  FileBacked implement it; AwsKmsDynamo returns `:unsupported` — a per-run DynamoDB
  Scan is not free, so the wrong-key probe is an operator TODO on that adapter,
  recorded not faked).
- `Samen.Vault` gains `scan_no_wrong_key/2`, `scan_pitr_key_absent/2`. **The
  wrong-key scan routes through the SINGLE existing decrypt chokepoint
  (`do_decrypt/2`)** — it does NOT add a second `Crypto.decrypt(` call site, so
  `Samen.Chokepoint`'s single-chokepoint invariant still holds (5/5 chokepoint
  tests green).
- `Samen.NonPii` gains `unredacted_columns_for_subject/3` (the oracle probe that a
  non_pii! row was actually redacted for the subject).

Copied `samen_core` into a self-created subdir OUTSIDE the /tmp root
(`.t29_antitaut_scratch/`, cleaned up after). Sabotaged all three checks to
always-`:pass`:

- check 1: `DbContent` live scan forced to `:pass` (ignore leaks);
- check 2: `BackupPitr` `backups_disabled_findings` forced to `:pass`;
- check 3: `KmsAttestation` `check/1` forced to a single `:pass`.

Re-ran `test/post_shred_oracle_test.exs` in the scratch copy: **exactly the red
paths targeting checks 1-3 flipped to FAILING** (5 tests) — RP-1 (check 1), RP-2b
(check 2), RP-3 + RP-3b (check 3), and the discriminating-pair ANTI-TAUTOLOGY test
(whose green-shred `:pass` detail became "SABOTAGED always-pass"). This proves the
checks are non-vacuous discriminators, not always-fire/never-fire tautologies.
Reverted (deleted scratch). The un-sabotaged suite is green (21/21).

## Simulation seams (documented, registered as operator TODOs)

- **Replica** — no physical replica in this env. SIMULATED as a snapshot-restored
  second DB (`replica:` opt); `replica: :none` declares absence; undeclared = fail
  closed. Real streaming replica = operator TODO.
- **PITR history** — no Neon/AWS. SIMULATED with the T2.5 pg_dump→restore snapshots
  (`pitr_repos:` opt). Real Neon branch-and-restore = operator TODO
  (`docs/runbooks/pitr-gameday.md`).
- **Wrong-key probe on production** — `AwsKmsDynamo.list_active_subjects/0` returns
  `:unsupported` (a per-run Scan is not free); the tier records a documented seam,
  never a fake pass. Local dev adapters (FileBacked/InMemory) run it for real.
- **CDC mirror** — Phase-6 H4 / T6.5. Stub inactive; fails closed if configured.

None of these fake a pass: every simulated absence is either a real assertion on an
available surface or an explicit `:pass` finding carrying the seam note.
