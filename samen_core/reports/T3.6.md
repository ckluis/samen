## Free-Text vs Composite Tension (Honest Residue)

The scope-authoring doc flags `message.body` as vault-routed but does not prescribe a composite type (FullName/Emails/Phones require a typed struct). Message body is free-form text (a whole conversation reply), not a structured field.

**Decision**: `message.body` is a **scalar pii_attribute** (column `pii_smg_body`, vault `:pii_body`). It is vault-routed and fully masked on read, but it uses `Samen.Type.VaultField` (not a composite type). This is the honest implementation: the ciphertext blob covers the entire body. Typed decomposition (e.g., extracting email addresses from the body) is out of scope for T3.6 and would require a separate redaction pipeline.

This tension is documented in `Samen.Scopes.Support.Blueprint` moduledoc and is a conscious, justified choice — not an oversight.

## SlaBreachWorker: Raw SQL Rationale

`Ash.Query.filter` is a compile-time macro. The ticket resource module is resolved at runtime from config (`Application.get_env(:samen_core, :support_sla_breach_ticket_resource)`). These two facts are incompatible.

**Decision**: use raw SQL (`repo.query/2`) for the SLA breach scan. The table name and column names are derived from the abbrev convention (`#{abbrev}_ticket`, `#{abbrev}_sla_breach_at`, `#{abbrev}_breached`) — the same convention the catalog verifier enforces. This is a narrow, documented seam: the worker does not use Ash changesets, and its SQL is covered by the catalog_parity and prefix verifiers.

## Caveats

1. **message.body free-text tension** — documented above; honest residue; not a bug.
2. **SlaBreachWorker raw SQL** — documented above; narrow, testable seam.
3. **Agent write policy** — the blueprint sets `:member` as the write threshold for agents (consistent with other resources). If the product intent is admin-only agent writes, a single policy change in the blueprint macro is sufficient. This is documented in `support_scope_rbac_red_path_test.exs`.
