## Design decisions

- **Plain `Mix.Generator`, not Igniter.** `igniter` is `optional: true` under ash/ash_postgres/
  spark and is not installed. The generator adds no template runtime — substitution is a trivial
  `<%= key %>` string replace, so the generator itself compiles `--warnings-as-errors`.
- **Named `mix samen.gen.app`** (Ash `<domain>.gen.<thing>` convention). A `mix samen.new` alias
  can delegate later; the engine is `Samen.Gen.App`.
- **Output is a parametrized `pawchart`** — the proven correct-by-construction reference: ONE
  Billing scope mounted AS-IS (the "80%"), ONE authored resource with a `pii do` scalar vault
  field (the "20%"), ONE token-blind aggregate projection (so C7 / aggregate_privacy scan a real
  aggregate), all substrate migrations + a catalog-in-tx resource migration, and a `ci.sh` wired
  to the full 17-step gate.

## The global-registry coupling (T6.1 finding, handled)

Abbrevs are permanent and global (`samen_core/priv/abbrev_registry.json`, read at compile time by
`Samen.Verifiers.AbbrevRegistry` via `:code.priv_dir(:samen_core)`, which symlinks to source
`priv`). The generator reserves the app's 10 abbrevs (8 billing + aggregate + resource) there,
idempotently, preserving `$comment` + formatting. `validate!/1` fails closed on bad shapes,
internal collisions, and cross-owner collisions. The `samen_core` path dep is a **computed**
relative path so the app resolves whether placed as a direct sibling (`../samen_core`) or nested.
