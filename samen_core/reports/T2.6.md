## Scope delivered

### (a) OTel deps + `db_statement: :disabled` config

Added to `samen_core/mix.exs`:
- `{:opentelemetry_api, "~> 1.4"}` — compile-time API surface
- `{:opentelemetry, "~> 1.5"}` — SDK (span processor, exporter, propagation)
- `{:opentelemetry_ecto, "~> 1.2"}` — Ecto telemetry integration

Config in `config/config.exs`:
```elixir
config :samen_core, :opentelemetry_ecto, db_statement: :disabled
config :opentelemetry, span_processor: :simple, traces_exporter: :none
```

The `LogTelemetry` CI tier (`Samen.NoPlaintextPii.Tiers.LogTelemetry`) now asserts **two layers** per T2.6:
1. **Config-level** (T1.8d, Phase 1): `Application.get_env(otp_app, :opentelemetry_ecto)` must be `[db_statement: :disabled]`.
2. **Live handler check** (T2.6, Phase 2): every `:telemetry` handler with `handler_id = {OpentelemetryEcto, _}` must have `db_statement: :disabled` or omitted in its handler config.

A handler registered with `db_statement: :enabled` fails the tier even if the config-level key is correct — catching runtime misconfiguration.

### (b) Trace propagation across the Oban boundary

`Samen.Tracer` provides:

- `inject_trace_context/1` — stamps an Oban job changeset's `meta["trace_context"]` with W3C Trace Context headers (list of `[key, value]` 2-element lists for JSONB compatibility).
- `with_job_span/3` (macro) / `__with_job_span__/3` (function) — extracts the parent context from `meta["trace_context"]`, creates a child span via `:otel_tracer.with_span/4`, and restores the original context on exit (always, via try/after).

The enqueueing span ID rides the job row in `meta`. The worker continues the trace — one end-to-end trace per request across the queue boundary.

**Test:** `"with_job_span continues the trace as a child of the enqueuing span"` asserts:
- Both spans share the same `trace_id` (connected trace).
- `perform_span.parent_span_id == enqueue_span.span_id` (correct parent-child link).

### (c) `:reveal` span attribute allow-list

`Samen.Tracer.with_reveal_span/3` enforces the allow-list structurally:
- Allow-list: `[:subject_id, :grant_id, :reason]` — exactly three atoms (from `reveal_allowed_attrs/0`).
- Any key NOT in the allow-list is silently stripped by `filter_reveal_attrs/1` before span creation.
- The decrypted value is NEVER a span attribute — structural prevention, not policy.

`filter_reveal_attrs/1` is public so tests can verify stripping behavior directly.

## Red paths / anti-tautology probes

### Red path 1: Ecto span has no `db.statement`

**Test:** `"Ecto span has no db.statement attribute when opentelemetry_ecto is configured :disabled"`

- Attaches `OpentelemetryEcto` with `db_statement: :disabled`.
- Emits a synthetic Ecto query telemetry event with real SQL text.
- Collects exported spans via `:otel_exporter_pid`.
- **Asserts:** neither `"db.statement"` nor `:"db.statement"` appears in any Ecto-emitted span's attributes.

**Anti-tautology (proof of discriminating power):** `"Ecto span WOULD contain db.statement if :enabled"` — with `db_statement: :enabled`, the `"db.statement"` key IS present in the span. This proves the `:disabled` test is not vacuously passing.

### Red path 2: Reveal span attrs exactly three — decrypted value absent

**Test:** `"decrypted value is NOT present in exported span attributes"`

- Calls `with_reveal_span/3` with `%{subject_id: ..., grant_id: ..., reason: ..., decrypted_value: "Alice Smith — the plaintext that must not leak"}`.
- Collects the exported span.
- **Asserts:** `decrypted_value` key is absent from span attributes; no attribute value contains the plaintext string.

**Anti-tautology probe (in-process):** `"anti-tautology probe: filter_reveal_attrs strips the disallowed key"` calls `filter_reveal_attrs/1` directly and asserts `:decrypted_value` is absent from the result.

**Anti-tautology probe (sabotage, OUTSIDE /tmp):**

Probe dir: `/Users/clank/Desktop/projects/samen/_probes/t2_6_anti_tautology/` (created, sabotaged, confirmed, cleaned up).

Sabotage: changed `filter_reveal_attrs/1` to pass ALL attrs through (`%{attributes: raw}` without `Map.take`).

Result: **5 tests FAILED** including the critical `"decrypted value is NOT present in exported span attributes"` and `"filter_reveal_attrs strips disallowed keys"`. The red-path test is discriminating — it detects the sabotage.

Reverted. All 14 tracer tests pass post-revert.

### Red path 3: Live handler with `db_statement: :enabled` fails the tier

**Test:** `"flags a live OpentelemetryEcto handler with db_statement: :enabled"` in `log_telemetry_live_handler_test.exs`.

- Registers `OpentelemetryEcto.setup(prefix, db_statement: :enabled)`.
- Runs `NoPlaintextPii.run(tiers: [LogTelemetry])`.
- **Asserts:** a `:log_telemetry` violation is returned with `subject` containing `"live handler"`.

The complementary green path confirms no violation when the handler has `:disabled`.

## Simulation seam

No physical OTel collector exists in the local dev/CI environment. The simulation:

- **SDK config:** `traces_exporter: :none` (`config/config.exs`) — no exporter loaded.
- **Test config:** `:otel_simple_processor.set_exporter(:otel_exporter_pid, self())` at test setup — spans delivered as `{:span, record}` messages synchronously.
- **Span assertion:** `Record.defrecord(:span, ...)` + `:otel_attributes.map/1` converts the Erlang span record to assertable Elixir maps.
