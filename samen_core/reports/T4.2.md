## Design notes / doc parity

- **Structurally token-blind, not masked-by-policy.** The aggregate actor is a
  NAMED singleton with NO `org_id` — token-blindness is a property of the principal
  class + the C7-verified projection (no `pii_` columns physically exist), not a
  runtime mask that could be misconfigured. This is the doc's exact framing.
- **Mutual exclusion, both directions, all structural:** aggregate→reveal refused by
  `Samen.Reveal` (principal class); aggregate→tenant refused by OrgScope (org-less →
  `expr(false)`); tenant/impersonation→aggregate refused by `AggregateActorOnly`
  (default deny). The impersonation actor (`:operator`, T4.1) and the aggregate actor
  (`:operator_aggregate`) are distinct principal classes — the two operator paths
  cannot be conflated.
- **Verifier vs transformer split (honest seam).** The plan names a "NoPiiColumns
  Spark verifier". In this Ash/Spark version a verifier raise does NOT reliably abort
  `Code.compile_string` (empirically confirmed; matches the T1.3 note that verifiers
  are defense-in-depth and transformers are the reliable abort). To make the
  compile-time guarantee genuinely fail-closed, the enforcement ALSO runs as a
  transformer (the hard abort); the named verifier remains for introspection, the
  per-resource diagnostic, and as the whole-app backstop's shared rule source. One
  rule set (`violations/2`), no drift.
- **Vault-excluded projection.** MRR comes from Billing rollups (subscription/plan/
  price), queue depths from Support ticket rollups — the two doc examples. Both read
  bounded columns (tier/status enums + counts + a cents number); a subject is not
  reconstructible from a per-tier/per-status cross-tenant total (the k-anon /
  l-diversity FLOORS that harden this against differencing are T4.5, deliberately
  deferred — per the doc's own posture split).
