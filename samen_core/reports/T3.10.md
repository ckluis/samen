over the shared kernel, with the inherited plumbing (vault · catalog · org-scope · audit ·
crypto-shred) riding underneath UNCHANGED.

## Design decisions (documented)

- **`alias_resource` is a NAME, not a second Ash resource.** The alias module
  (`Ctx.Toy.Encounter`) is deliberately not defined as an Ash resource. Aliased
  queries route to the KERNEL resource via `Samen.Context.query/2`, so the kernel's
  own actions/policies/vault/audit run underneath — the alias physically cannot widen
  or re-declare a policy because it exposes no policy surface of its own. Verified:
  `refute Ash.Resource.Info.resource?(Ctx.Toy.Encounter)`.
- **`reshape` = ad-hoc Ash expression calculations, not baked into the kernel.** A
  reshape records `calculate name, type, expr(...)` entries; `reshaped_query/2` loads
  them onto a query via `Ash.Query.calculate/8` (passing the raw expression, which Ash
  wraps in `Ash.Resource.Calculation.Expression`). The kernel resource and its table are
  genuinely untouched — verified against `information_schema.columns` (no
  `patient_responsibility`/`payer_claim` column) and `fld_field` (no derived field row).
  Derived values come back in each record's `:calculations` map, NOT as top-level
  fields — exactly right for "a reshape mints no column."
- **`:money` is sugar for `:decimal`.** Ash has no built-in `:money` type and AshMoney is
  not a substrate dep. `resolve_type/1` maps `:money → :decimal` (decimal is an Ash/Ecto
  dep). Documented as a seam: a host adding AshMoney passes its type module directly.
- **Introspection representation (T3.10 (c) decision).** `catalog_context_map/1` returns a
  flat machine-readable map: `aliases` name a kernel TABLE; `derived_fields` name a
  context-derived field keyed to a kernel table, each carrying `physical?: false`. This
  explicitly distinguishes a context-derived field from a physical `fld_field` column so
  the catalog/LLM never mistakes a reshape for storage.
- **DSL shape vs the doc's `use`-line calls.** The vision doc writes
  `use Samen.Context, domain: X` with top-level `alias_resource`/`reshape` calls for
  brevity. The real DSL nests them (and `domain`) inside the `context do … end` block —
  the ordinary Spark shape. Reason documented in code: Spark's generated `__using__`
  drops any NON-LITERAL `use` option (`domain: Some.Module` is an alias AST, not a
  literal), and a hand-written `__using__` that emits `use Spark.Dsl` internally does not
  bring the section macros into scope. Declaring inside the block is the faithful,
  working shape; the semantics (rename + reshape + domain) are identical.

## Red paths (must-fail) + anti-tautology

`test/context_red_path_test.exs` (7 tests) + `test/context_test.exs` (17 tests) = 24, all green.

1. **An alias cannot widen policies** — an aliased read from a FOREIGN org returns `[]`
   (org-scope FilterCheck holds through the alias), and an `:owner` role does NOT widen it.
   Control: the OWNING org's `:viewer` DOES see the row (proves the deny is org-mismatch,
   not a blanket break).
2. **A reshape cannot touch storage (compile-time `Spark.Error.DslError`)** — three red
   paths: (a) a calc name colliding with a logical column (`:total`); (b) a calc named after
   the abbrev-prefixed storage source (`:cei_total`); (c) a calc `expr` referencing a raw
   storage column (`expr(cei_total - covered_amount)`). Control: the same reshape over
   LOGICAL fields compiles cleanly.
3. **Calculations correct against worked examples** — 100/70→30/70; fully-covered→0;
   nothing-covered→total; and the invariant `responsibility + claim == gross total`. Plus a
   discriminator red path: a WRONG split (`payer_claim = total`) yields 130.00, NOT 100.00
   — proving the assertion is non-vacuous.

**Plumbing-rides-underneath tests (T3.10 (b))** — a reshaped/aliased resource's PII still
masks (`%Samen.Masked{}` on read; `vt_*` token in the DB column, no plaintext); org-scope
still filters the aliased AND reshaped reads; an audit call lands a token-only `aud_event`
row.

## Seams / notes for later phases

- `:money → :decimal` is the only type seam; a host adding AshMoney passes its type module
  directly.
- Audit under a context: the context contributes audit WRITERS over the existing `aud_event`
  tier (the scope-authoring idiom), never a new audit schema — same as every scope. The toy
  test exercises `Samen.AuditEvent.insert/2` to prove the writer path rides underneath.
- Phase 5 (which cites T3.10 as needed) can build a real vertical context on this DSL: the
  `catalog_context_map/1` surface is the LLM-grounding artifact for the vertical's ubiquitous
  language (renames + derived fields, marked non-physical).
