## What shipped

### Resources / storage (clause a)
- `lib/samen/reveal/schema.ex` — three abbrev-prefixed Ecto schemas (plain Ecto, mirroring the `Samen.Vault.VaultRow` decision — kernel infra consulted by the `Samen.Reveal.Grant` seam, not tenant-facing Ash resources):
  - `Samen.Reveal.RevealRequest` (`rvq_*`): subject_id, requestor_id, reason, resource/action, status.
  - `Samen.Reveal.RevealGrant` (`rvg_*`): request_id, subject_id, requestor_id, granted_by, reason, resource/action, **expires_at**, revoked_at.
  - `Samen.Reveal.RevealAudit` (`rvl_*`): event, subject_id, actor_id, request_id, grant_id, detail, recorded_at.
- Bounded default window: `default_window_minutes/0` = 15 (configurable via `:reveal_grant_default_window_minutes`), overridable per approval with `:window_minutes`.
- Migration `priv/test_repo/migrations/20260705050100_reveal_grants.exs`.

### Distinct-party approval — BOTH layers (clause b)
- **Policy layer:** `Samen.Reveal.Grants.approve/2` refuses `{:error, :self_approval}` before touching the DB when `granted_by == req.requestor_id`, and writes a `denied` audit row.
- **DB layer:** migration adds `constraint(:rvg_reveal_grant, :rvg_distinct_party, check: "rvg_granted_by <> rvg_requestor_id")`. Even a direct/raw insert bypassing the policy is rejected by Postgres.

### Deny-on-read expiry (clause c)
- `Samen.Reveal.Grants.active?/3` denies the moment `now() > expires_at`, computed against the row's `expires_at` with NO dependence on the auto-revoke job having run. Also denies on `revoked_at` set. The distinct-party invariant (`granted_by != requestor_id`) is re-checked on read too (defence in depth over the DB CHECK).

### Same-tx Oban auto-revoke (clause d)
- Added `{:oban, "== 2.23.0"}` to `mix.exs`; Oban tables migrated by `20260705050000_add_oban.exs`; Oban configured (`config/config.exs`, `testing: :manual` in `config/test.exs`); started in `test/test_helper.exs` after migration and (in a host) via `SamenCore.Application` when it supervises the repo.
- `approve/2` builds ONE `Ecto.Multi`: grant insert + `granted` audit insert + `Oban.insert(multi, :auto_revoke, AutoRevokeWorker.new(%{grant_id}, scheduled_at: expires_at))`, run in one transaction. Grant rollback ⇒ no `oban_jobs` row.
- `Samen.Reveal.AutoRevokeWorker` (queue `:reveal`) flips `revoked_at` at `expires_at` (idempotent; only touches `revoked_at`, never `expires_at`), writes an `expired` audit row.

### No renew-in-place (clause e)
- No function in `Samen.Reveal.Grants` mutates `expires_at`. `revoke/2` sets only `revoked_at`. `attempt_extend/2` always returns `{:error, :no_renew_in_place}` (exists solely as the red-path handle). Re-access = fresh `request/1` + `approve/2` → a NEW grant row.

### Lifecycle audit (clause f)
- `requested` / `granted` / `revoked` / `expired` / `denied` rows via `write_audit/2` (`granted` written inside the grant's transaction). Plain rows now; hash chain is Phase 4 (G4) — schema leaves room for `prev_hash`/`hash`.

### T1.5 wiring
- `Samen.Reveal.Grants` implements the `Samen.Reveal.Grant` behaviour (`granted?/1` → `active?(actor, subject_id)`; no subject scope ⇒ deny). Wire via `config :samen_core, :reveal_grant, Samen.Reveal.Grants`. `test/reveal_grant_seam_test.exs` proves an operator with no/revoked grant is denied (vault never reached) and an active distinct-party grant reveals.

## Caveats / notes for later phases
- `active?/2` keys the reveal on `granted_by == actor` — the operator who HOLDS the live grant. The two-party model is enforced (distinct approver required to create the grant), but the kernel's reveal check authorizes the grant-holder. If Phase 4 needs the *requestor* to be the reveal actor (approver merely enabling), this is a one-line filter change; the load-bearing invariants (subject scope, expiry, revoke, distinct-party) are unchanged and exercised by the red paths.
- Audit rows are plain (no hash chain / no append-only trigger yet) — Phase 4 G4 and Phase 2 append-only tier respectively. The schema is chain-ready.
- Oban runs `testing: :manual` in the kernel's test env; T2.1 layers AshOban conventions + queue taxonomy on top of this base Oban.
