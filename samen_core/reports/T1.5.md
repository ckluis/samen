## Scope delivered (T1.5 clauses a/b/c + Gate-0 fix tasks #1 and #6)

### (a) `%Masked{}` as the vault field's normal value — every egress path masks

`Samen.Masked` (`lib/samen/masked.ex`) already carried `String.Chars`, `Inspect`,
`Jason.Encoder`, and a compile-guarded `Phoenix.HTML.Safe` from T1.4. T1.5:

- **Made `phoenix_html` a real dependency** (`mix.exs`, `{:phoenix_html, "~> 4.1"}`)
  so the `Phoenix.HTML.Safe` protocol module is always present at compile time and
  the `defimpl` is actually compiled (previously the `Code.ensure_loaded?/1` guard
  was dead — no Phoenix dep meant the impl never compiled, so the Gate-0 fix-task-#1
  clause "renders `••••` in HEEx" was untested/unmet). The guard is retained as
  defence-in-depth for a host that strips the dep.
- **Routed `Phoenix.HTML.Safe.to_iodata/1` through Phoenix's own String impl** so
  the escaping guarantee is inherited, not hand-asserted.
- **Added `Samen.Masked.to_iodata/1`** for the CSV-ish `IO.iodata` egress path.

**Gate-0 fix task #1 (mandatory) — CLOSED.** `test/masked_render_test.exs` renders a
`%Masked{}` through the exact `Phoenix.HTML.Engine` path a HEEx `<%= @x %>` compiles
to (`EEx.eval_string(..., engine: Phoenix.HTML.Engine) |> Phoenix.HTML.safe_to_string`)
and asserts the output is `<span>••••</span>`, never raises, and never leaks the
token. Also covers `to_string`/interpolation, `Inspect`, `Jason` (incl. nested-in-map),
and CSV-ish `IO.iodata`/`IO.iodata_to_binary`.

### (b) Exactly ONE decrypt chokepoint

`Samen.Vault.do_decrypt/2` (invoked only by the reveal path) remains the single
`Crypto.decrypt(` call site. Ported the spike's structural scanner into a first-class
module: **`Samen.Chokepoint`** (`lib/samen/chokepoint.ex`) with
`decrypt_call_sites/1` and `single_chokepoint/1`. `test/chokepoint_test.exs` asserts
exactly one sanctioned call site in `samen/vault.ex`, and the RED PATH plants a second
`Crypto.decrypt(` in a scratch-copy of the tree and confirms the scanner flips to
`{:error, …}` naming the rogue file.

**Literal-match limitation noted (C3 is the real check).** The scanner is a literal
`Crypto.decrypt(` text scan; it does not catch aliased (`C.decrypt(`), fully-qualified
(`Samen.Kms.Crypto.decrypt(`), `:crypto` primitive, or `apply/3` decrypts. This is
documented on `Samen.Chokepoint`'s moduledoc AND proven honest by a test that plants
an aliased decrypt and asserts the scanner (correctly) misses it — the C3 `pii_reads`
AST verifier (T1.8b) is the real check for those evasions. The scanner also skips
comment/backtick-doc lines and its own module so it does not flag its own prose.

### (c) `:reveal` as a first-class, introspectable marker + the grant seam

- **DSL marker.** Added a `reveal :action` entity to the `pii do … end` section
  (`Samen.Pii.RevealAction`). A resource marks an action a reveal action by
  declaration, e.g. `reveal :reveal_email`.
- **Real introspection (Gate-0 fix task #6).** `Samen.Transformers.RevealActions`
  persists a `MapSet` of reveal-action names (`:samen_pii_reveal_actions`) and
  fail-closes if a marker names a non-existent action.
  `Samen.Pii.Info.reveal_actions/1` and `reveal_action?/2` read the persisted marker
  — **declaration-driven, NOT name-matching**. Verified: a real action named
  `:read_email_looks_like_reveal` (name contains "reveal") returns `false` from
  `reveal_action?/2`; only the declared `:reveal_email` returns `true`. This closes
  the S0.7 `reveal`-lexical-prefix false-negative evasion; T1.8b keys on this API.
  `Samen.Pii.Verifiers.RevealActionExists` is the defense-in-depth verifier.
- **The grant seam T1.6 fills (default deny).** `Samen.Reveal` (`lib/samen/reveal.ex`)
  enforces two gates in order — (1) marker gate (`reveal_action?/2`), (2) grant gate
  (`Samen.Reveal.Grant.granted?/1`) — then, and only then, calls the single vault
  chokepoint. `Samen.Reveal.Grant` is the behaviour T1.6 fills; the default
  `Samen.Reveal.DenyAll` returns `false` for everything, so **every ungranted
  `:reveal` denies (`{:error, :denied}`) and never touches the decrypt path**.
  `Samen.Reveal.Context` carries actor/subject/resource/action/label — what T1.6's
  distinct-party, time-boxed grant model keys on. Configure via
  `config :samen_core, :reveal_grant, MyApp.Reveal.Grant`.

### Pre-existing T1.4 flake fixed (test isolation only)

The baseline suite was seed-dependently flaky (`vault_test.exs`: `store_field`
returning `{:error, :shredded}`). Root cause: `Samen.Kms.FileBacked` used a single
shared key directory (`$TMPDIR/samen_core_keystore`) that persisted **across runs**,
so stale subject tombstones from a prior run collided with a new run's reused
`System.unique_integer/1` subject ids. Fixed in `test/test_helper.exs` by pointing
`:kms_key_dir` at a fresh per-run temp dir (test infra only; the FileBacked adapter
and vault runtime are unchanged). Confirmed: previously-failing seeds 1 and 111 now
pass, and the fix does not alter any T1.4 assertion.
