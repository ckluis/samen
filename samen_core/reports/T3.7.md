## Search convention (spec: "tokenized index convention over catalogued fields")

`SearchIndex` is a **registry resource** — one row per (resource_name, field_name) that the host has indexed into a Postgres `tsvector`. The physical tsvector column (e.g. `pfl_file.pfl_search_vector`) lives on the resource's table; this registry is the governance layer.

**PII constraint:** `Samen.Scopes.Primitives.SearchIndexGuard.assert_no_pii_column/2` raises `ArgumentError` if a vault-routed field is registered. This is the enforcement mechanism for the spec's named red path.

## PII vault round-trip per 🔒 object

### Notification (`rendered_body`)
- Write with plaintext → domain column `pii_pnt_rendered_body` stores `vt_*` token
- Plaintext never in domain row; vault row holds ciphertext
- Two notifications → distinct tokens
- Default read → `%Masked{}` (renders `•••`)
- Render check: `Phoenix.HTML.Safe.to_iodata(masked) =~ "•"`

### Webhook (`signing_secret`)
- Write with plaintext → domain column `pii_pwh_signing_secret` stores `vt_*` token
- Plaintext never in domain row; vault row holds ciphertext
- Two webhooks → distinct tokens
- Default read → `%Masked{}` (renders `•••`)

## Anti-tautology probes (hard rule 2)

### Probe 1: SearchIndexGuard

**Scratch dir:** `.t37_antitaut_scratch/` (created and removed during probe)

**Sabotage:** `SearchIndexGuard.get_pii_fields/1` overridden to always return `[]` (no PII fields found).

**Red path FLIPPED to FAILING:**
- `test "SearchIndexGuard raises when a PII-declared field is registered"` → `Expected exception ArgumentError but nothing was raised`
- `test "SearchIndexGuard raises when webhook signing_secret is registered"` → same

**Result after revert:** 9/9 green. `mix compile --warnings-as-errors` clean. 0 occurrences of `SABOTAGED` in source.

**Conclusion: NON-VACUOUS** — the guard is a genuine discriminator, not an always-pass tautology.

### Probe 2: OrgScope FilterCheck

**Scratch dir:** `.t37_orgscope_probe/` (created and removed during probe)

**Sabotage:** `OrgScope.filter/3` overridden to return `expr(true)` (allow all rows regardless of org).

**Red path FLIPPED to FAILING:**
- All 3 cross-org property tests FAILED (org B's rows became visible to org A's actor)
- 3 cross-org write tests also affected

**Result after revert:** 18/18 policy matrix tests green. All CI green.

**Conclusion: NON-VACUOUS** — the org-scope filter is a genuine tenant isolation mechanism.
