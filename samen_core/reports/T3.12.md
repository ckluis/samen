## What was built

### `Samen.ApiContract` (samen_core)

Core module with three sub-modules:

- **`Samen.ApiContract`** — public API: `snapshot/2`, `diff/2`, `encode!/1`, `decode!/1`
- **`Samen.ApiContract.Snapshot`** — introspects AshJsonApi resources from Ash domains using `apply/3` to avoid compile-time warnings (AshJsonApi is optional in samen_core, only required in the host app). Resources are skipped silently if `AshJsonApi.Resource.Info` is not loaded.
- **`Samen.ApiContract.Differ`** — diffs live vs stored snapshot, returns `{:ok, []}` or `{:error, violations}`. Additive changes are not violations.

### Snapshot format (`api_contract.v1.json`)

Deterministic JSON with sorted keys (same convention as `schema.dict.json`):
- Resources sorted by `type`
- Fields sorted by `name`
- Routes sorted by `method` then `path`

Structure per resource:
```json
{
  "type": "contact",
  "module": "Elixir.Demo.Crm.Contact",
  "fields": [
    {"name": "display_name", "type": "Ash.Type.String", "required": false}
  ],
  "routes": [
    {"action": "read", "method": "GET", "path": "/contacts", "required_args": []}
  ]
}
```

### Structural breaks detected (exit 1)

1. **`field_removed`** — a previously exposed field is absent from `show_fields` in the live resource
2. **`type_narrowed`** — an exposed field's Ash type string changed
3. **`route_dropped`** — a previously declared route `{method, path}` is absent from the live resource; also fires if an entire resource type is absent
4. **`required_arg_added`** — a route action now has a required argument it previously lacked

### Additive changes (pass, no violation)

- New field added to `show_fields`
- New route declared
- New resource added to the API surface
- New optional argument added (required_args unchanged)

### Semantic breaks: explicitly out of scope

Each diagnostic includes:
> "NOTE: semantic breaks (changed meaning or unit with the same type/shape) are not caught by this structural diff — they remain the author's responsibility."

This matches the vision doc: "Be precise about the boundary: the diff catches the shape of the contract; a semantic break that keeps the shape (the same field, same type, but a changed meaning or unit) is not a schema diff and remains the author's responsibility."

### `--update` flag

`mix samen.verify.api_contract --version v1 --update` regenerates the snapshot from the live contract and writes it to the snapshot file. Used after an intentional, versioned API change.

## Anti-tautology probe (HARD RULE 2)

**Method:** In-memory sabotage — no file I/O, no committed snapshot mutation. The probe:

1. Builds the live snapshot from the demo app (`Samen.ApiContract.snapshot([Demo.Crm, Demo.Identity], "v1")`)
2. Injects a `GHOST_FIELD_NOT_IN_LIVE` field into the stored snapshot's `contact` resource (a field that does NOT exist in the live contract)
3. Calls `Differ.diff(live, sabotaged_stored)` — the live contract does NOT have `GHOST_FIELD_NOT_IN_LIVE` → structural break
4. Asserts `{:error, violations}` with a `field_removed` violation naming `GHOST_FIELD_NOT_IN_LIVE`
5. Confirms the un-sabotaged baseline (`Differ.diff(live, live)`) returns `{:ok, []}` (the violation came from the sabotage, not a broken baseline)

**Result:** **PROBE PASSED** — the differ returned a `field_removed` violation when the stored snapshot contained a ghost field absent from the live contract. The verifier is a genuine discriminator, not an always-pass tautology.

Scratch state: the sabotaged snapshot exists only as an in-memory map local to the test. No file was mutated, no revert step was required.

**In scope (implemented):**
