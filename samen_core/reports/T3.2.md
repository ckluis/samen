## ADR-004 compliance (scope packaging)

The CRM scope follows ADR-004 Option C (blueprint macro) exactly:

- `Samen.Scopes.Crm` is a library-authored blueprint macro.
- `use Samen.Scopes.Crm, otp_app:, repo:, namespace:` inside `Demo.CrmScope` expands into six host-owned `use Samen.Resource` modules.
- Each resource's `otp_app`, `repo`, `domain` are the host's — resources are catalogued in the host's catalog (not `samen_core`'s), scanned by host's unchanged verifiers, and PII routes into the host's vault.
- Abbrevs are resolved to literals at macro expansion time (guide §1 "resolve abbrevs to literals at expansion time").
- Migration is a copied `Samen.Migration` template with `catalog_sync(@resources)` in the same transaction as DDL.

## Vision-doc canonical vault case (the Core.Person pattern)

The task spec says: "person composes a Core.Person-style fragment (the doc pattern: fragment + base:)."

**Implemented:** `Samen.Fragments.CorePerson` is a `Spark.Dsl.Fragment` (tableless, no data layer) carrying:
- `full_name` → vault `:pii_name` (composite `Samen.Type.FullName`, no `pii_` prefix)
- `emails` → vault `:pii_email` (composite `Samen.Type.Emails`, no `pii_` prefix)
- `phones` → vault `:pii_phone` (composite `Samen.Type.Phones`, no `pii_` prefix)
- `job_title`, `custom` (non-PII plain attributes)

`Demo.CrmScope.Person` (abbrev `per`) uses `use Samen.Resource, ..., base: Samen.Fragments.CorePerson` — a single physical table `per_person` carrying all nine core person columns. The fragment is tableless; FKs from Activity/Attachment target `Demo.CrmScope.Person` (the composed resource with a table), never the fragment.

The vision doc §core "PII routing note": "composite-type fields (per_full_name, per_emails) route by vault name (→ pii_name / pii_email), so they carry the resource abbrev but not a pii_ column prefix." Confirmed by `per_person` migration DDL (`per_full_name`, `per_emails`, `per_phones` are plain `:text` columns that hold `vt_*` tokens).

## Anti-tautology sabotage probe (HARD RULE 2)

### Probe 1 — OrgScope filter (cross-org red path)

**Target:** `Samen.Policy.OrgScope.filter/3` in `samen_core/lib/samen/policy/org_scope.ex`.

**Sabotage:** Changed `filter/3` to return `expr(true)` (bypassing all org filtering), making every actor see all orgs' rows.

**Scratch:** `/Users/clank/Desktop/projects/samen/crm_antitaut_scratch/org_scope.ex.bak` (created, probe run, then directory removed).

**Result:** `mix test test/crm_scope_policy_matrix_test.exs` → **5/12 passed, 7 failed** (2 property tests + 5 unit tests flipped to failing). The cross-org read/write denied tests all failed — exactly the tests that depend on the org filter. The OrgScope filter IS the genuine mechanism.

**Revert:** Restored original `filter/3` from backup. `mix test --warnings-as-errors` → 12/12 green. `bash ci.sh` → ALL PASSED.

### Probe 2 — Catalog-parity (ghost table / uncatalogued column)

**Target:** `CatalogParity.check/1` via the `crm_scope_catalog_parity_red_path_test.exs` in-test sabotage (deletes `tam_table`/`fld_field` rows within the sandbox transaction).

**Result:** `catalog_parity` returned violations naming `per_person` as a ghost table when the `tam_table` row was deleted inside the sandbox. The positive control was green. The verifier IS a genuine discriminator (not a tautology).

## Deviations from scope-authoring guide

None. Every item in the §10 checklist is satisfied:

1. The mount macro follows the exact pattern from `identity.ex`: reads `otp_app/repo/namespace`, resolves abbrevs to literals at expansion time, emits `resources do … end` + one `Blueprint.define_*` per resource.

3. No scope audit module (CRM scope has no scope-level audit events — this is consistent; the guide §6 says "only if the scope emits audit events").
4. Abbrevs are permanent, 3-letter, collision-free in the registry.
5. Migration uses `use Samen.Migration` with `catalog_sync(@resources)` at the end of `up/0` and `catalog_sync_down(@resources)` at the start of `down/0`.
6. Four test files shipped per §9.
7. Anti-tautology sabotage probes run and results stated.
