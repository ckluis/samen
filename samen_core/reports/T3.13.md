## Scope delivered

### T3.13 — Webhook subsystem

**1. `Samen.Webhook.Signer`** (`lib/samen/webhook/signer.ex`)

HMAC-SHA256 sign + receiver-side verify with anti-replay:

- `sign/3` — `HMAC-SHA256(secret, "<timestamp>.<body>")` → `"t=<ts>,v1=<hex>"` header
  (Stripe-compatible shape).
- `verify/4` — parses the header, recomputes HMAC, constant-time compares, checks
  timestamp is within tolerance window (default 300s). Rejects stale timestamps EVEN
  when the HMAC is valid — the anti-replay gate.
- `secure_compare/2` — XOR-accumulate constant-time comparison (Bitwise.bxor + bor).

**2. `Samen.Webhook.Payload`** (`lib/samen/webhook/payload.ex`)

Payload serialization under the T3.11 allowlist:

- Filters storage names (3-letter-abbrev_ prefix and pii_-prefix columns — ABSENT).
- `%Masked{}` PII serializes as `"••••"` (safe default); if `include_masked: false`,
  PII fields are ABSENT.
- Plaintext PII in a PII-declared field: OMITTED (fail-closed, not passed through).
- Never includes vault tokens, storage names, or raw PII in the output map.
- `build/3` + `encode/1` → pre-serialized JSON frozen at enqueue time.

**3. `Samen.Webhook.DeliveryWorker`** (`lib/samen/webhook/delivery_worker.ex`)

Oban worker for at-least-once outbound delivery:

- `queue: :webhooks_out`, `max_attempts: 20` (capped exponential backoff; ~6h ceiling).
- DLQ: after max_attempts Oban moves to `:discarded` state.
- Per-event idempotency: `unique: [fields: [:args], keys: [:idempotency_key], period: 86_400]`
  — same event within 24h is a no-op.
- Job args shape: opaque UUIDs, hex idempotency key, bounded `event_type`, pre-serialized
  body, opaque `org_id` — satisfies the F2.1 token-only-args convention.
- Signing secret revealed from the vault at delivery time; NEVER stored in job args.
- HTTP adapter injected via `Samen.Webhook.HttpAdapter` behaviour (production: httpc;
  test: `Test` agent).

**4. `Samen.Webhook.HttpAdapter`** (`lib/samen/webhook/http_adapter.ex`)

- `HttpAdapter` behaviour + `Httpc` production adapter (`:httpc`).
- `HttpAdapter.Test` agent for testing without a network.

**5. `Samen.Webhook`** (`lib/samen/webhook.ex`)

Public entry point:

- `deliver/3` — resolves active endpoints subscribed to `event_type`, builds allowlisted
  payload, encodes, enqueues one `DeliveryWorker` per endpoint.
- `:endpoints` override for tests.
- `enqueue_in_tx/3` for same-transaction delivery (no orphan jobs on rollback).
- Idempotency key: deterministic `SHA-256(endpoint_id:event_type:record_id)[:32]`.

### F2.1 — `oban_jobs` oracle tier

**6. `Samen.NoPlaintextPii.Tiers.ObanJobs`** (`lib/samen/no_plaintext_pii/tiers/oban_jobs.ex`)

New oracle tier added to `default_tiers/0`:

- **CI mode**: samples recent `oban_jobs` rows per queue, checks arg values via
  `Samen.PiiValueShape.classify_id_value/1` — email/SSN/phone/name-shaped values are
  `:violation`. Known-safe Samen workers are skipped (convention-verified). No repo →
  fail-closed violation. `oban_jobs` absent → no finding (Oban not yet deployed).
- **Post-shred mode**: with `context.subject_id` set, scans `args::text`, `errors::text`,
  `meta::text` for the subject_id string — a reference is a violation (operator must
  inspect: is it an opaque ID reference or a leaked PII value?).
- **Tier map documentation**: `@known_safe_workers` registers every Samen-owned worker
  class that follows the convention; the tier emits a violation for unknown workers with
  PII-shaped arg values.

**7. `Samen.NoPlaintextPii.default_tiers/0` updated** to include `ObanJobs`.

## Documented seams (honest)

1. **`Samen.Webhook.deliver/3` endpoint resolution** — the `endpoints: opts` override is
   the only working path in the library; the DB lookup seam (resolves active endpoints
   from the configured `webhook_endpoint_module`) requires the host to configure
   `:webhook_endpoint_module` and `:webhook_repo`. Without that, `deliver/3` returns
   `{:ok, 0}` (no endpoints found). Documented in moduledoc.

2. **ObanJobs CI scan is sampling, not exhaustive** — reads the last 100 rows per queue.
   A host with thousands of old jobs containing PII may not have them flagged until they
   appear in the sample window. The convention doc is the primary control; the scan is a
   belt.

3. **Post-shred subject_id reference** — finding a subject_id in oban_jobs.args is not
   necessarily a breach (it may be a legitimate opaque ID reference: "process record X").
   The tier reports it as a violation so the operator inspects; if the reference is opaque
   (not a leaked name/email), it is documented as a known seam, not a fix.

4. **Pre-existing intermittent flake** — `Core.Ctx.Activity.create` test intermittently
   fails in the full suite (timing-sensitive; unrelated to T3.13; present before this work
   per Gate-2 report's 588-passed baseline). T3.13's own 44 tests are consistently green.

subject_id/record_id and reveal at `perform/1` time through the vault chokepoint.
