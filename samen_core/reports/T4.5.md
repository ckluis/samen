## What shipped (files)

### samen_core — the floors, the sentinel, the ledger scaffold, the verifier
- `lib/samen/aggregate/suppressed.ex` — `%Samen.Aggregate.Suppressed{}`, the aggregate
  cell's fail-closed value (mirrors `%Masked{}`). Carries only the reason
  (`:k_anonymity` / `:l_diversity`) + floor params + the observed metric — **never the
  withheld value**. Renders `⊘` via `String.Chars` / `Inspect`, and a machine-readable
  `{"suppressed": true, "reason": …}` via `Jason.Encoder` — no value leaks by any path.
- `lib/samen/aggregate/cohort_spec.ex` — `%CohortSpec{}` + `spec_for/1`. Per-resource:
  the cohort-key columns (accounting granularity), the cohort-count column (k-anon
  size), the optional distinct-sensitive column (l-diversity), the releasable value
  columns to suppress, and the named sensitive attribute. A resource with no
  `aggregate_cohort_spec/0` → `nil` → fail-closed downstream.
- `lib/samen/aggregate/privacy.ex` — the FLOORS, **enforced**. `apply/3` runs k-anon
  FIRST (cohort count `< k` — count-of-one included — suppresses), then l-diversity
  (distinct sensitive `< l` — homogeneous cohort included — suppresses). `nil`/unknown
  cohort count fails closed (suppresses). `nil` cohort spec → `{:error, :no_cohort_spec}`
  (mask-unknown-by-default). `k()`/`l()` read config (defaults k=5, l=2).
- `lib/samen/aggregate/query_budget.ex` — the SCAFFOLD. `Samen.Aggregate.QueryLedgerRow`
  (`aqb_*` Ecto schema) + `QueryBudget`: `record/1` writes one ledger row per read keyed
  by **cohort** (`{resource, cohort_key, tenant_scope}`), `tenant_scope` = `"__aggregate__"`
  for the cross-tenant plane; `count/2` and `over_threshold?/2` **ignore the actor**;
  crossing `:query_budget_warn_threshold` fires a `[:samen, :query_budget,
  :threshold_exceeded]` telemetry event + a WARN log — but **never denies**. `actor_id`
  is recorded for forensics only, explicitly NOT the accounting unit. Recording is
  best-effort (a ledger failure never fails a read — the floors, not the budget, are the
  enforced defence).
- `lib/samen/aggregate.ex` (T4.2, extended) — `read_all/2`, the ONLY aggregate-actor
  read surface, now routes every returned row set through (1) `QueryBudget.record/1` per
  cohort, then (2) `Privacy.apply/3` (the floors), keyed off the resource's cohort spec.
  This is the enforcement point that makes suppression un-bypassable via the domain's
  operator-facing path. `read/3` doc'd for the suppressed-cell case.
- `lib/mix/tasks/samen.verify.aggregate_privacy.ex` — the CI gate: every aggregate-plane

## Red paths (all fail closed, tested)

1. **Count-of-one cohort SUPPRESSED (k-anon).** `aggregate_privacy_test.exs` (unit) +
   `aggregate_privacy_floors_test.exs` (demo, real DB): a single-tenant MRR tier / a
   single-ticket status cohort returns `%Suppressed{reason: :k_anonymity, observed: 1}` —
   the exact value (e.g. `777_777`) is NEVER returned.
2. **Homogeneous k-cohort SUPPRESSED (l-diversity).** A status cohort with `depth >= k`
   but all tickets sharing ONE priority (`distinct_priorities == 1`) returns
   `%Suppressed{reason: :l_diversity, observed: 1}` — proven on the real sensitive
   dimension (ticket priority).
3. **k-anon BEFORE l-div.** A count-of-one cohort that is also homogeneous suppresses
   with `reason: :k_anonymity` (the smaller-cohort floor fires first).
4. **Fail-closed no-cohort-spec.** `Privacy.apply(rows, nil)` → `{:error, :no_cohort_spec}`;
   and `mix samen.verify.aggregate_privacy` FAILS an aggregate resource with no cohort
   spec (`aggregate_privacy_verifier_test.exs` RED) — the specless resource is flagged,
   the spec'd one passes (positive control).
5. **Bypass impossible via the domain (the read chokepoint).** The operator-facing path
   (`OperatorDashboard` → `Samen.Aggregate.read_all/2`) routes every row through the
   suppression module; a grep confirms the ONLY `Ash.read` of the aggregate resources is
   inside the `read_all/2` chokepoint, and the dashboard reads exclusively through it.
   Sabotaging `Privacy.suppress_row` to a passthrough FLIPPED all 6 demo suppression red
   paths (2/8 remained green — the ledger/collusion tests) — see anti-tautology below.
6. **Ledger accounts per-cohort, NOT per-actor (collusion).** `query_budget_test.exs` +
   `aggregate_privacy_floors_test.exs`: two DISTINCT actors reading the SAME cohort
   accrue against ONE growing per-cohort count (`count == 2`), not two per-actor budgets.
   Both actor ids are recorded (forensics) but the count ignores them.

## The DIFFERENCING test (clause d) — total honesty about today

`aggregate_privacy_floors_test.exs` "DIFFERENCING: two near-identical cohort queries
isolating one subject". It documents exactly what happens **today**:

- **(1) The floor catches the isolating side.** The differencing attack's payoff is one
  subject's value; the count-of-one cohort that would expose it is SUPPRESSED by k-anon.
  Asserted: `%Suppressed{reason: :k_anonymity, observed: 1}` on the isolating tier; the
  larger cohort (`>= k`) releases.
- **(2) The ledger records both reads.** Every cohort touched is accounted per-cohort, so
  a repeated/overlapping differencing pattern IS observable (and WARNs past threshold).
- **(3) Full cross-query defence is DEFERRED — stated, not hidden.** The ledger does NOT
  block the second overlapping query; there is no cross-query suppression, no DP noise,
  no t-closeness. The defence that matters for THIS test (the isolating count-of-one) is
  the k-anon floor, which IS enforced. A subtler differencing attack that stays ABOVE the
  k floor on both sides while still leaking via the diff is **not defended today** — the
  ledger records it and the WARN surfaces it for a human, but it is not stopped. We do
  not claim otherwise. Asserted: `over_threshold?/2 == false` (no read denied by the
  budget — the scaffold never enforces).

## Design notes / doc parity

- **Enforced today vs posture under construction — matched EXACTLY.** k-anon + l-div are
  ENFORCED (the floors replace values with `%Suppressed{}` on every read). The
  cross-query budget is a SCAFFOLD (accounting + WARN, never enforce). DP + t-closeness
  are NOT implemented — named as a research track (plan T6.6) in the `Privacy` and
  `QueryBudget` moduledocs and here. There is deliberately **no `enforce` flag** on the
  budget — enforcement is T6.6, not a switch we could flip and claim the defence.
- **Per-actor is the wrong unit — made real, not just claimed.** The ledger key is the
  cohort being queried (`{resource, cohort_key, tenant_scope}`), `tenant_scope =
  "__aggregate__"` for the cross-tenant plane ("and per-tenant in aggregate" — the scope
  column is where a future per-tenant budget aggregates). `count/2` takes no actor. The
  collusion test proves two coordinating actors accrue against ONE per-cohort count.
- **`%Suppressed{}` is not `nil`/`0`.** Returning `0` for a suppressed cell is a leak by
  another name (indistinguishable from a real zero, and the drop-below-floor itself is
  re-identifying). A distinct sentinel makes suppression explicit + inspectable while
  never carrying the withheld value.
- **The honest seam on "bypass impossible".** Suppression is enforced by the read-surface
  CONVENTION (`Samen.Aggregate.read_all/2` is the sole operator-facing path and routes
  through the floors) + the fact that no other code reads the aggregate resources. It is
  NOT a DB-policy-level suppression: a caller already holding the aggregate actor could
  in principle call `Ash.read(MrrByTier, actor: agg)` directly and bypass the floors —
  the SAME chokepoint design as `Samen.Vault.reveal` being the sole plaintext path. The
  `aggregate_privacy` verifier + the routing probe make the convention gated and
  load-bearing; a DB-level suppression (a `WHERE cohort_count >= k` view, or a policy
  filter) would harden this further and is a natural T6.6 companion. Stated, not hidden.
- **Demo floor is k=2/l=2, production keeps k=5.** The small dogfood datasets would fully
  suppress under k=5. The demo floor is small-but-non-trivial: a count-of-one still
  suppresses (the load-bearing guarantee) and a homogeneous cohort still suppresses.
