## Scope delivered (plan T3.11; vision doc "The external surface")

1. **`/api/v1` mounted over Identity + CRM** — `AshJsonApi` ONLY (plan OD-6).
   - `DemoWeb.Api.Router` (`use AshJsonApi.Router, domains: [Demo.Crm, Demo.Identity], prefix: "/api/v1"`).
   - `DemoWeb.Api.Endpoint` — the plug pipeline (`KeyAuthPlug` → `Router`).
   - `DemoWeb.Router` — the top-level host router; `forward "/api/v1", DemoWeb.Api.Endpoint`
     so the versioned prefix is exercised end-to-end (`/api/v1/contacts`, `/api/v1/users`, …).
   - Exposed resources: `Demo.Crm.Contact` (PII-bearing CRM), `Demo.Identity.{Org,User,Membership}`.

2. **Allowlist serialization (opt-in, default not-exposed).**
   - Each resource declares `json_api do show_fields([…]) end`. `show_fields` is the
     load-bearing schema-level allowlist: the AshJsonApi serializer filters every
     selected field through `AshJsonApi.Resource.Info.show_field?/2`, which requires
     `field in show_fields`. A field NOT named is ABSENT from every payload — even via
     `?fields=` (it can only narrow WITHIN the allowlist).
   - Proven: a public storage-backed attribute (`org_id`, injected `public?: true` by
     `CoreAttributes`) does NOT appear; the plaintext `notes` column does NOT appear;
     `?fields=org_id` cannot force it in (rejected or absent — both fail-closed).
   - Payloads carry CATALOG names (`:full_name`, `:display_name`, `type: "contact"`),
     never storage names (`cnt_*`, `com_*`, `pii_*`) nor vault tokens (`vt_*`) — asserted
     by a storage-name regex sweep over the whole response body.
   - Masked values serialize `••••` (the existing `Samen.Masked` Jason encoder).

3. **Two key classes (same policy stack, two actors).**
   - `DemoWeb.Api.KeyAuthPlug` resolves `Authorization: Bearer <key>` → a `%Samen.Scope{}`
     actor by SHA-256 digest lookup on `Demo.Identity.ApiKey` (never a plaintext key at
     rest; revoked keys rejected). It sets the actor's `:plane` (`:tenant | :operator`)
     from the key row and the `:api_key` map (for `Samen.Scope.ApiKey`).
   - **Tenant key** — org-bound; the org-scope FilterCheck isolates it to its own org,
     and `Samen.Api.PiiResolution` reveals its own-org PII in CLEAR (no reveal grant —
     the tenant owns its customers' PII).
   - **Operator key** — cross-tenant class; masked by default. `Samen.Api.PiiResolution`
     sets each vaulted field to `%Ash.ForbiddenField{}` (the serializer OMITS it →
     ABSENT) unless a live T1.6 grant covers the subject, in which case it reveals
     plaintext through the single vault chokepoint.
   - The two planes are the actor types the T3.1 policies + `Samen.Scope.ApiKey` already
     distinguish — no new policy stack.

## Simulated seams / honest edges

- **No AWS/Neon here.** The operator-plane reveal uses the real T1.6 `Samen.Reveal.Grants`
  model against local Postgres (request → distinct-party approve → time-boxed grant); the
  vault decrypt is the local `Samen.Vault` chokepoint. No cloud KMS is faked.
- **`/api/v1` mount** is proven through a real `DemoWeb.Router` `forward`; the demo has no
  full Phoenix endpoint (it is a LiveView dogfood), so the top-level router is a thin
  `Plug.Router` — the mounting contract (prefix strip → resource routes) is real.
- **Domain-extension collision:** `AshJsonApi.Domain` could not be added to `Demo.Identity`
  (macro import collides with the blueprint's nested resource `json_api/1`). Documented in
  code; the controller's per-resource route fallback is used instead, with a hand-written
  `json_api_match_route/2 -> :error`. `Demo.Crm` (top-level resources) uses the full
  extension. This is a real AshJsonApi seam, noted for the fan-out.
- **Contact write-side org-scope** is intentionally `always()` (the T1.9 dogfood seeds
  directly); write-side org-scope is proven on the policy-gated Identity scope (T3.1).
