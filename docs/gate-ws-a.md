## Cross-phase hunt (the round-2 focus — all 5 verified)

The five highest-risk interactions BETWEEN phases, each attacked by reading code plus one
live projection run and targeted test execution:

1. **A5 sample-data × A1 default-deny — SAFE.** Proven by a LIVE run of
   `Samen.Cdc.Projection.classify_columns` on `Driftwood.Crm.Person` (the actual
   sample-data CRM target): `fpr_display_name`/`fpr_job_title`/`fpr_custom` (freeform
   String/Map that sample-data populates) all classify `:plaintext_pii` and are PROVABLY
   ABSENT from `project/1`; only vault tokens + structural-safe scalars mirror. The
   projection is structural (keys on attribute declarations + two-reviewer `non_pii!`
   clearances), so a seeded value cannot change it.
2. **A4 notification for an A3-created record × per-plane masking end-to-end — SAFE.**
   `notifications_masking_test.exs` + `notifications_realtime_test.exs` prove the SAME
   notification (vault-routed body + `subject_ref` to a vaulted person) renders
   tenant-clear vs operator-`••••` with plaintext body+person-PII ABSENT and no `vt_` leak,
   both directions on one record (anti-tautology), across BOTH the rendered path and the
   realtime `handle_info` re-read-per-scope; the domain row stores the `vt_` token at rest
   (raw SQL).
3. **A3 write guard × A4/A5 framework writes — SAFE.** `Samen.Pii.WriteGuard` is injected
   by `Samen.Transformers.MaterializePii` into every resource's global `[:changes]`
   (verified: `add_entity([:changes], guard)` at `materialize_pii.ex:96-101`), so ALL
   create/update actions on any pii-bearing resource are guarded below any caller — no
   framework write path dodges it. A5 sample-data adds a belt-level operator-plane refusal;
   A4 engine writes nil-plane (system-authored, masked on read — correct).
4. **A2 keyset pagination × A4 realtime inserts — CONSISTENT.** `InboxLive.refresh/1`
   re-runs the current bounded read preserving sort/filter/cursor and re-counts the badge
   via a fresh `unread_count` (no increment/double-count); keyset is stable under head
   inserts.
5. **Fail-honest delivery × email prefs — HONEST.** An email-channel notification for an
   email-preferring user (`email_enabled: true`) lands status `:pending` (NOT fake
   `:delivered`; engine `initial_status(:email)→:pending` with no auto-flip) and only
   advances on a real adapter `{:ok}`; email is opt-IN (no pref row → `{:ok, :suppressed}`,
   zero records); `SendWorker.decide/3` blocks nil/unconfigured adapters in non-test env
   with anti-tautology pairing, and `LocalSink` is provably never the non-test fallback.

`marketing_session_roundtrip`), first-run (appears+disappears), sample/create (vault-routed

`dogfood_walkthrough_test` proves the end-to-end vertical spine incl. operator-plane
masking live. The ONLY skeleton-deep step is email SMTP/ESP dispatch — but that is
DISCLOSED out-of-scope (design §2.6, operator TODO) and fail-honest (`:pending` /
`{:error, :not_configured}`, never fake-delivered), so it is a documented limitation, not a
gap.
