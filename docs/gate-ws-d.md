## Findings

### WS-D-G1-P2-1 — adoption-sweep over-claim (P2)

D11.1 over-claim: the adoption unit states "After adoption, zero `%Samen.Type.FullName{}`
composites remain in ANY vertical lib" — but one exists at
`demo/lib/demo/support_scope.ex:261` (`Demo.SupportScope.Smoke.mk_agent/1`), an EXERCISED
person-PII create site (full_name composite + email through
`Ash.Changeset.for_create |> Ash.create`, the exact shape `Samen.Factory` replaces; called
by `demo/test/support_scope_policy_matrix_test.exs:360` via `Smoke.run/1`). The enumerated
adoption scope (6 sites in pawchart+driftwood) is accurate and demo was never in-scope, so
this is a precision defect in the summarizing sentence, NOT a correctness defect: the demo
Agent PII still vault-routes correctly, proven by
`demo/test/support_scope_vault_routing_test.exs:159-167` (asserts `vt_` tokens at rest for
`sag_full_name` + `pii_sag_email`, no plaintext). No gate/suite/red-path is affected. Fix:
either convert `mk_agent` to `Samen.Factory` (one more site, tightening the sweep) or narrow
the claim to "pawchart + driftwood libs". Flagged because the workstream's own
non-negotiable is "any drift is a finding".

### WS-D-G1-P2-2 — AC-G4-9's named LOC-parity assertion missing (P2)

AC-G4-9's named D6.2 deliverable has no covering test. The build-plan (D6.2) and design
(§5 AC-G4-9 Test clause) specify "an LOC-parity assertion in gen_app_test comparing emitted
authored LOC to a pinned bound" — grep for AC-G4-9 across the whole tree returns only
ADR-022 (a design doc); no test counts authored web+API+seed LOC vs a numeric bound (the
only `byte_size` assertion, `abbrev_allocator_test.exs:122` == 12_067, is the registry file
size). The SUBSTANTIVE half of AC-G4-9 (framework inherited, not re-emitted) IS covered —
and arguably more strongly — by structural drift-guard tests: `gen_app_test.exs:366` (router
mounts framework macros ONLY, zero authored LiveViews), `:400` (shell HTML inherited never
re-emitted), `:530`/`:552` (PageLimitClamp inherited never re-emitted). So the AC's
guarantee holds; the gap is the belt-and-suspenders numeric LOC bound the plan named. A
future regression that re-implemented framework code WHILE still mounting the macros would
be caught by the drift-guard tests, so residual risk is low. Fix: add the pinned
authored-LOC assertion the plan specified, or fold D6.2 into ADR text noting the structural
drift-guard supersedes the LOC delta.

No P0/P1.
