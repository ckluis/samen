Deep Dive: Communication & Social / Federation

Five self-hosted Elixir projects sit in this cluster, and all five share a domain samen has zero use for: ActivityPub-federated bulletin boards, social networks, event platforms, and community toolkits. None of it — federation, feeds, follows, boosts, moderation strike ladders — transfers to a multi-tenant B2B SaaS foundry, and the license mix keeps code-lifting off the table for four of five (Baudrate, Bonfire, Kammer, and Mobilizon are all AGPL-3.0; only vutuv clears MIT). What makes the cluster worth reading closely anyway is that federated/social products are forced to solve exactly the hostile-input problems samen's chokepoint philosophy already cares about — untrusted URLs, account takeover, privacy-by-default, i18n at scale — and three of the five converge hard on the same two answers: passkeys via wax_ and DNS-rebinding-proof outbound fetch. Where a lesson repeats across projects it is said once below and attributed to all; per-project cards then cover what's unique to each.

Cluster 1 — three projects converge on passkeys, two on step-up reauth

Samen's identity spine (ADR-035) has TOTP and OIDC but no hardware-key second factor — an open rung on the auth ladder. Baudrate, Kammer, and vutuv independently built the same answer with the same library (wax_ + eqrcode for the QR enrollment flow already used for TOTP), which turns "which WebAuthn library and what does the LiveView integration look like" from an open question into a settled one. The three implementations also agree on the one invariant that matters most: passkeys are a faster return login, never a new root of trust — vutuv states this explicitly (enrollment lives behind an already-authenticated settings page, the original password/PIN flow stays the only way to bootstrap an account), Baudrate mandates 2FA enrollment by role rather than letting it self-serve trust, and Kammer's usernameless discoverable-credential flow still feeds the same login handler that magic links use rather than forking a parallel session path. Kammer adds the detail worth stealing for clone-detection: COSE keys stored opaquely, `sign_count` checked to catch credential cloning. A second, related convergence: Baudrate and Kammer both build a generalized step-up ("sudo mode") layer on top of whatever first factor authenticated the session — Baudrate checks a `verified_at` timestamp on admin routes (stale past 10 minutes ⇒ redirect to TOTP/WebAuthn re-verify, 5 failures lock verification without dropping the session), Kammer instead scopes the elevation to the credential itself (`stepped_up_at` lives on the `users_tokens` row, dies with that token, cannot be replayed onto another device). Kammer's framing is the sharper of the two: the elevation is a property of the credential that asked, not the session. Samen has TOTP step-up for OIDC but no generalized version of this gate, and both projects hand it a ready list of trigger surfaces — PII reveal-grant approval, session revocation, DSAR export, and crypto-shred initiation are exactly the actions step-up gates were designed for in both source projects.

Cluster 2 — DNS-rebinding-proof outbound fetch, two implementations of the same three layers

Samen's fail-honest adapters and Samen.Delivery.Chokepoint already take operator- or tenant-supplied URLs (webhook subscriptions, org verification, fleet heartbeat endpoints per ADR-044), and the digest doesn't record a rebinding-proof answer for any of them — Baudrate and vutuv both do, and they land on the identical three-layer shape independently. Layer one is a literal, no-DNS check safe to run inside a changeset — reject localhost/private/link-local/reserved ranges outright, and vutuv is explicit that this must also catch the cloud metadata IP (169.254.169.254). Layer two closes the gap layer one cannot: resolve the hostname's A/AAAA records at fetch time, because a public hostname can have a DNS record that resolves to an internal address — this is the actual SSRF defense, not the literal check. Layer three closes the TOCTOU window between layer two's lookup and the real connection: pin the outbound connection to the exact IP just validated and set the Host header manually, so there is no second DNS lookup for an attacker to race or poison. Baudrate names this "ADR-0007" and applies it to every outbound POST including Web Push; vutuv's version (Vutuv.Ssrf) goes one step further, using the vetted-address pin to drive a headless-browser screenshot fetch through a loopback SOCKS5 proxy that dials only that address, covering redirects and in-page navigation too. Both make the resolver injectable for deterministic tests. This is a clean fit for samen's existing chokepoint discipline (`Samen.Delivery.Chokepoint`, the AI egress chokepoint) — one client, enforced by a verifier that no module calls `Req` directly outside it, exactly the "one place to audit" shape samen already applies elsewhere. Baudrate additionally specs a bounded hostile-fetch walk (≤N hops, ≤M distinct hosts, visited-URI cycle guard, rate limits keyed on the target host as well as the sender) for the day samen agents or link-unfurl features fetch attacker-influenced URLs.

Cluster 3 — Bonfire's Boundaries model as the design reference for G28

Samen's open RBAC-granularity gap (G28) currently has org-scope + role as its only sharing primitive; saved_views and support/CRM objects will eventually want per-record or per-group sharing. Bonfire's Boundaries system is the most battle-tested Elixir implementation of exactly that shape: named user-defined circles crossed with verbs (read, reply, like, quote, mention, edit) crossed with a three-valued grant (Yes / No / Nil), resolved most-restrictive-first — an explicit No always wins, Nil falls through to the next rule, and preset boundaries (public, local, follows, mentions) plus role bundles compile down to ordinary grants. The resolution semantics map cleanly onto Ash policy checks the way samen already composes `OrgScope` + `PiiResolution` — steal the model, not the code (AGPL-3.0). A scoped pilot (a circle resource + grant check inside existing Ash policies for one surface, e.g. saved_views) is M; generalizing it substrate-wide is L. Bonfire contributes two smaller, unrelated ideas worth noting alongside it. Its Epics pattern — pipeline steps declared as config data so any extension package can insert or wrap a step in another extension's workflow without editing it — is a useful review lens on samen's ADR-039 automation engine (Action registry → Compile → Reactor): the automation engine already covers execution, but Epics demonstrates the *authoring* seam samen's `Automation.Compile` should have if it doesn't already, so verticals like driftwood or pawchart can insert acts into a substrate-owned flow purely via config (S to audit the seam, M to add config-driven step injection). And its operator plane mounts Phoenix LiveDashboard plus an Oban queue monitor behind admin auth — a cheap, dependency-light addition that complements samen's ops-hardening workstream (WS-L, G11 metrics/alerts) (S).

Baudrate medium

ActivityPub-federated BBS on Phoenix/LiveView/Postgres with Rust NIFs for untrusted parsing — plain Ecto contexts, no Ash, no Oban. AGPL-3.0, single maintainer, 22-ADR security doc set, Wallaby e2e, notably itself an AI-authored codebase with committed CLAUDE.md/AGENTS.md.

Adopt: the SSRF-pinned egress client (Cluster 2, M); operator sudo mode / step-up reverification (Cluster 1, S–M); WebAuthn via wax_ (Cluster 1, M); first-run claim gate — setup-key-gated `/setup`, 503 until complete, guard duplicated in LiveView `mount/3` since websocket bypasses the plug, never enforced via a `runtime.exs` raise (S, directly template-able into `mix samen.gen.app`); rate-limiter failure-mode doctrine — Hammer fails open, `RealIp`/trusted-proxies fails closed (S); progressive per-account login delay over hard lockout (S); session-token hygiene — SHA-256-hashed tokens, dual token + 24h rotation (S each, verify what samen already has first); total-i18n discipline as the enforceable-convention playbook for G24 (no bare user-visible strings, gettext interpolation only, locales kept in sync — doctrine is S to write down, retrofit is L).

Skip: ActivityPub federation itself; the DB-backed delivery queue (right call for a single-node BBS, wrong once Oban is pinned); Rust NIFs (contradicts samen's no-NIF posture); config-keyed vault encryption (samen's per-subject-KMS vault is already stronger). AGPL-3.0 — patterns only, clean-room reimplementation, never code.

Bonfire medium

NGI/EC-funded toolkit for federated digital spaces, composed from per-feature extension repos into deployable "flavours." Phoenix + LiveView + Surface, plain Ecto (not Ash) via the Needle universal-pointer layer, Oban, GraphQL, Meilisearch. AGPL-3.0, ~933★, actively maintained.

Adopt: the Boundaries three-valued ACL model as the design reference for G28 (Cluster 3, M scoped pilot / L substrate-wide); the Epics config-declared pipeline as a review lens on the ADR-039 automation engine's extensibility seam (Cluster 3, S audit / M to build); LiveDashboard + Oban queue monitor under the operator plane (Cluster 3, S); release-channel discipline (stable/RC/beta/alpha tags) if samen ever ships `mix samen.gen.app` outputs to external builders (S, docs only).

Skip: the Needle universal-pointer data layer (trades away referential integrity and would fight samen's Ash resources and verifiers — samen's `object_ref` + catalog already solve this); ActivityPub federation and the whole social domain; separate-repo-per-extension modularity (contradicts ADR-033's in-monorepo distribution); LiveAdmin's raw DB browser (exactly what mask-by-default forbids); Meilisearch, Surface UI, GraphQL, Co-op Cloud/Guix deploy paths. AGPL-3.0 — steal the model, never the code.

Kammer medium

Self-hosted community platform ("Facebook Groups for associations") on Phoenix 1.8/Ecto with a Svelte PWA frontend, Oban, Docker Compose. AGPL-3.0, pre-v1, tiny audience but strikingly disciplined: 29 ADRs, Credo strict + Dialyzer + coverage floors, Playwright e2e — and notably authored primarily by Claude working autonomously on the issue queue, the same development religion samen applies to itself.

Adopt: step-up reauth as a credential-scoped token property (Cluster 1, M); passkeys via wax_ (Cluster 1, M); three-tier settings precedence — DB-backed admin UI overlaid by boot-validated env (rate limits, token lifetimes) overlaid by non-configurable module-attribute security constants, "security footguns shouldn't hide behind runtime knobs" — plus its first-run wizard, setup token printed to server logs (M doctrine + settings resource, S wizard on top of existing onboarding); email privacy mode — an instance-level switch stripping content from notification emails so substantive content never transits third-party ESPs, a `content_minimal` variant of the Delivery Chokepoint (S); `sobelow` + `mix_audit` added to the CI gate, closing a supply-chain/OWASP lane samen's bespoke verifiers don't cover (S); i18n + timezone existence proof (gettext + `tz`) validating the G24 library set already confirmed elsewhere in this scan (L for the retrofit, libraries now de-risked).

Skip: all code verbatim (AGPL-3.0); the Svelte PWA migration (samen is LiveView-committed); domain features — feeds, polls, sealed groups, decisions register; presets-not-ACLs (right for a consumer product, wrong once samen's Ash-policy + reveal-grant model is the differentiator); the plain-Ecto context architecture.

Mobilizon medium

Framasoft's federated event/group platform — Elixir/Phoenix API-first behind a Vue SPA + Absinthe GraphQL, PostGIS, Oban, Guardian JWT + wide Ueberauth matrix. Mature (~6,900 commits, 91 releases, active since 2017). AGPL-3.0-or-later, no Ash, authorization via a forked GraphQL middleware rather than a policy engine.

Adopt: the extracted `geospatial` hex package — a pluggable `Provider` behaviour (Nominatim, Addok, Photon, Mimirsbrunn…) swapped by one config line — as the shape for a `Samen.Geo.Provider` INV-4 adapter package with fail-honest `{:error, :not_configured}` skeletons (S–M); tokenized private ICS feed URLs as a distinct revocable-credential class layered on samen's existing ICS support and grant/audit machinery (S); web push (`web_push_encryption`, VAPID) as a third notification channel behind the Delivery Chokepoint (M); one named rich-text sanitize chokepoint (`fast_sanitize` + Floki + `linkify`) for any scope with user-authored markup — cms, docs, chat, support (S); `ex_cldr` + `tz_world`/`tzdata` as a further-validated G24 library set, including the timezone-from-lat/long trick any calendar scope eventually needs (M library adoption, L full gettext sweep); anonymous, capability-token, email-confirmed participation as a pattern for end-customer-facing verticals like pawchart booking (M, only when a vertical needs it).

Skip: ActivityPub federation and instance moderation/relays; Absinthe GraphQL + Vue SPA + Dataloader + `rajska` authz (would fork samen's deny-by-default JSON:API + Ash-policy authz story); Guardian JWT + the wide Ueberauth OAuth matrix (samen's assent-based ADR-035 spine is stronger and already vaulted); PostGIS (heavyweight until a vertical needs radius search). No multi-tenancy, no masking/vault, no policy engine, no verification harness — domain reference only, not a substrate reference.

vutuv medium

Self-hostable federated professional network ("LinkedIn of the Fediverse"), MIT-licensed, ~90 top-level context modules of plain Ecto/Phoenix (no Ash), Bandit, LiveView, Tailwind v4, a reference production install (vutuv.de). Active daily development, 334★, last push same-day as this scan.

Adopt: the three-layer SSRF module (Cluster 2, S–M); passkeys via wax_, never a root of trust (Cluster 1, M); a versioned DSAR self-serve export registry (`@schema_version` with an inline changelog, required to stay in lockstep with `delete_user/1`) for the open G19 gap — samen's catalog and `pii_declared` metadata could auto-derive most of it (M); a member-facing account-activity log complementing samen's hash-chained audit — a *declared* vocabulary of event kinds with a build-time test that fails if any `details` key looks like a credential, emails masked at write time rather than read time, no IP stored, and admin reads of a member's log themselves logged as an event on the admin's own account (S); a blue/green deploy script as a concrete worked example of the invariants samen's Fly production deploy (currently operator-TODO) needs — backward-compatible migrations, health-gated cutover, single-flight lock, careful cleanup-on-abort (S to read as reference, M to adapt); bounce-driven deliverability state — hard-bounce ledger, address marked undeliverable, account frozen only after repeated failures, auto-thaw on next successful login — as an optional `samen_core` capability feeding the ESP adapters (M); the same real bilingual gettext + `ex_cldr` + `ex_phone_number` + `tz` (compiled into the release, no runtime network) stack as a third production-proven G24 reference (L, own ADR + phased items per the decompose-cross-cutting-changes convention).

Skip: the entire product surface — profiles, follows, DMs, job board, CV export, organization pages; ActivityPub/Fediverse federation and Bluesky bridging; the moderation strike ladder and reporter trust scoring (no analogous surface today); the single-node ETS rate limiter, explicitly weaker than samen's already-pinned `ash_rate_limiter` + Hammer combination; ads/newsletter/CV-export subsystems; German-Impressum-law-specific legal pages.

Net read: nothing in this cluster is vendorable at the code level (four of five AGPL, only vutuv MIT), so its value is entirely as hardened design reference for problems samen already has open gaps against. Two convergences carry the most weight because independent teams solving unrelated problems landed on the same answer: wax_ passkeys plus credential-scoped step-up reauth (Baudrate, Kammer, vutuv) directly fills the missing rung on ADR-035's identity spine and hands samen ready trigger points — reveal-grant approval, DSAR export, crypto-shred initiation; and the three-layer SSRF-safe egress pattern (Baudrate, vutuv) closes an unaddressed DNS-rebinding gap in the webhook/AI-egress chokepoints with a design that composes directly with samen's existing "one place to audit" discipline. Bonfire's Boundaries model is the strongest single design reference for the open G28 RBAC gap, sized to a cheap scoped pilot before any substrate-wide commitment. Everything else — Mobilizon's geocoder behaviour and sanitize chokepoint, vutuv's DSAR export and activity log, Kammer's config-tier doctrine and email privacy mode — is S–M reference material that closes named, already-tracked gaps (G19, G24, G28) rather than opening new scope. Effort clusters low across the board; the one L item (i18n) is cross-cutting by nature and already flagged for the ADR-plus-phased-items treatment elsewhere in this scan.
