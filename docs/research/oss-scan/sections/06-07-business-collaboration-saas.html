Deep Dive: Business & Collaboration / Productivity SaaS

Six self-hosted Elixir SaaS products sit in this cluster — a translation management system, an artisan-manufacturing ERP, a venue/staff-ops platform, a goals-and-projects "operating system," a Calendly clone, and a document-lifecycle/e-sign platform. None of the six offer a substrate to lift wholesale: four are AGPL-3.0 (Craftplan, nyght, Tymeslot, Wraft — patterns and library picks only, never source), one is Apache-2.0 with a separately-licensed enterprise slice (Operately), and only one clears MIT-compatible outright (Accent, BSD-3-Clause). What makes the group worth reading together is the convergence: four independent codebases, built by different teams for different problems, land on the identical ex_cldr + gettext + tz stack to solve i18n — strong signal for closing samen's own G24 gap. A second convergence, just as loud, is four different teams each inventing a new "scope" vertical samen's blueprint catalog doesn't have yet (staffing/shifts, bookable scheduling, light-ERP/inventory, document-lifecycle). A third, quieter thread: three of the six independently reject cloak_ecto-shaped field encryption in favor of nothing stronger, which functions as repeated confirmation that samen's ADR-003 vault (per-subject KMS keys, crypto-shred) is already ahead of the ecosystem norm — nothing to adopt there, just validation.

Cluster 1 — four codebases, one i18n stack (closes G24)

Samen is hardcoded to USD and UTC with no gettext catalog — an acknowledged P2 gap (G24). Four unrelated projects in this batch independently converged on the same fix. Craftplan pairs Cldr, Gettext, and the tz timezone database with ash_money/ex_money_sql on the same Ash 3 base samen runs, which makes it a working reference for exactly the libraries samen would pick and confirms they compose cleanly with Samen.Type.Money. nyght proves the identical stack (ex_cldr + ex_cldr_dates_times/calendars/territories/plugs + gettext 1.0 + tz/tz_extra) in a real production, multilingual (fr/de/en) Phoenix 1.8/LiveView 1.1 app, and adds a detail Craftplan doesn't: Weblate as the community translation pipeline, plus locale negotiation via ex_cldr_plugs. Tymeslot proves the same core (gettext + tz) still works at samen's exact current stack versions (Elixir ~1.20/OTP 28, Phoenix 1.8, LiveView 1.1) with six shipped UI locales. Accent contributes a different, complementary piece: not the runtime stack but the data model for the string catalogs themselves — a neutral Document/Entry/ValueType core (lib/langue/) with pluggable per-format parser+serializer pairs behind one behaviour, which is the right shape reference for samen's own i18n string import/export chokepoint (one module, format plugins, round-trip tested — the same discipline samen already applies to its RFC-4180 CSV chokepoint). Put together: three projects de-risk the library selection for G24, one de-risks the format-abstraction design once G24 actually builds import/export. Per the decompose-cross-cutting-changes convention, G24 itself should land as an ADR plus phased items rather than one L-sized push, but the risk of picking the wrong libraries is now close to zero.

Cluster 2 — four projects, four proposed scope blueprints

Samen's scope catalog (work, calendar, locations, docs…) has gaps that these four AGPL products each fill with a different, well-proven vertical shape — none copyable as code, all copyable as design. nyght contributes shifts/staffing: a shift + shift_location + application model (worker applies, manager approves) that maps cleanly onto samen's E3 approvals engine and calendar/notifications scopes — a recurring need across venues, clinics, field service, and retail. Tymeslot contributes bookable scheduling: a layered availability engine (weekly schedule → date overrides → breaks → buffers/min-notice → conflict merge against synced calendars → slot generation) plus a public booking page, the natural fit for pawchart's vet-appointment vertical, backed by the best open Elixir calendar-sync adapter family found in the scan (Google/Outlook/Apple iCloud/CalDAV/Nextcloud/Radicale/Zimbra/Baikal, with reconnection and cross-calendar conflict detection). Craftplan contributes a light-ERP/inventory idea bank: versioned BOMs with cost rollups, movement-based inventory, production batching, and a pure forecasting module — filed as reference rather than a build, since samen already has versioning and rollup machinery a third vertical could reuse. Wraft contributes document lifecycle: content authored as Markdown+JSON, strictly separated from layout, compiled through a typesetting engine to branded PDFs — directly relevant since every samen vertical eventually needs generated documents (driftwood BOLs/invoices, pawchart discharge summaries, G8 dunning letters), with a natural samen_typst adapter package keeping the engine dependency out of core per INV-4. Wraft's second contribution extends samen's own approvals machinery rather than inventing new machinery: external-counterparty signing — a document state machine (draft → approved → sent → signed) plus QR verification, layered onto the existing E3 requester≠approver engine and AshStateMachine, with the counterparty treated as a vaulted, masked-by-default identity and the sign token time-boxed like a reveal grant. That's the same "governed signing" idea nobody else in the ecosystem has, because nobody else has samen's masking/vault substrate to hang it on.

Cluster 3 — Operately: the one with a clean-enough license to study closely

Operately's core is Apache-2.0 (a separate license covers optional enterprise files), which puts it a notch closer to actually inspectable than the four AGPL neighbors in this batch, even though samen would still re-derive rather than vendor. Two pieces are worth real attention. First, its MCP OAuth model: grants carry mcp:read/mcp:write-style scopes that default to read-only when unrequested, each grant binds to exactly one company so a tool structurally cannot take a tenant-selection argument, arbitrary clients connect via Client ID Metadata Documents with no pre-registration step, and operators get a connection dashboard with immediate revocation. That one-grant-one-tenant rule is the same shape as samen's token-blind, org-scoped actor discipline, and it's a concrete hardening target for samen's own MCP server (ADR-043, currently per-operator tokens over HTTP+SSE) — samen already has assent, sessions, and revocation machinery, so this is composition, not new infrastructure. Second, Operately ships the packaging layer samen's G22 gap ("agent-grounding packaging for builders") is missing: a small CLI over its API, published agent skills for Claude Code/Codex/OpenClaw, and docs written for AI agents as a primary client persona — the last mile samen's catalog and MCP server don't yet have. Two smaller items round out the card: a per-mutation activities record that doubles as both audit trail and a human-readable feed (samen already pays the write cost via its hash-chained audit and wide events; a masked-aware read-side projection would convert that into product value with zero new invariant risk), and an opinionated check-in-cadence engine on top of goals/projects (scheduled reviews, on-track/at-risk status, reminder jobs) that's a vertical-agnostic depth addition to samen's existing work scope, buildable from parts samen already owns (Oban scheduling, notifications, automation engine).

Accent medium

Self-hosted developer-facing TMS (Phrase/Crowdin alternative): Phoenix + GraphQL backend, format-agnostic Langue parser/serializer core, MT provider adapters, per-string collaboration and rollback. v1.30.5, BSD-3-Clause, ~1.5k★, actively maintained.

Adopt: Accent itself as the fleet's translation workflow once G24 lands — self-hosted, CLI+GraphQL-driven, exactly the "many repos, one translation team" shape a foundry needs (M, ops integration only); the Langue Document/Entry/ValueType format-abstraction pattern as the design reference for samen's own i18n import/export chokepoint (L when G24 builds it, reference-only now); opentelemetry_oban to round out samen's existing OTel stack (S); telemetry_ui as a small first-party-friendly metrics-panel dep for the operator cockpit (S–M).

Skip: Absinthe/GraphQL (samen is deny-by-default JSON:API), ueberauth (samen standardized on assent), cloak_ecto (weaker than ADR-003's vault), the EmberJS frontend, and the product's core domain code — nothing exports as a Hex dep to vendor.

Craftplan medium

Single-tenant artisan-manufacturer ERP on Ash 3 + ash_postgres: versioned BOMs with cost rollup, production batching, lot-traced inventory, z-score demand forecasting, JSON:API + GraphQL. AGPL-3.0, ~1.1k★, v0.6.0, actively maintained.

Adopt: ex_cldr + gettext + tz wiring on the same Ash 3 + ash_money base samen runs (Cluster 1, M); its waffle + ex_aws_s3 + MinIO local-dev setup as the reference for turning samen's honest Storage.S3 stub into a real, CI-provable adapter (M); open_api_spex-emitted OpenAPI docs alongside JSON:API, strengthening samen's contract-verifier story and G22 grounding (S); the singleton encrypted-settings-resource UX for runtime email-provider selection, adopting the shape only — Craftplan's own cloak_ecto storage must be swapped for samen's vault (M); the inventory/manufacturing domain decomposition as an idea-bank reference for a future light-ERP vertical (L, file don't build).

Skip: any code reuse (AGPL vs MIT), ash_authentication, ash_graphql, cloak_ecto encryption, and its single-tenant CSV/command-palette/iCal handling — samen's equivalents already meet or exceed these.

nyght medium

Real, revenue-adjacent venue/staff-ops platform (plain Ecto, no Ash) run by a Swiss music venue under a paying-member steering committee: events, shifts with volunteer applications, integrations marketplace, DB-backed RBAC. AGPL-3.0, 2,759 commits, 67 releases.

Adopt: the CLDR-first i18n stack proven in fr/de/en production (Cluster 1, L, cross-cutting per the decompose rule); shifts/staffing as a new scope blueprint (Cluster 2, M); its Integration/Installation split with per-adapter config UI and tenant-visible buffered delivery logs, as the pattern for a tenant-facing "install and configure an integration" surface samen's webhook machinery lacks today (M); DB-backed granular RBAC (org-defined roles from a permission catalog) for the open G28 gap (M); hand-rolled iCalendar/vCard emission confirming samen's zero-dependency ics approach and adding a vCard idea (S); sobelow in CI, cheap to add to samen's gate (S).

Skip: the plain-Ecto context architecture (Ash + generators already supersede it), cloak_ecto, Flop pagination (would regress samen's keyset-pagination contract), and Kino/kino_db in prod deps.

Operately medium

Goals/OKRs, projects, and team-space "operating system" for 5–100 person teams. Phoenix/plain-Ecto backend, React+TypeScript frontend (diverges from samen's LiveView), hosted MCP server with OAuth. Apache-2.0 core, ~543★, 4,300+ commits, active.

Adopt: MCP OAuth with default-read scopes and single-tenant grant binding, as a direct hardening target for samen's ADR-043 MCP server (Cluster 3, M); agent CLI + skills packaging closing the G22 last-mile gap (M); check-in cadence engine deepening the work scope (M); a masked-aware activity feed as a read-side projection over samen's existing audit substrate (S–M); site_encrypt in-BEAM Let's Encrypt as a reference for a future self-host lane (S to note, M to ship).

Skip: the React/GraphQL/Apollo frontend and API layer (reverses samen's LiveView + deny-by-default JSON:API decisions and reopens the %Masked{} server-side-rendering problem), plain-Ecto operations-pattern architecture (Ash actions + chokepoints already deliver the same audit/notify pipeline), ueberauth, and the tenancy model (no PII vaulting, no two-plane split — strictly weaker than samen's).

Tymeslot medium

Self-hosted Calendly alternative backing a real managed cloud (tymeslot.app): named availability schedules, calendar sync across seven+ providers, Stripe Connect payments. Same-stack as samen (Elixir 1.20/Phoenix 1.8/LiveView/Oban). AGPL-3.0, v1.11.1, ~3,300 commits.

Adopt: the calendar-sync adapter family (Google/Outlook/CalDAV/Nextcloud/…) as a samen_calendar_* vendor package with reconnection and conflict detection, feeding OAuth refresh tokens through the vault (Cluster 2, L); the layered availability/booking engine for a scheduling scope (Cluster 2, M on top); signed no-login action links (HMAC, expiring, single-purpose) as a general "capability URL" primitive for notifications/DSAR/approvals (S); its SSRF guard suite (DNS pinning, private-IP rejection, URL validation) at the outbound-webhook/CalDAV chokepoint (S–M); online credential re-encryption workers as a modeled key-rotation drill for samen's vault (M); excellent_migrations + sobelow + mix_audit for the CI gate (S); its Stripe Connect integration as a live reference once samen's G13 stub goes live (reference only).

Skip: any code reuse (AGPL), plain-Ecto architecture, its auth stack (samen's identity spine is already deeper), video-provider/Slack/Telegram integrations, and single-container bundled-Postgres deploy (contradicts samen's Fly/Neon posture).

Wraft medium

Open-source Document Lifecycle Management platform (DocuSign/PandaDoc alternative): content-type → template → layout/theme → typesetting-engine → branded PDF, with external counterparty signing. Elixir/Phoenix, Rust NIF PDF analyzer, recent AI additions. AGPL-3.0, ~1,685 commits, v0.6.6.

Adopt: the structured document-generation pipeline as design input for deepening samen's shallow docs/cms scope, via a fail-honest samen_typst adapter package (Cluster 2, L full depth, M first cut); external-counterparty signature lifecycle extending E3 approvals with a vaulted, masked counterparty identity and QR verification (Cluster 2, L, design as an ADR first); reusable content blocks/templates/frames as the authoring schema underneath the pipeline (M, bundled with the pipeline item); OpenAPI spec emission strengthening G22 grounding (M).

Skip: any code lifting (AGPL), jido_ai/req_llm (samen already evaluated and rejected Jido), cloak_ecto, mutable ex_audit (samen's hash-chained WORM audit is strictly stronger), backpex admin + fun_with_flags (first-party operator plane and feature flags already exist), the Rust NIF PDF analyzer (no-NIF posture), ex_typesense (Postgres tsvector is the settled search story), and y_ex/Yjs collaborative editing (large PII-masking surface, revisit only once the docs scope itself ships).

Net read for a product leader skimming only this section: nothing here is vendorable at the code level — four of six projects are AGPL, one is Apache-2.0-with-caveats, only Accent is outright clean — so this cluster earns its keep as design evidence, not dependencies. The clearest, lowest-risk win is closing G24: four independent codebases converge on ex_cldr + gettext + tz, which turns "which i18n libraries" from an open question into a settled one, leaving only the (already-flagged, ADR-plus-phased-items-sized) integration work. The second win is a menu, not a mandate: four well-proven scope blueprints (staffing/shifts, bookable scheduling, light-ERP, document lifecycle) that samen can pull off the shelf whenever a vertical actually demands one, each cleanly composable with machinery samen already owns (E3 approvals, calendar/notifications scopes, the vault, INV-4 adapter packages). The third is Operately's MCP OAuth scope model and agent-CLI packaging — the one item in this section that's both concretely actionable now and sitting on the cleaner license, directly hardening samen's own ADR-043 MCP surface and closing the G22 agent-grounding gap. Effort clusters at S–M for the immediately actionable items, with the vertical-scope and document-pipeline ideas correctly filed as L idea-bank material rather than queued work.
