Deep Dive: AI Agent Products & Personal Assistants

Nine self-hosted, BEAM-native agent products — AlexClaw, Ankole, Glorbo, Long, OSA, Pepe, Shem, Vibe, ZAQ — cluster together for the opposite reason the license-risk section did: nothing here is legally blocked, but every one of them is architecturally wrong for samen at the top level. All nine are single-user or single-tenant by design (no org model, no policy layer in samen's sense, several run bash/shell tools with full host access or eval directly against the runtime), and several are built on stacks samen has already rejected on the record (Jido, in Long and ZAQ; a filesystem-as-source-of-truth posture in Glorbo that has no answer to crypto-shred or org-scoping). None is a dependency candidate — bus factor ranges from "one maintainer, 0 stars" (Shem, Pepe) to "42–224 commits, pre-1.0, no compat contract" (Ankole, Glorbo) even at the higher-star end (Vibe ~99★, ZAQ 66★). What they are, collectively, is the densest idea-mine in this scan for one specific target: samen's own ADR-047 agent loop and the open G22 gap (packaging agent grounding for builders). Because eight of the nine independently solved overlapping problems — cost-aware model routing, long-horizon memory under a context budget, tool/skill discoverability, agent self-scheduling, egress attribution — the pattern below groups by lesson first and attributes every source, then gives each project its own card with the concrete adopt/reject call. Read the clusters for the design target; read the cards for provenance and effort.

Cluster 1 — cost control by construction: tiered routing and fail-honest budgets

Four projects independently arrive at the same shape for AI spend: classify the request, route it to the cheapest model tier that can do the job, and refuse rather than silently run up an unattributed bill. AlexClaw's router is DB-backed (provider type/tier/priority/daily-limit rows) with ETS+DB usage counters keyed {provider, date} and a step > workflow > global tier-override hierarchy. OSA classifies every inbound message into a 5-tuple and routes across a three-tier model ladder (utility/specialist/elite) with automatic mid-stream fallback. Pepe runs a one-shot triage classifier at session start that downgrades the whole session to a cheaper model on a "SIMPLE" verdict, paired with an explicit failover event on transient errors so substitution is never silent. Glorbo is the outlier worth stealing whole: its BudgetTracker.check_budget/1 returns a tri-state — :ok / {:alert, used, cap} (80%, deduplicated) / {:stop, used, cap} (hard refusal) — and, critically, a provider whose usage parser can't attribute cost is refused at dispatch unless the caller explicitly opts in. That refusal is exactly samen's fail-honest adapter doctrine (ADR-014/024/026/038) applied to AI spend: samen's AI kernel already has one real provider behind Samen.AI.Provider and ADR-047 already commits to budgets and cost caps, so the tier router and the tri-state check are two halves of the same feature, both fitting as chokepoint-side logic — never inside `samen_anthropic` itself, per INV-4 — and both testable with the same sabotage-harness discipline the rest of samen uses (flip the refusal, a named test fails). Effort M for the router, S for the tri-state refusal grafted onto the existing budget substrate.

Cluster 2 — long-horizon memory: consolidation, chunking, and compaction under a context budget

A durable multi-turn agent loop eventually runs into two related but distinct pressures — the working context window fills up, and the useful facts from old sessions need to survive into new ones — and this scan turns up a clean division of labor between them. For the context-window pressure, OSA's 6-step pipeline (micro-compact old tool results, strip/merge tool args, structured compression, 413-recovery collapse, post-compact reinjection of critical context, priority-weighted budget allocation) and Pepe's simpler at-60%-replace-the-middle-with-a-summary approach — including Pepe's explicit tradeoff note that per-turn "micro-compaction" keeps cost steady but breaks provider prompt-cache reuse — are both directly portable to ADR-047's loop, with one non-negotiable samen twist neither source enforces: every compaction/summarization call is itself governed egress and must run through the masking chokepoint with a per-turn grant re-scrub, and the compacted history must stay crypto-shreddable (tokens, not restored plaintext) to respect the ADR-046 erasure envelope. For the cross-session pressure, Ankole's "Dreaming" is the standout design doc: a two-stage offline job (Stage A collapses raw chat into episode summaries; Stage B curates episodes into knowledge entries) triggered by silence/backlog thresholds, where the cursor advances only on success and every persisted block must cite a canonical source marker — paired with a before/after audit log that supports inverse-operation recovery (replay newest-to-oldest, stop on conflict rather than clobber) and withdrawal propagation (deleting a source reverses only the derived blocks that still match it). AlexClaw contributes the mechanical half that composes underneath either design: async embed-after-insert so writes never block on the embedding call, parent/child semantic chunking (children embedded, parent keeps full text, search dedups by parent), and embedding-model staleness tracking with a batch reembed_all. Ankole's recall recipe layers on top: hybrid keyword+vector via Reciprocal Rank Fusion, exponential temporal decay with a knowledge floor, and per-candidate token caps inside a global budget so one long thread can't starve others — directly upgradeable onto samen's existing pgvector + non-PII tsvector search using Postgres FTS instead of Ankole's ParadeDB dependency, so zero new infra. The unifying samen-specific constraint across all of it: consolidation, chunking, and recall all operate on already-masked content and gate any shared-store write through the E3 approvals engine — Ankole explicitly ships no approval flow for memory writes, which is the one place samen should deliberately diverge. Effort M for compaction (both sources), L for full Dreaming-style consolidation, S each for staleness tracking and parent/child chunking.

Cluster 3 — skills as data: progressive disclosure over hand-registered tools

Three projects converge on the same fix for a tool catalog that grows without bound: stop putting every tool/skill's full definition in every prompt, and instead give the model an index it can pull from on demand. ZAQ's "Open Agent Skills" implementation is the most rigorous: skills live as DB records (name, description, markdown body, tool keys); the system prompt carries only the name+description index (O(skill count) tokens, not O(skill count × body size)); a load_skill tool call pulls the full body as a tool result, scoped to the invoking agent's own enabled skills, with an explicit fix over the pattern's upstream form — a not-found response never enumerates the catalog, closing an info-leak. Long's version is filesystem-native (SKILL.md files with YAML frontmatter, a watcher-driven ETS index, per-member-vs-promoted-to-global scoping) and is the more portable authoring format since it's Anthropic-ecosystem-compatible — operators could author skills as files that mix samen.gen.agent then consumes. Vibe adds the generative end of the same loop: distilling a successful session into a reusable, versioned skill discovered from well-known paths ("create a skill from what just worked"). All three map onto the same samen shape — a skills-as-data extension of the Prompt resource, index-only in the system prompt, full body loaded via a governed tool call that stays inside the EG2 masking chokepoint, personal-vs-global scoping mapping to tenant-vs-operator plane, and any session-to-skill distillation routed through the normal review/approval path rather than auto-trusted. This is the most direct available design input for G22 (packaging the agent-grounding differentiator for builders), a gap the report currently has no other section closing. Related but adjacent, three projects add self-scheduling verbs worth folding into the same automation surface: Ankole's typed check_back_later wake event (a durable "check back at T" ActorEvent the loop consumes), Long's agent-initiated createScheduledTask mid-conversation, and Glorbo's heartbeat-with-empty-inbox grooming tick (agent dispatches against a checklist even when nothing is queued) — all three are thin wrappers over machinery samen already has (Oban + ash_oban + ADR-039's automation engine), landing as agent-proposable drafts routed through the E3 approvals engine, never auto-executed. Effort M for the skills-as-data extension, S–M for each self-scheduling verb.

Cluster 4 — the governance fine print: injection, attribution, identity, and honest replay

The remaining patterns are smaller but sharper, each closing one specific hole in the ADR-047 loop rather than a whole subsystem. AlexClaw's ContentSanitizer is the complementary threat to samen's egress-only chokepoint: a layered scrubber (zero-width Unicode stripping, hidden-HTML/CSS detection, a runtime-data injection-pattern list, an imperative-tone heuristic) applied to external content before it enters prompt assembly — samen governs what goes out via %MaskedPayload{}, but nothing today governs what comes in from tool results and web content, which is exactly what the ≥90% red-team eval bar should be measuring on both sides. Glorbo's per-dispatch egress attribution token (an ephemeral id minted per agent dispatch, stamped into every audit event downstream) and ZAQ's trusted-execution-context identity rule (identity for permission-scoped tools comes only from the loop's actor context, never from LLM-supplied parameters — an explicit skip_permissions: true opt-in required to override, and a blank/nil actor is never an implicit grant) are two sides of the same "know who really caused this" problem, and both are cheap: threading a dispatch id through the AI chokepoint into the hash-chained audit is a schema addition, and the actor-never-from-params rule is exactly the kind of AST/structural check samen's samen.verify.agent_coverage tier already does for other invariants. Shem contributes the most differentiated idea in the section: deterministic replay of recorded agent-loop turns as a CI regression tier (samen.verify.agent_replay-shaped — replay recorded events, diff against current code, fail on divergence) plus fail-closed declared-action tool manifests (undeclared action ⇒ refused, checked by a manifest-parity verifier) and offline-verifiable attestation bundles (a stdlib-only verifier script an auditor can run with no samen checkout) — all three extend samen's existing "every guarantee ships with a proof" culture into the AI plane specifically, and the replay tier is buildable now since EG2-governed transcripts and fixture-transport cassettes already exist. ZAQ's smaller persist-before-deliver ordering rule (transcript persistence must succeed before channel delivery, never delivered-but-unrecorded) is almost certainly already true of samen's delivery chokepoint but is worth encoding as a named, sabotage-able red-path test rather than left implicit. Vibe closes the loop with pure operator-plane ergonomics: first-class inspect/cancel/resume verbs on a running agent run (an operator "stop this run now" button, audited, mostly wiring existing OTP + AshStateMachine state to UI) and multi-surface attach (TUI and LiveView as adapters over one supervised session) as a live-attach affordance for the operator cockpit. Effort S–M across the cluster; the replay tier is the only M-leaning item, and none require new infrastructure beyond what ADR-046/047 already ships.

The nine, in detail

AlexClaw medium

A self-hosted, single-user BEAM-native personal agent (Apache-2.0, 115★, actively maintained) on samen's own stack — Phoenix LiveView, Ecto/Postgres + pgvector — monitoring RSS/web/GitHub sources, running scheduled workflows, and talking to its owner over Telegram/Discord.

Adopt: the ContentSanitizer inbound-scrubbing pattern (Cluster 4); the DB-backed tier-based LLM router with ETS+DB usage counters (Cluster 1); embedding-model staleness tracking + batch reembed, and parent/child semantic chunking with search dedup (Cluster 2); capability-token attenuation (HKDF-derived, chain-depth-capped) for nested tool/agent calls, adopted as a concept into Samen.AI tool dispatch, not its process-dictionary carriage.

Why it fits: same stack, different domain — no wholesale adoption, but five to six concrete AI-plane patterns transfer cleanly because they're already Elixir/Postgres/pgvector-native.

Ankole medium

A self-hosted "AI workforce operating system" (Apache-2.0, 42★, MVP/early-production, explicit no-compat-contract) — agents as bounded-authority workers with durable execution and an operator console — but built on a polyglot Rust-NIF/Bun/ZeroMQ runtime samen deliberately avoids.

Adopt: the Dreaming two-stage memory consolidation blueprint, citation-required audit-reversible memory blocks, and withdrawal propagation (Cluster 2, this project's design docs are the reference blueprint); RRF-based recall ranking with temporal decay and per-candidate token caps (Cluster 2); the typed check_back_later wake-event verb (Cluster 3); Oban Lifeline as a stale-lock guard for long agent jobs.

Why it fits: don't adopt the platform — the polyglot stack and CEL-based AuthZ conflict with samen's pure-BEAM, zero-NIF posture and its already-stronger Ash-policy trust kernel — but mine the unusually rigorous design docs as the reference blueprint for agent long-term memory.

Glorbo medium

A filesystem-first agent orchestration platform (MIT OR Apache-2.0, 3★, pre-1.0) modeling companies as org charts with AI-agent "employees" run in kernel-level bwrap sandboxes; state is Markdown + YAML/JSONL with SQLite as a rebuildable index — the structural opposite of samen's Postgres/Ash substrate.

Adopt: the tri-state fail-honest budget check with explicit-opt-in for untracked-cost providers (Cluster 1); per-dispatch egress attribution tokens (Cluster 4); heartbeat-with-empty-inbox maintenance ticks (Cluster 3); a mix samen.doctor-style operator preflight composing samen's ~20 existing verifier tiers into one command.

Why it fits: adjacent domain, tiny community, but a serious solo-built OTP codebase with three to four concrete governance patterns worth mining for ADR-047 — take patterns, not code; the company-as-employees metaphor and filesystem-as-truth model add nothing over samen's stronger substrate.

Long medium

A LAN-first, single-binary LLM agent runtime for a household or small team (MIT, ~26★, beta) — and, unexpectedly for the category, a genuine Ash 3 stack (AshSQLite, AshOban, ReqLLM, Jido). Trust posture is the deliberate inverse of samen's: no RBAC, unsandboxed bash tool, no PII controls, no cost budgets.

Adopt: Anthropic-compatible SKILL.md filesystem skills with a watcher-driven index (Cluster 3); the schema-introspection tool idea — one read-only, policy-scoped query tool over the catalog instead of N hand-registered tools, writes excluded (Cluster 3); agent self-scheduling as a first-class, approval-gated verb (Cluster 3); the L1–L4 memory-tier taxonomy as design input only, not code (Cluster 2).

Why it fits: a well-built personal-scale Ash agent runtime with the opposite trust posture to samen; mine the agent-UX patterns, ignore the architecture wholesale — ReqLLM and Jido are both already-rejected dependencies.

OSA medium

A local-first coding/general-purpose agent (Apache-2.0, 43★, active, v1.0.118) — an Elixir/OTP engine paired with a Rust ratatui TUI, 82 deferred-loaded tools, 27 LLM providers, and up to 16-agent bounded fan-out. A developer tool, not a SaaS substrate: no tenancy, no PII model.

Adopt: the 6-step context-compaction pipeline with priority budget allocation (Cluster 2); complexity-scored model-tier routing with fail-honest fallback chains (Cluster 1); deferred tool loading + tool search to shrink the governed-egress scrub surface (Cluster 4-adjacent); the workspace-trust pattern (untrusted repo-local config until explicitly trusted) mapped onto tenant-authored automations.

Why it fits: an actively maintained Elixir/OTP agent engine worth mining for loop mechanics, but its local-first, ungoverned execution model — shell/file/browser access, "overdrive" yes-to-everything mode — is the philosophical inverse of samen's governed-egress AI plane; adopt patterns, never the trust posture.

Pepe medium

A deliberately database-free agent runtime (MIT, ~253 commits, 6★, one maintainer) — agent definitions as JSON config, OTP process-per-conversation state — speaking the OpenAI Chat Completions protocol across dashboard, API, WebSocket, CLI, embeddable widget, and chat-channel connectors.

Adopt: complexity-based model triage with fail-open fallback and honest failover events (Cluster 1); context-window compaction at ~60% with the documented prompt-cache-reuse tradeoff (Cluster 2); the tool-approval TTL vocabulary (once / this-turn / this-session / permanent) plus surface-aware refusal — headless surfaces deny-by-default for gated tools (Cluster 4-adjacent); directed agent-to-agent ACLs as declarative, tenant-scoped data (Cluster 4-adjacent).

Why it fits: tiny single-maintainer runtime, never a dependency, but a dense catalog of agent-runtime product patterns worth mining — its reversible PII redaction is explicitly weaker than samen's token-blind masking and should not be adopted.

Shem medium

A newly public, single-author BEAM-native agent platform (Apache-2.0, 0★, ~847 commits) built around debuggability: a hash-chained flight recorder, a forensic time-travel WebUI, and install-time "graduation gate" re-verification of third-party tool packs in throwaway containers.

Adopt: deterministic replay of recorded agent-loop runs as a samen.verify.agent_replay-style CI tier (Cluster 4, the section's most differentiated idea); fail-closed declared-action tool manifests with a parity verifier (Cluster 4); offline-verifiable attestation bundles (mix samen.attest-shaped) extending the claim-evidence/audit-chain story; the forensic-UI design register (monospace numerics, integrity badges, zero decorative chrome) as free direction for the operator cockpit, idea only.

Why it fits: pattern mine, not a dependency — 0 stars, single author, pre-1.0 rules out depending on it, but the replay/attestation ideas are on-brand extensions of samen's existing "every guarantee ships with a proof" posture; skip its container tool-sandboxing, which guards an escape hatch samen's ADR-047 AST lock already covers differently.

Vibe medium

An experimental BEAM-native local coding agent (MIT, ~99★, actively developed) that runs as a real OTP application — sessions, jobs, and subagents as supervised, monitorable, cancellable, resumable processes — with a deliberately eval-first control plane (few tools; the model gets a rich Elixir eval context instead).

Adopt: multi-surface attach over one supervised session — TUI and LiveView as adapters — as a live-attach affordance for the operator cockpit (Cluster 4); first-class inspect/cancel/resume verbs on agent runs, mostly wiring existing OTP + AshStateMachine machinery (Cluster 4); "create a skill from session history" as a concrete shape for G22 (Cluster 3); the rules-directory pattern (markdown standing instructions, per-model filtering) as a cheap delta on the existing Prompt resource.

Why it fits: excellent OTP session/subagent supervision and multi-surface attach UX worth borrowing, but its eval-first control plane is the structural opposite of samen's governed-egress AI plane — handing the model an open eval context would un-prove samen's hero claim, so that core idea must never be adopted.

ZAQ medium

A sovereign, self-hosted "company brain" (AGPL-3.0 with commercial dual-license, 66★, active, v0.16.0) connecting org knowledge (pgvector RAG) to configured AI agents with person-scoped permission filtering, multi-channel delivery, and a JSONB-DAG workflow engine — built almost entirely on the already-rejected Jido ecosystem.

Adopt: progressive-disclosure agent skills — index-only in the prompt, full body via load_skill tool call, no-catalog-leak on not-found (Cluster 3, this project's implementation is the most rigorous of the three); the trusted-execution-context identity rule as a verifier — LLM-supplied params must never select the acting identity (Cluster 4); persist-before-deliver ordering as a named, testable rule (Cluster 4); no-answer/low-confidence telemetry feeding an operator-cockpit tile for support/CRM AI surfaces; the atom-safety guard pattern for any runtime-minted atoms.

Why it fits: AGPL-3.0 rules out any code reuse regardless of technical merit, and its all-in Jido dependency list (several pinned to forks/branches) is exactly the fragility INV-4 exists to prevent — but the skills index and identity-rule invariants are free, license-clean ideas worth re-deriving clean-room.

Net read for a product leader skimming only this section: none of these nine are dependency candidates — wrong trust posture, wrong tenancy model, or (ZAQ) copyleft-incompatible — so nothing here changes samen's dependency graph, and every item below is a clean-room re-derivation. What they collectively hand samen is design input at the two places the report currently has the thinnest coverage: the ADR-047 agent loop's cost, memory, and governance mechanics (Clusters 1, 2, and 4 — cost-tier routing and fail-honest budgets, consolidation/compaction/recall under a context budget, and injection/attribution/identity/replay hardening), and the open G22 gap of packaging agent grounding for builders (Cluster 3 — skills as data, plus the self-scheduling verbs that make an agent's own automation proposals a normal E3-approved draft). Effort clusters at S–M throughout, with exactly two L-sized items flagged as future-roadmap rather than now: Ankole's full Dreaming-style consolidation and Long's L1–L4 memory taxonomy. Every adoption, without exception, routes through samen's existing masking chokepoint and E3 approvals rather than adding a parallel path — the one invariant all nine source projects, in their different ways, do not enforce.
