- **Need:** every generated app is English/USD/UTC-only; G24 ("i18n / timezone / currency — USD + UTC hardcoded, no gettext", P2, `docs/saas-gap-roadmap.md:78`) is the largest still-open end-user product gap in the register.
- **Sources:** Craftplan `findings/055-craftplan.md` (ex_cldr+gettext+tz on Ash 3 + ash_money — samen's exact data stack); nyght `findings/057-nyght.md` (fr/de/en production, ex_cldr_plugs locale negotiation, Weblate pipeline, gettext 1.0); Tymeslot `findings/059-tymeslot.md` (gettext+tz at samen's exact Elixir 1.20/Phoenix 1.8/LiveView 1.1 versions, 6 locales); vutuv `findings/078-vutuv.md` (gettext+ex_cldr+ex_phone_number+tz compiled into the release, no runtime network); Nivose `findings/081-nivose.md` + OLI Torus `findings/095-oli-torus.md` (two more production confirmations); Accent `findings/053-accent.md` (Langue Document/Entry/ValueType format-abstraction core as the design reference for the string import/export chokepoint).
- **License:** the *apps* are AGPL (Craftplan/nyght/Tymeslot/Nivose) / MIT (vutuv, Torus) / BSD-3 (Accent) — but they are only evidence of stack choice. The *libraries* to adopt (ex_cldr family, gettext, tz) are permissive Hex deps: importable.
- **Mode:** import (libraries) behind an **adapt** ADR. Seven independent codebases converged on the same stack, so library selection is de-risked — with **one wrinkle the report missed that makes the ADR genuinely load-bearing**: samen's pinned `ex_money 6.1.1` no longer sits on the ex_cldr family — it depends on `localize 0.50` (which itself carries `gettext 1.0.2` + CLDR-derived data; verified in `samen_core/mix.lock:18,24`). The reference apps all run the older ex_money 5.x/ex_cldr lineage. The ADR must rule: localize-first (ride what Samen.Type.Money already ships) vs ex_cldr-first (the ecosystem-proven stack) vs both-with-a-boundary. That is exactly a fable/ADR-level call, not a mechanical adoption.
- **What to build (ADR + phase-1 slice only, per the decompose-cross-cutting-changes rule):** the ADR (locale/currency/timezone as first-class Scope/Org attributes; library ruling above; locale negotiation at the plane routers; gettext extraction policy for samen_web UI kit + generator-emitted apps; Accent-Langue-shaped import/export chokepoint mirroring the RFC-4180 CSV chokepoint discipline; a `verify.i18n`-class tier for bare-string detection) plus a bounded first slice (deps in, `Cldr` backend module, org-level locale/currency/timezone settings resource, `Samen.Type.Money`/Duration render paths locale-aware). The full string sweep is later phased items the ADR enumerates.
- **Effort:** ADR + slice M; full retrofit L (phased).
- **Gap mapping:** G24; WS-C remnants/P2 sweep (`docs/saas-gap-roadmap.md:154-156, 647-649`).
- **Repo evidence it is missing:** zero first-party gettext usage (`grep -rn "use Gettext" samen_core/lib samen_web/lib` → empty); gettext/localize/expo present only as transitive ex_money deps; `attribute(:currency, :string, default: "USD")` in `samen_core/lib/samen/scopes/billing/blueprint.ex:115,460`; `default: {Money, :new!, [:USD, 0]}` in `scopes/crm/blueprint.ex:304`; `attribute(:timezone, :string, default: "Etc/UTC")` in `scopes/calendar/blueprint.ex:89`; no i18n ADR in `docs/adr/` (ends at ADR-047); no i18n item in `_orch/plan/backlog.yaml`.

### 2. Automation run-definition pinning — snapshot-per-run so "edit freely, history stays true"
- **Need:** data-integrity of the shipped ADR-039 automation engine. Verified today: `RunWorker.load_workflow/2` reads the **live** workflow row at execution time and executes `Compile.run(wf.actions, ctx)` where `:actions` is an `{:array, :map}` attribute on the workflow (`samen_core/lib/samen/automation/run_worker.ex:94-106,198`; `scopes/automation/blueprint.ex:105`). Consequences: (a) a tenant edit between event capture and execution — or between Oban retry attempts (max_attempts 3) — silently changes what an already-triggered run executes against the old event; (b) after any edit, a historical `Automation.Run` row's per-action outcomes can no longer be interpreted against the definition that actually ran; (c) a deleted workflow mid-flight is handled (`:workflow_gone` skip) but an *edited* one is invisible. Lightning is the production proof of the fix: every run pins to an immutable workflow snapshot; jobs/triggers can be freely edited or deleted without corrupting in-flight or historical runs (`findings/050-lightning.md` §adopt-1).
- **Source:** Lightning (OpenFn) `findings/050-lightning.md` — LGPL-3.0/GPL-3.0, **patterns only, clean-room**, never code.
- **Mode:** adapt. Composition of machinery samen already owns: the `versioned:` opt-in (ash_paper_trail, ADR-040 §6.2, built in T38/T119) applied to the workflow resource, + `EventCapture`'s same-transaction enqueue as the natural capture chokepoint (stamp the definition — actions array, conditions, resource_key — or its version id/digest into the dispatch args/Run row), + `RunWorker`/`Compile` executing the pinned definition, kill-switch/owner checks staying live-read (a pause must still stop a pinned run). Definition maps are non-PII by schema (NonPiiPredicates write-guard), so this does NOT collide with ADR-039 §13's rejection of snapshot-based *undo* (that rejection is about subject attribute values, INV-1; this is about the workflow definition).
- **Effort:** M.
- **Gap mapping:** ADR-039 §3.3/§8.1 hardening; complements identity-trust's proposed E3 "version-pinned consent" item (that one pins tool/action definitions into *approvals*; this pins workflow definitions into *every* automation run — most runs are not approval-gated). Cross-referenced, not duplicative.
- **Repo evidence:** no `versioned:` on any automation blueprint resource (`grep -rn "versioned:" samen_core/lib/samen` hits only cms + framework files); no snapshot/pin/digest in `run_worker.ex`/`compile.ex`/`dispatch_worker.ex` (grep → zero hits); ADR-039 nowhere addresses edit-during-flight (grep for snapshot/version in the ADR hits only undo-rejection and webhook-payload snapshot tests).

### 3. G19 DSAR self-serve — streamed, schema-versioned export surface over the existing kernel primitive
- **Need:** G19 ("DSAR self-serve + compliance reporting", P2, `docs/saas-gap-roadmap.md:73`). Verified: the kernel primitive is **built and strong** — `Samen.Dsar.export_subject/2` (`samen_core/lib/samen/dsar.ex`, F3.3) walks the subject's vault, is org-bound fail-closed, plane-correct, and refuses to return a bundle it could not audit-log. What does not exist: any web surface (zero DSAR references in `samen_web/lib`), any downloadable artifact (the bundle is an in-memory map; no zip machinery anywhere — `grep zstream|packmatic|zip` over both mix.lock → empty), any export schema versioning, and retention admin.
- **Sources:** Plausible `findings/049-plausible-analytics.md` §adopt-4 (zstream streaming-zip + nimble_csv + multipart upload — export streams, never materialized); Lightning `findings/050-lightning.md` (packmatic streaming-zip DSAR shape — second confirmation of the streamed-zip approach); vutuv `findings/078-vutuv.md` §adopt-1 (`@schema_version` with inline changelog, export registry required to stay in lockstep with deletion, and the test that fails when a new PII-bearing resource joins the catalog but not the export).
- **License:** Plausible AGPL / Lightning LGPL-GPL — patterns only; vutuv MIT — design directly reusable. `zstream` itself is MIT (importable, lives in samen_web per INV-4 — no vendor/HTTP dep needed if the artifact streams straight down the conn rather than to S3).
- **Mode:** adapt. Build: (a) a tenant-plane self-serve surface (settings-adjacent LiveView + download controller mirroring `Samen.Web.Csv.ExportController`'s mount/org posture) streaming a zip of `export_subject/2` bundles — streamed response, never an at-rest artifact, so no new PII-at-rest surface and no files-module interaction; (b) a versioned export schema (vutuv `@schema_version` discipline) auto-derived from the catalog's `pii_declared` metadata, with a catalog-parity test that fails when a vaulted class exists that the export doesn't cover (the same parity-verifier shape as `vault_declared_parity`); (c) the export event already lands on the audit chain (built — O9 precondition). Retention admin stays a separately-judged G19 half (not in this item).
- **Effort:** M.
- **Gap mapping:** G19 / WS-C remnants; directly strengthens `docs/compliance-story.md`'s GDPR Art. 15/20 posture — on-brand for the hero claim.
- **Repo evidence:** `samen_core/lib/samen/dsar.ex` exists (275 lines, operator/tenant-callable API only); `find samen_web/lib -path "*dsar*"` → empty; no zip dep in either lockfile.
