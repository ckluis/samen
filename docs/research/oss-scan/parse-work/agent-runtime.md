# Theme: agent-runtime — ADR-047 agent-loop hardening + foundry dev-process orchestration

Sections owned: `01-02-agent-frameworks-orchestration.txt` (whole), `02-03-software-factories.txt` (whole), `03-04-agent-platforms-license-risk.txt` (Neoharness cluster only), `00-01-executive-summary.txt` (LangChain for Elixir + Sagents cards). All candidates verified against `findings/*.md` and against the samen repo directly.

**The single most important repo finding of this parse**: the assembled report sections systematically UNDERSTATE how much of ADR-047 is already built. Claims in sections 02/03/04 that samen "has no cancellation," "no stall detection," "no provider circuit breaker," "no terminal-state vocabulary," "no checkpoint-backed approval pause/resume," and "no approved-vs-actual binding" are all FALSE against the current repo:

- Durable cancel: `samen_core/lib/samen/ai/agent/run.ex` (`cancel_requested_at`, `Samen.AI.Agent.cancel/2`, re-checked at every turn boundary, cancel valid from `:queued`/`:running`/`:awaiting_approval`).
- Provider circuit breaker + rate trip + host kill-switch + durable per-`{org, agent}` kill rows: `samen_core/lib/samen/ai/agent/breaker.ex` + `kill.ex` (provider trip threshold 5, fail-closed on unreadable kill row, explicit-operator-only re-arm).
- Stall handling: the AshOban `:agent_turn_due` scan (`run.ex` ~L390-420) — never-nil `next_turn_at` invariant means every stalled `:queued`/`:running` run is eventually re-armed; parked runs are swept by the sibling `:agent_proposal_expiry` trigger into an honest terminal `:expired`.
- Checkpoint-backed approval pause/resume: `transition(:park, from: :running, to: :awaiting_approval)` / `:resume` (`run.ex` L73-74) — the BeamWeaver/ElGraph headline pattern already exists as A4's propose-then-approve park, with turn-level checkpointing via `find_or_reuse_turn!/3` (`turn.ex`).
- Approved-vs-actual binding: `write_proposal.ex` carries the validated-args sha256 `args_digest` in bounded meta, with a digest-binding refusal at execution and refusal when a tool is de-registered between proposal and approval.
- Fail-closed declared-action tool manifests (Shem's headline): `tools.ex` — every tool declares `effect: :read | :write`, `effect_for/1` defaults `:write` (fail-closed), unregistered/non-opted-in kind refuses `{:error, :invalid_tools}`, and `mix samen.verify.agent_coverage` checks the declared-tools subset structurally.
- Terminal states: `{succeeded, failed, cancelled, budget_exhausted, expired}` on AshStateMachine — Symphony/Genesis's graceful-vs-forced and Pixir's partial vocab add little that isn't representable today.

What is GENUINELY missing after that audit — verified by grep, not by trusting the report: token streaming (ADR-047 §9#5 explicitly deferred, "needs its own chokepoint contract (a future ADR)"; §11 carries "No token streaming in v1" AND "No live-progress PubSub in v1" as named residuals), trajectory/behavioral regression testing (no hits for `trajector|golden` in samen_core lib/test/ai; `agent_coverage` is structural-only), a duplicate tool-call guard and structured tool-arg error feedback (no hits in `agent/tools.ex`/`turn_worker.ex`), AI-plane telemetry (zero `:telemetry` emission under `samen_core/lib/samen/ai/`), and prompt caching (no `cache_control` anywhere in `samen_anthropic/`). Nothing in `_orch/plan/backlog.yaml` (grepped all 169 titles) covers streaming, trajectory testing, loop guards, or an orch tick.

## 1. Adopt candidates (ranked)

### 1. Trajectory-based agent regression testing (golden tool-call sequences)
- **Foundry need**: samen's "every guarantee ships with a proof" religion applied to agent BEHAVIOR — today a refactor can silently change which tools an agent calls and in what order, and no test flips.
- **Source**: LangChain for Elixir `LangChain.Trajectory` — findings/041-langchain-for-elixir.md (relevance: high). Strict / wildcard / unordered / superset matchers, ExUnit `assert_trajectory`/`refute_trajectory` macros, golden-file round-trip.
- **License**: Apache-2.0 — importable, but **mode: adapt** (ADR-047 is a zero-new-deps loop; the library fails the masking-chokepoint test as a dependency).
- **What to build**: capture a run's tool-call sequence from the EXISTING `Samen.AI.Agent.Turn` log — `tool_kind` + arg key NAMES + `args_digest` are already persisted token-only (`write_proposal.ex` provenance discipline), so goldens are crypto-shred-safe and EG2-clean by construction (a property LangChain doesn't have to solve). Matchers + ExUnit macros in samen_core; `mix samen.gen.agent` emits a golden trajectory test per generated agent; one committed sabotage patch (reroute a tool) proves the tier can fail.
- **Effort**: M. **Gap mapping**: complements WS-D D8/T72 (shipped mask-leak red-team tier covers LEAKS, not behavior pins) and `mix samen.verify.agent_coverage` (structural only). Satisfies the sabotage-ability mandate directly.
- **Missing-evidence**: `grep -rniE 'trajector|golden' samen_core/lib samen_core/test/ai` → zero agent hits; `samen.verify.agent_coverage.ex` checks tool-subset membership, raw-spawn AST lock, and `tool_schema` presence only.

### 2. Token-streaming chokepoint contract with per-delta re-scrub (the deferred ADR)
- **Foundry need**: ADR-047 v1 reports turn-level progress only; every generated app inherits a non-streaming agent surface. Streaming is the single feature the ADR itself names as a future ADR, and six independent projects prove the surrounding plumbing is a solved zero-dep problem.
- **Sources**: streaming-backpressure cluster — Lemon (MIT, findings/044: bounded `EventStream` GenServer, synchronous `push/2` → `{:error, :overflow}`, drop strategies, typed event vocabulary; explicitly "zero-dependency OTP-only, reimplementable inside the kernel without violating INV-4"), Nous (Apache-2.0, 046: pull-based hackney `[{:async, :once}]` with between-chunk cancellation), Alloy (MIT, 034: versioned envelope `%{v, seq, correlation_id, turn, ts_ms, event, payload}`), BeamWeaver (Apache-2.0, 036: typed `%Stream.Envelope{}`, providers refuse raw chunks by pattern-match — samen's own FunctionClauseError trick), Cantrip (MIT, 037: `cast_stream`, events minted post-chokepoint). Plus Sagents (Apache-2.0, 047: field-tested LiveView PubSub event taxonomy — status lifecycle, `llm_deltas`, token-usage, per-tool events), Pixir (MIT, 024: canonical-vs-ephemeral split — deltas broadcast but never persisted, canonical events get monotonic seq, `turn_failed` dedicated, salvaged partials flagged), LangChain (041: MessageDelta merge-function design + its streaming fix history as a pre-paid bug list).
- **License**: all MIT/Apache-2.0. **Mode: adapt** (design synthesis; no code taken).
- **What to build**: the ADR first — the chokepoint grows a streaming contract where EVERY delta re-passes the scrub (the part none of the six solve): provider chunk → `Samen.AI.Chokepoint` per-delta scrub → typed versioned envelope → bounded pull queue → LiveView consumer; ephemeral deltas never persisted, only the merged post-scrub canonical message enters the transcript (preserving the ADR-046 erasure envelope); closes BOTH §11 residuals (token streaming AND live-progress PubSub) in one contract. Then the build, inheriting into `samen_web` AgentLive + `mix samen.gen.agent` scaffolds.
- **Effort**: L (ADR + build). **Gap mapping**: ADR-047 §9#5 TAKEN-deferred ruling + §11 named residuals; EG6 shadow explicitly called out there ("partial deltas would bypass `seal/3`'s whole-payload scrub"). No backlog item exists.
- **Missing-evidence**: ADR-047 lines 624, 688, 751-753; `Samen.Web.AI.AgentLive` re-reads on every navigation (no PubSub, per §10a row 15).

### 3. Agent-loop turn guards + small AI-plane wins pack
- **Foundry need**: cheaper, earlier tripwires than the budget caps (the caps bill a degenerate run before they stop it), plus the two cheapest cost/observability wins the scan surfaced.
- **Sources**: Neoharness — findings/016-neoharness.md (**NO LICENSE FILE — `license: null`, all-rights-reserved despite README MIT claim; patterns only, strictly clean-room**): duplicate tool-call guard (consecutive identical `{kind, args}` → 2nd repeat nudges, 3rd+ blocks with a synthetic tool result; `allow_repeat: true` opt-out for polling tools). LangChain (Apache-2.0, 041): v0.9.6 actionable tool-arg error feedback (name required/missing/unrecognized params from the tool schema so the model self-corrects next turn) + GenAI OTel-semconv spans + Anthropic prompt caching (`cache_control` on chokepoint-minted MaskedPayload system/context segments; Alloy 034 claims 60-90% input-token savings on loop workloads).
- **License**: mixed — Neoharness pattern clean-room only; LangChain Apache-2.0. **Mode: adapt** (all four sub-items are first-party re-implementations; breaker precedent shows where each lives — guard in core loop, caching in `samen_anthropic` only, per INV-4).
- **What to build**: (a) duplicate-call guard keyed on `{tool_kind, args_digest}` (the digest is already computed) with a verifier probe + sabotage; (b) structured arg-error tool results derived from the already-registered tool schema; (c) `:telemetry` events on the `Samen.AI` chokepoint mapped to GenAI semconv spans, content structurally absent (samen already runs opentelemetry with `db_statement` disabled — same posture); (d) `cache_control` support in `samen_anthropic` (adapter-local, fail-honest if unconfigured).
- **Effort**: S per sub-item, M as a batch (samen batches small AI-plane fixes — T147 precedent). **Gap mapping**: ADR-047 §6 budgets ("backstop, not tripwire"), INV-4, cost-cap efficacy.
- **Missing-evidence**: no `duplicate|repeat` guard logic in `agent/tools.ex`/`turn_worker.ex`; `grep -rn telemetry samen_core/lib/samen/ai/` → 1 doc-comment hit only; `grep -rniE 'cache_control|prompt_cach' samen_anthropic/` → empty.

### 4. `mix samen.orch.tick` — claim/reconcile bookkeeping over backlog.yaml (dev-process; the ONE orchestration item)
- **Foundry need**: the recorded `_orch/` failure modes — session limits stranding an agent mid-task, resumes re-running completed work, serialized fan-outs — are all state-bookkeeping failures, not judgment failures.
- **Sources**: Symphony (Apache-2.0, findings/026: SPEC claim machine `Unclaimed → Claimed → Running → RetryQueued → Released`, restart recovery with NO database — re-poll the tracker; stall timeout default 5m; blocked runs stay claimed and visible), Shep (MIT, 025: tracker-as-database, restart re-derives the world; "green means a check reported" — no-report-within-grace = failure), Svärm (FSL-1.1-MIT — **patterns only**, 030: GenServer poll over Tracker/Runner behaviours), ControlKeel (Apache-2.0, 018), Camelot (GPL-2.0 — **patterns only**, 017: adopt-vs-fail `recovery_action/4` for completed-but-unharvested sessions).
- **License**: Apache-2.0/MIT sources carry the whole mechanism; FSL/GPL entries contribute nothing not already in Symphony/Shep. **Mode: adapt.**
- **What to build**: a mix task (foundry-owned, NOT product runtime) that (a) polls `_orch/plan/backlog.yaml`, resolves `blocked_by`, and prints/records the claimable set; (b) maintains a single-authority claims file (item, session-id, claimed_at) so a resumed session adopts completed-but-unharvested work instead of re-running it; (c) flags stale claims past a stall timeout as stranded (the resume digest, mechanized). It does NOT launch sessions, does NOT gate, does NOT auto-merge — the human-launched adversarial process stays exactly as deliberate as it is.
- **Honesty note**: this is the weakest of the four and the first to cut against the cross-theme budget. The pain is real and recurring across BATON runs, but the mitigation is S-sized bookkeeping, and the deliberate human-gating limits how much a tick can ever buy. Proposed at S-scope only; the Symphony full-service shape (L) is explicitly rejected.
- **Effort**: S–M. **Gap mapping**: `_orch/` conventions (foreground gates, serialize-fan-outs, resume-only-stragglers); "encode knowledge as infra" house rule.
- **Missing-evidence**: `_orch/` contains plan/tasks/verify state but no claim ledger and no tooling (`ls _orch/` → directive.md, manifest.json, plan/, tasks/, verify/ — no scripts).

## 3. Explicit discards
- **All eight agent frameworks as dependencies** (Alloy, BeamWeaver, Cantrip, Condukt, ElGraph, Legion, Lemon, Nous): every one fails the masking-chokepoint test that sank ash_ai/Jido (ADR-037) — raw-string provider paths, most pull ReqLLM/HTTP toward core (INV-4), BeamWeaver adds a Rust NIF (`fastest_tiktoken`). Value is pattern-only, captured above.
- **Sagents direct-execution-on-approval**: an approved tool executes directly there; adopting the execution model would regress "AI writes do not exist" — only the decision UX transfers.
- **Sandboxed LLM-authored code** (Cantrip Dune port-isolation, Legion Lua, Condukt microVM ladder): samen has no code-execution tool and no roadmap line asking for one; L-effort gated on a feature that doesn't exist. Legion's AST-denylist diff vs samen's raw-spawn lock is a free 30-minute audit, not a backlog item.
- **Shem declared-action manifests / Symphony-Pixir terminal-state taxonomies / BeamWeaver-ElGraph checkpoint-resume / Neoharness cancel+breaker / CYFR-style args binding**: already built (repo citations in the preamble) — the report sections' biggest systematic error.
- **Symphony full orchestrator service (L)**: unattended burn-down contradicts the deliberately human-gated adversarial process; only the S-sized bookkeeping slice (item 4) survives.
- **Neoharness MCP client pool, Horde clustering, hot code reload, SQLite/Mnesia/DETS stores, ReqLLM anywhere**: each violates a named invariant (Postgres-only, INV-3 full-gate, INV-4).
- **Shep "green means a check reported"**: right idea, but it targets GitHub PR checks — samen's gates run `./ci.sh` foreground inside the session (recorded convention); nothing to build, worth one line in `_orch/directive.md` at most.
