**Repo ground truth established first (what the AI plane already ships):**
- Per-run fail-honest budgets ARE built: `max_turns` / `max_tool_calls` / `max_input_tokens` / `max_output_tokens` / `deadline_seconds` + consumption counters on the Run row, explicit `:budget_exhausted` terminal state (`samen_core/lib/samen/ai/agent/run.ex:148-168,316-322`), rate trip 60 runs/org/hour counted from the run log, per-`{org, definition}` durable kill rows + host kill switch (`agent/breaker.ex`, `agent/kill.ex`). ADR-047 §9#3 TAKEN.
- Metadata-only AI logging IS the standing contract: EG6 (ADR-043 §3.2b / ADR-047 §6) — the one terminal log line is "ids, enums, counts — token-only, never prompt/completion text" with a named A1 no-text-in-logs test asserting on exactly that line (`agent.ex` `log_terminal/1`, ~line 2108); the T72 red-team tier passes only at zero canary plaintext and zero `vt_*` in "any log line, telemetry event" (ADR-047 §-red-team); provider errors normalize content-free `{:provider_error, provider}`; otel `db_statement` disabled.
- Declared-tool manifests ARE built: the four-way narrowing intersection (registry ∩ opt-in ∩ declared ∩ actor-policy) with fail-closed `:tool_refused` (`agent/tools.ex`).
- Actor identity is structural: tools execute AS the run's owner actor; "the chokepoint never elevates, substitutes, or synthesizes an actor (INV-2)" (`agent/tools.ex` arm 4) — LLM args cannot select the actor.
- What is genuinely ABSENT (greps: `spend|price|pricing|usd|daily`, `tier|rout`, `memory|consolidat|decision.graph`, `skill` over `samen_core/lib/samen/ai/` → zero relevant hits): any cost/dollar dimension (no rate map, no per-org spend cap, no alert threshold — budgets are counts, not money); any model tier routing (`samen_anthropic/lib/samen_anthropic/provider.ex:37` pins `@default_model "claude-opus-5"`; every call pays flagship price); any cross-session/structured reasoning memory (the loop persists ONE artifact — the vault-routed transcript, 90-day shred); any skills concept (Prompt resource = name/version/body only, `ai/prompt.ex`); embedder version metadata on vector rows (`embeddings.ex` `store_vector/7` — no model/version column).

## 1. Adopt candidates (ranked)

### 1. AI spend governance at the chokepoint: rates-as-data + tri-state budget refusal + declared tier routing
- **Foundry need**: every generated app inherits an AI plane whose only cost controls are per-run count caps. Nothing prices a dispatch, nothing aggregates org spend across runs, nothing alerts before a hard stop, and every call — a one-shot triage classify or an 8-turn agent run — goes to the same flagship model. This is the AI-plane instance of samen's own fail-honest doctrine: today an unpriced dispatch "succeeds" with unattributed cost, which is exactly the fake-success shape ADR-014/024/026/038 exist to refuse.
- **Sources**: Glorbo — `findings/003-glorbo.md` (tri-state `BudgetTracker.check_budget/1` `:ok` / `{:alert, used, cap}` at 80%, deduped via restart-rehydrated `alerts_fired` / `{:stop, used, cap}` hard refusal; a provider whose usage can't be attributed is refused at dispatch unless `allow_untracked_budget: true` — greppable risk opt-in; per-model rate map as data in config). AlexClaw — `findings/000-alexclaw.md` (DB-backed provider/tier registry, ETS+DB usage counters keyed `{provider, date}`, step > workflow > global tier-override hierarchy). OSA — `findings/005-osa.md` (complexity-scored three-tier ladder utility/specialist/elite). Pepe — `findings/006-pepe.md` (one-shot triage classifier downgrades a whole session to the cheap model; explicit failover events — substitution never silent).
- **License**: Glorbo MIT OR Apache-2.0; AlexClaw Apache-2.0; OSA Apache-2.0; Pepe MIT — all clean. **Mode: adapt** (chokepoint-side logic in `samen_core`; rate values and any HTTP stay out of core per INV-4).
- **What to build**: (a) rates-as-data — an effective-dated `{provider, model} → {input_rate, output_rate}` table (the ADR-036 effective-dated posture; catalog-as-data discipline), host-supplied, never baked into the adapter; (b) per-dispatch cost attribution folded from `%Completion{}.usage` (already returned per call) into insert-only usage facts; a dispatch against a model with no rate entry is refused fail-honest unless explicitly opted in (Glorbo's discipline verbatim); (c) a per-org monthly tri-state check evaluated at the chokepoint BEFORE dispatch — `:ok` dispatches, `{:alert, used, cap}` dispatches + notifies once (dedup), `{:stop, used, cap}` refuses honestly (`{:error, :ai_budget_exhausted}`), operator-clearable like the kill rows; (d) declared tier routing — verbs/agent definitions declare `tier: :light | :standard | :heavy`, the chokepoint resolves tier→model from host config so triage stops paying `claude-opus-5` price. Mid-stream failover chains deliberately OUT of v1 (one real adapter exists; silent substitution is the named anti-pattern) — Pepe's explicit-failover-event vocabulary is the recorded design for when a second adapter lands. Sabotage: flip the `:stop` refusal → named test fails.
- **Effort**: M. **Gap mapping**: extends ADR-047 §6/§9#3 (per-run caps) to the org/month cost dimension it deliberately left open; fail-honest doctrine (ADR-014 family); adjacent to T152's "wire a key → real value" complaint. Distinct from the G13/Osmotic usage-rating item (billing TENANTS for product usage — another theme); this governs the operator's own AI bill. If both land, the insert-only-ledger shape should be shared.
- **Repo evidence of absence**: `grep -rn -iE 'spend|price|pricing|dollar|usd|daily' samen_core/lib/samen/ai/` → 1 hit, a moduledoc word in `health.ex`; budgets in `run.ex` are token/turn counts; `provider.ex` behaviour has no model-selection seam; `samen_anthropic/provider.ex:37,69` static model from config. No backlog item touches routing or spend (T63–T72, T134–T155 reviewed).

### 2. Decision-graph agent memory as an Ash resource family (ADR-first)
- **Foundry need**: ADR-047's loop has transcripts + retention but zero structured, queryable reasoning memory — a run's "why" evaporates into a vault-routed text blob. A token-only decision graph gives every generated app agent runs that explain themselves, gives the operator plane a genuinely new surface, and unifies approvals with reasoning (an E3 decision becomes an outcome node) — all inside the masking chokepoint and erasure envelope, which no source project even attempts.
- **Sources**: Loomkin — `findings/021-loomkin.md` (relevance: **high**; the exec-summary card is this theme's). 7 node types (goal/decision/option/action/outcome/observation/revisit), 7 typed edges (`leads_to`/`chosen`/`rejected`/`requires`/`blocks`/`enables`/`supersedes`), per-node confidence 0–100 with `upstream_uncertainty` cascade down `requires`/`blocks` edges, pulse reports over stale/low-confidence regions, context_builder injecting active goals + recent decisions under a token budget, approvals logged as outcome nodes. Ankole — `findings/001-ankole.md` (recall recipe as design reference: RRF fusion of keyword+vector routes, exponential temporal decay with a knowledge floor, per-candidate token caps in a global budget — portable onto existing pgvector + tsvector, zero new infra; ParadeDB not needed).
- **License**: Loomkin MIT, Ankole Apache-2.0 — but Loomkin is built on Jido (ADR-037/jido-eval REJECTED), so **mode: adapt** — clean-room patterns regardless of the permissive license; no code translation.
- **What to build**: ADR first (this is a new AI-written persistent substrate — the erasure questions are the hard part), then the resource family: org-scoped nodes/edges written by the loop at turn boundaries from already-rendered token-only material (node text passes the same `vt_`-free rendering discipline as transcript lines; ADR-047 §10a row 9 precedent), retention-spec'd like transcripts (the ADR-046 §7#5 third-party-free-text boundary must be ruled on for graph nodes explicitly), injected into prompt assembly through the existing D9 grounding path — grounding is already chokepoint-scrubbed (T136 closed that seam). Recall = RRF over pgvector + non-PII tsvector. Writes to the graph are the LOOP's own bookkeeping (like Turn rows — not tenant-visible side effects), so they ride the loop's provenance, not E3; anything the graph proposes back into the product remains a draft through E3. Operator surface: the graph read-only on the run detail page.
- **Effort**: M–L (ADR + resource family + injection + recall). **Gap mapping**: no G-number — this is the "structured reasoning memory" hole ADR-047 leaves between transcript (opaque) and RunRecord (bounded outcomes); the exec-summary Loomkin card names it; roadmap theme "packaging the agent-grounding differentiator".
- **Repo evidence of absence**: `grep -rln -iE 'memory|consolidat|decision.graph' samen_core/lib/samen/ai/` → zero; `run.ex` moduledoc confirms the transcript is "the run's ONE persisted text artifact".

### 3. Skills-as-data with progressive disclosure — the G22 grounding-packaging shape
- **Foundry need**: G22 (P2, open: "agent-grounding packaging … differentiator built but unpackaged for builders"). Samen has catalog-as-data for SCHEMA grounding but nothing for packaging agent INSTRUCTIONS: a builder's only options today are the compile-time `goal_prompt` heredoc or the bare Prompt resource. Three scanned projects converge on the same fix for prompt-bloat + discoverability: index-only in the system prompt, full body pulled on demand.
- **Sources**: ZAQ — `findings/009-zaq.md` (the rigorous one: skills as DB records name/description/body/tool-keys; system prompt carries name+description index only — O(count) tokens; `load_skill` tool returns the body, scoped to the agent's own enabled skills; not-found NEVER enumerates the catalog — an explicit info-leak fix; write-time byte/token caps + truncation guard). Long — `findings/004-long.md` (Anthropic-compatible SKILL.md authoring format — YAML frontmatter + markdown; watcher-driven index; per-member vs promoted-to-global scoping). Vibe — `findings/008-vibe.md` (skill-from-session-history distillation, versioned).
- **License**: ZAQ **AGPL-3.0 — patterns only, clean-room, no code**; Long MIT; Vibe MIT. **Mode: adapt.**
- **What to build**: a `Samen.AI.Skill` resource beside Prompt (name, description, body, tool-key hints; versioned via the Prompt resource's writable?-false version discipline); agent definitions declare enabled skills; prompt assembly injects the index only; `load_skill` ships as a governed read tool through the normal four-way narrowing (the body re-enters as EG2 tool-result egress — already re-scrubbed per turn); skill bodies are EG5 authored artifacts (`vt_`-free validation, the `use Samen.AI.Agent` goal_prompt precedent); not-found is a bounded error that names nothing; tenant-vs-operator scoping rides the existing two-plane model; `mix samen.gen.agent` emits a skill scaffold and imports/exports SKILL.md as the on-disk interchange format (DB stays truth — no filesystem-as-truth). Session→skill distillation (Vibe) only as an E3-approved draft, never auto-trusted. Agent self-scheduling verbs (Ankole `check_back_later`, Long `createScheduledTask`, Glorbo heartbeat grooming) are the natural v2 of the same surface — thin wrappers over Oban/ash_oban/ADR-039, agent-PROPOSED and E3-approved; recorded here, not a separate item.
- **Effort**: M. **Gap mapping**: G22 direct (`docs/saas-gap-roadmap.md:76`). **Repo evidence of absence**: `grep -rln -i skill samen_core/lib/ samen_web/lib/` → one false positive (`support_operator.ex`); `ai/prompt.ex` is name/version/body only.

## 3. Explicit discards
- **`samen.verify.ai_log_shape` as a new verifier tier (Codex Pooler, Elastic-2.0)** — ALREADY BUILT as the EG6 contract: metadata-only is not a convention to codify but a tested invariant (ADR-043 §3.2b; `agent.ex` `log_terminal/1` "ids, enums, counts — token-only" + the A1 no-text-in-logs test; T72 red-team pass criterion "zero `vt_*` in any log line, telemetry event"; content-free provider errors; otel `db_statement` disabled). The report section's S-effort claim ("codifying an existing posture") confirms the value already lives in samen. Residual delta = one annotation (§4). This is the section's instance of the systematic-understatement error the audit warned about.
- **Glorbo per-dispatch egress attribution token** — largely built: `Run.origin` ("user:<id>" | "workflow:<id>" | "agent:<run_id>") + `depth` + `chain` plus per-turn rows already give per-dispatch provenance (`run.ex:163-167`); a proxy-stamped ephemeral token adds a carriage mechanism, not a capability.
- **ZAQ LLM-params-never-select-actor rule as a new verifier** — structural today: tools execute as the run's owner actor under real policies; "the chokepoint never elevates, substitutes, or synthesizes an actor (INV-2)" (`agent/tools.ex`). There is no code path by which a model arg selects an actor, so a verifier would assert the absence of a seam that doesn't exist.
- **ZAQ persist-before-deliver ordering** — vacuously satisfied: v1 has no push delivery at all (no PubSub, no channel connectors; `AgentLive` re-reads after persistence — ADR-047 §10a row 15). Nothing to encode until a delivery surface exists.
- **Shem declared-action manifests / Neoharness cancellation + breaker / checkpoint-resume** — already built (`tools.ex` four-way intersection; `cancel_requested_at` + `kill.ex` + `breaker.ex`; turn-row cursor); the agent-runtime theme reached the same verdict. Shem replay + Pepe failover surfaces belong to that theme and are not claimed here.
- **OSA 6-step compaction / Pepe 60%-compaction / Ankole Dreaming as standalone items** — compaction is folded into the agent-runtime theme's streaming/loop-v2 ADR scope (their rank-6 note; any fold output is EG2 egress needing the chokepoint, per both themes' analysis); Dreaming is L-effort, single-user provenance, and premature while runs are 8-turn/90-day-shred bounded. Study-only, referenced from item 2's ADR.
- **Loomkin keeper-style full-fidelity context offload** — structurally incompatible: full-fidelity ETS/Redis context stashes live outside the DEK envelope, defeating crypto-shred and the destruction oracle, and "zero loss" retention is precisely what the masked-only posture forbids. The value lives in unbounded single-user coding agents.
- **OSA deferred tool loading + tool_search** — solves an 82-tool catalog problem samen structurally doesn't have: the four-way narrowing yields small per-agent tool sets by construction.
- **Long introspectable single data tool** ("one GraphQL-ish tool over the whole data layer") — the inverse of the narrowing-intersection posture: a universal query tool re-widens what four arms deliberately narrow; schema awareness already flows through D9 catalog grounding, and builder-side browse/search already exists in the MCP server (T69).
- **Pepe tool-approval TTL vocabulary (once/turn/session/permanent)** — "once" is exactly today's per-proposal distinct-human semantics; the longer grades are auto-approval, which regresses the deliberately-attended §9#1 posture. Pepe's headless-deny half is moot (no headless agent surface exists).
- **AlexClaw capability-token attenuation** — depth cap + chain provenance already on the Run row (`@max_agent_depth`, raw-spawn AST lock in `agent_coverage`); HMAC capability carriage adds no power to a policy-checked actor model.
- **All nine products as dependencies** — single-user trust postures throughout; Jido (Long, ZAQ, Loomkin-adjacent) and ReqLLM stacks already rejected (ADR-037, `_orch/jido-eval-report.md`, INV-4); ZAQ additionally AGPL-3.0.
- **Pepe tenant-facing spend metering surface** — the tenant-billing half of usage belongs to the G13/Osmotic direction (another theme's scope); only the operator-side governance half is kept (item 1).
