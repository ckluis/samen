# Theme: billing-metering — usage metering/rating, Stripe sync, entitlements, spend receipts

Sections owned: the Osmotic card in `00-01-executive-summary.txt`, the G13 cluster (Azimutt + Wanderer) in `08-09-quick-hits.txt`, and ONLY Svärm's cost-receipts/budget-hold/ROI line in `02-03-software-factories.txt` (Svärm's orchestrator shape belongs to agent-runtime; the tri-state AI-budget item belongs to ai-governance and is NOT duplicated here).

**Repo ground truth established first — the G13 "stub" framing is stale.** The digest ("Stripe sync is a stub (`SyncAdapter.Stub`)"), the gap register (`docs/saas-gap-roadmap.md:66`), and the spec (`spec/full-saas-readiness.md:71` "sync is a stub") all describe a state the T18–T26 + T106/T108 builds have since replaced:

- `Samen.Scopes.Billing.SyncAdapter.Stub` was **deleted** and superseded by the fail-honest `Samen.Billing.Provider` behaviour — the supersession is documented in `samen_core/lib/samen/billing/provider.ex:24-30` ("The old `SyncAdapter.Stub` always returned a fake `{:ok, %{stub: true}}` — the tautological-success shape ADR-014 abolished").
- `SamenStripe.Provider` is a **real implementation**, not a skeleton (its moduledoc header "SKELETON" is a stale T18-era label — see annotations): real webhook signature verification with 5-min replay tolerance (`do_verify_and_parse`, `samen_stripe/lib/samen_stripe/provider.ex:224`), real checkout-session creation (:330), real billing-portal sessions with a hardcoded name/email-only customer-sync whitelist (:403), real subscription/customer/invoice fetch (:471/:492/:516), real cancel/change with proration opts (:596/:624), real metered-usage reporting (:547), allowlist payload redaction (`@safe_keys`), and a bounded vendor-event→`ProviderEvent` kind map. The ONLY `:not_implemented` capability is `fetch_object(:payment_method_summary, ...)` (:166) plus the honest no-webhook-secret refusal (:210).
- The HTTP layer is real: `SamenStripe.Transport.live/1` does actual `Req` dispatch to `api.stripe.com` with Bearer auth and Stripe's `Idempotency-Key` header for usage batches; every callback accepts an injectable `config[:transport]` so CI runs **fixture-transport cassettes** with zero network/credentials — exactly the samen_anthropic posture the theme brief demanded. Only the live smoke lane (`STRIPE_TEST_KEY`) remains operator-gated.
- **Azimutt's "revalidate the plan on every webhook event" pattern is already built, stronger**: `Samen.Billing.Reconciler` calls `fetch_object` (authoritative provider re-fetch) on EVERY verified webhook event and upserts the mirror from the returned snapshot, "NEVER from the event payload directly" (`provider.ex` `fetch_object` doc; `reconciler.ex`), with an idempotent `{:ok, :duplicate}` replay gate and an out-of-order watermark that discards strictly-older events (`{:ok, :stale}`, `reconciler.ex:32,138`) — a discipline Azimutt does not have.
- Production Ash-backed mirrors exist for subscription/checkout/invoice/dunning/usage (T108; `samen_core/lib/samen/billing/ash_*_mirror.ex`, `*_mirror.ex` ports, honest `Fake*` doubles), plus a subscription-movement MRR ledger with a disclosed going-forward-only day-one backfill (`movement_backfill.ex`).
- Entitlements exist and are checked **locally, fail-closed**: `Samen.Scopes.Billing.Entitlement.entitled?/4` — missing/ungranted/expired row ⇒ `{:ok, false}` (`samen_core/lib/samen/scopes/billing/entitlement.ex:28-30`), with a direct-Ecto hot path. The plan/entitlement editor shipped (F7, `docs/saas-gap-roadmap.md:570-576`) with a fail-closed feature-key allowlist; billing LiveViews cover overview/plans/invoices/dunning/settings (`samen_web/lib/samen/web/billing/`).
- Usage **reporting** exists end-to-end: Usage blueprint resource → `UsageMirror` port → `UsageReporter` batch pull of `reported_at IS NULL` rows → `report_usage/2` with per-record idempotency keys → mark-reported only after provider success (no-data-loss contract) → `UsageReportWorker` (Oban, host-opt-in cron).

**What is genuinely absent** (greps over `samen_core/lib` + `samen_web/lib`):
1. **Nothing writes usage rows.** `grep -rn 'record_usage\|Meter\|metering'` → zero capture code; the Usage resource ships default `create: :*, update: :*` actions with **no idempotency-key attribute, no uniqueness identity, no insert-only discipline** (`scopes/billing/blueprint.ex:634-700`) — a host retrying an event write double-counts, and a `:member`-role actor can mutate `quantity` after the fact. There is no tally/quota helper joining usage to entitlements, and no tenant-facing usage surface (`grep -i usage samen_web/lib/samen/web/billing/*.ex` → one moduledoc cross-ref in `settings_live.ex:268`).
2. **Local rating/proration/tax is absent BY DESIGN, not by gap**: `proration_amount_cents: … MIRRORED from the provider, never computed` (`billing/mirror.ex:54`); Stripe rates, samen mirrors. Osmotic's effective-dated local pricing table must NOT be imported for tenant money — it would break the mirror doctrine. (The operator's own AI bill is different and already owned by the ai-governance theme's rates-as-data item.)
3. **No mirror-staleness policy.** Convergence is purely event-driven; there is no periodic true-up sweep (`grep -i 'sweep\|drift\|periodic' billing/` → only the day-one `MovementBackfill`), no surfaced last-event watermark, and no documented rule for what entitlement checks mean when the webhook feed is silently broken (rotated secret, dead endpoint): mirrors drift indefinitely and `entitled?` keeps answering from stale rows forever. T151 already records one concrete fail-open edge (nil `period_end` → `expires_at: nil` → entitled INDEFINITELY, `entitlement.ex:100`). Wanderer's fail-open ("can't reach billing") vs fail-closed ("billing said no") split is exactly the policy statement missing here — transposed to samen it becomes a *staleness* policy, since samen never calls the provider at check time.

## 1. Adopt candidates (ranked)

### 1. Idempotent insert-only usage-metering capture substrate (`Samen.Billing.Meter`)
- **SaaS-foundry need**: every generated app inherits a complete usage *reporting* pipe (mirror → reporter → Stripe idempotency keys) but no way to *capture* usage: no chokepoint writes usage rows, the ledger is mutable, and a retried capture double-bills the tenant once live keys land. This is the samen-side half of G13's "usage rating" that needs **no Stripe credentials** — capture, immutability, tallies, quota checks, and tenant-visible receipts are all keyless-buildable; only the final rate-into-dollars stays mirrored from the provider.
- **Source**: Osmotic — `findings/108-osmotic.md`. License **BSD-2-Clause** (MIT-compatible), but 0-star/7-commit early-stage ⇒ **mode: adapt** (pattern, never a dependency).
- **What to build**: (a) a capture chokepoint `Samen.Billing.Meter.record/3` in samen_core — caller supplies `{org, subscription, metric, quantity, event_ref}`; the idempotency key derives from `event_ref` (Osmotic's UUID-key discipline), landing via an upsert action with a uniqueness identity + `on_conflict: :nothing` so crash-and-replay cannot double-count; (b) harden the Usage blueprint: add the `idempotency_key` attribute + identity, drop/lock the default `update: :*` action (insert-only fact table — the audit-chain/insert-only precedent samen already lives by; ADR-002 ethos), keeping `reported_at` marking as the one sanctioned mutation through the existing mirror port; (c) period tallies as a *set rebuild from source* at rollover (Osmotic's crash-safe tally rule), not an additive counter — reusing the `Samen.Rollup` recompute-from-source machinery; (d) `within_limit?(org, metric, opts)` joining tallies to entitlement limits (numeric quotas currently have no typed home — Plan.features/`custom` are untyped maps, `blueprint.ex:321,921`); (e) a tenant-facing usage panel on the existing billing LiveView surface showing per-metric tallies and honestly-labeled "estimated" spend receipts (the one Svärm idea not already owned by ai-governance — receipts surfaced in *billing*, `findings/030-sv-rm.md` item 2, FSL ⇒ pattern-only); (f) sabotage patch: break the idempotency identity → named double-count test must fail. **Explicitly out of scope**: local money rating/proration/tax (mirror doctrine, `mirror.ex:54`), and the effective-dated *pricing* table for tenant billing (demoted — see discards).
- **Effort**: M. **Maps to**: G13 (usage-rating half, `docs/saas-gap-roadmap.md:66`), ADR-038 §3.1 (report_usage + idempotency-key rule — capture side currently unprotected), WS-B B8 (T25 built the outbound half only). Coordinate with ai-governance item 1: their AI-spend facts and this ledger should share the insert-only + idempotency-key shape (their file says the same).
- **Repo evidence of absence**: `scopes/billing/blueprint.ex:687-689` (`defaults([:read, :destroy, create: :*, update: :*])`, no identity, no idempotency attribute); zero hits for a capture writer in core/web/verticals (driftwood/pawchart billing modules reference Usage only via seeds); `usage_mirror.ex:36-37` ("No host currently wires `:billing_usage_mirror`").

### 2. Billing-mirror trust boundary: staleness sentinel + documented fail-open/fail-closed policy (ADR-038 addendum)
- **SaaS-foundry need**: samen's entitlement checks are local-mirror-truth (correct — Wanderer's cached-row pattern, already stronger because no runtime provider call exists to fail). But the design's honest weakness is undocumented and unmonitored: if webhook ingress silently breaks, every mirror (subscription, invoice, dunning, entitlement) drifts stale forever with no signal, and the framework nowhere states which surfaces fail open on staleness (feature access keeps working — availability) vs fail closed ("billing said no" — dunning/expiry). This is precisely a fail-honest policy decision in the ADR-014/024/026/038 lineage, and Osmotic independently demonstrates the same discipline (a written per-control fail-open/fail-closed matrix).
- **Sources**: Wanderer — `findings/097-wanderer.md` item 2 (MIT; the "can't reach billing" vs "billing said no" split); Osmotic — `findings/108-osmotic.md` item 3 (BSD-2-Clause; controls matrix stated as policy). **Mode: adapt/study** — this is mostly an ADR plus a small build.
- **What to build**: (a) ADR-038 addendum stating the per-surface rule: entitlement gating fails OPEN on staleness within a bounded grace window and names the window; dunning/expiry transitions fail CLOSED (only provider-confirmed state moves money-adjacent state); (b) a staleness sentinel: persist a per-org (or per-host) last-verified-event watermark (the Reconciler already computes watermarks per object — surface the max), and raise an operator-plane warning + notification when orgs with revenue-active subscriptions have seen no verified billing event beyond a threshold; (c) surface the watermark on the existing billing `settings_live.ex` honest-empty-state page; (d) an optional host-opt-in periodic true-up sweep (same posture as `UsageReportWorker`: NOT in `default_crontab/0`) that re-runs `fetch_object` over revenue-active subscriptions — the convergence primitive already exists, only the sweep is missing; (e) close T151's nil-`period_end` → entitled-indefinitely edge under the same ADR language (cite it as the first instance of the undocumented rule).
- **Effort**: S–M. **Maps to**: G13 hardening half; ADR-038 §3.4 convergence; T151's recorded fail-open edge; T26/B10 settings surface.
- **Repo evidence of absence**: no periodic reconcile sweep (`grep -irn 'sweep\|periodic\|stale' samen_core/lib/samen/billing/` → only the event-watermark `{:ok, :stale}` discard in `reconciler.ex` and the day-one `movement_backfill.ex`); no staleness/heartbeat concept in `webhook_dispatch.ex`; no fail-open/fail-closed statement in ADR-038-adjacent moduledocs; `entitlement.ex:100` treats `expires_at: nil` as entitled with no staleness qualifier.

- **Svärm budget hard/hold modes + tri-state refusal** — owned and already proposed by the ai-governance theme (AI-spend governance at the chokepoint + T155 tenant-surface annotation); duplicating it here would burn a cross-theme slot on the same build.
- **Svärm ROI dashboard ($/merged, merge-rate)** — dev-process/cockpit metric over coding-agent runs, not billing substrate; belongs (if anywhere) to agent-runtime/cockpit-v2, and FSL forbids anything beyond clean-room concepts anyway.
- **stripity_stripe as a dependency** (Azimutt's stack) — samen's INV-4 posture already solved this correctly: the vendor SDK surface samen needs is small and hand-built over `req` in `samen_stripe` with cassette transports; importing a community Stripe SDK would widen the wire surface the allowlist-redaction + snapshot tests currently pin.
