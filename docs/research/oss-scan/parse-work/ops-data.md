**Corrections to the assembled report (systematic understatement, confirmed again in this theme):**

1. **"Samen's fleet is push-only, a wedged heartbeat job reads healthy" is FALSE on both counts.** ADR-044 §4.2 defines **mode A pull**: the cockpit is the client and probes `GET /fleet/health` on a 60s interval with a signed shared-secret handshake (`samen_core/lib/samen/fleet/registry.ex:71-185` — `issue_probe_credential`, `fetch_probe_secret`, `:fleet_probe` capability); unreachable ⇒ `{:error, :unreachable}`, tile reads `unreachable · last seen …`, excluded from roll-ups (ADR-044 §"cockpit configured for pull, app unreachable"). And push-mode (mode B) staleness is computed **cockpit-side** from `received_at + stale_after_s` (default 300s, `fleet/registry.ex:640-683`) — a wedged heartbeat renders `stale`, never healthy. Dead-man's-switch semantics are BUILT. What is genuinely missing from G11 is only the **public status page** (grep: zero hits for `status_page|StatusPage` in samen_web/samen_core; `docs/saas-gap-roadmap.md:64` — "public status page still open").
2. **"Single-sink wide-event exporter" is understated.** `Samen.WideEvent.Sink` is already a behaviour (`samen_core/lib/samen/wide_event/sink.ex`) with THREE adapters (`sinks/{in_memory,file,otlp}.ex`), telemetry-handler attach (inherent fan-out), and per-sink retention config. Logflare's "Adaptor registry" adds essentially nothing; a webhook/Slack operator-alert sink would land as a fourth adapter with zero registry work.
3. **"libcluster closes the multi-node Oban gap" misreads the gap.** T90 (shipped, `docs/runbooks/multinode-oban-proof.md`) proves Oban multi-node needs **no BEAM clustering at all** — coordination is Postgres (`Oban.Peers.Database`, `FOR UPDATE SKIP LOCKED`, `Oban.Notifiers.Postgres`); the two `:peer` nodes never form a distributed-Erlang cluster. BEAM clustering is only needed for cross-node Phoenix.PubSub/LiveView, and that is **already planned**: `docs/plan.md` K4 names `dns_cluster`/libcluster + PubSub in the deploy component; production wiring rides the credential-gated T91 Fly BLOCK.
4. **KMS rotation is designed and runbooked but NOT mechanized — the delivery-egress grep was right.** `Samen.Kms` behaviour (`samen_core/lib/samen/kms.ex:91-134`) has callbacks for generate/unwrap/shred/attest/backups_disabled?/key_material_present?/pseudonym — **no rotate/rewrap callback**. `FileBacked` holds a single `master.key` (`kms/file_backed.ex:61-98`), no key ring. ADR-001 §2.1 specifies "master keys rotate on schedule; rotated masters retained unwrap-only" — unimplemented. `docs/runbooks/secrets-rotation.md` §3 concedes it: re-wrap is a hand-planned online migration, "run it in a mode that accepts both keys during the transition … **if the adapter supports it**" — it does not. (Distinct from ADR-044's deliberately-removed fleet `POST /fleet/rotate` — that is fleet credentials, a settled rejection; do not conflate.)
5. **Sequin's watermark backfill targets a layer samen deliberately does not own.** `docs/cdc-analytics-tier.md`: the CDC transport to ClickHouse is delegated to **ClickPipes/PeerDB** (which do their own snapshot+stream coordination); samen's load-bearing mechanism is `Samen.Cdc.Projection` (column-level default-deny) + `LocalPostgres` sim + `ClickHouse` skeleton. ADR-007's RollupRefreshWorker also EXISTS and is wired into `default_crontab/0` (`samen_core/lib/samen/jobs/rollup_refresh_worker.ex`); the deferred part is the `:source` generalization for domain-sourced vertical rollups (deferred on extract-on-3rd grounds, per the ADR — a correctness call, not a gap a Sequin pattern fixes).
6. **aud_event partition lifecycle is covered**: partitioned table + `Samen.AuditEvent.PartitionManager` with erasure-window-gated detach (`audit_event/partition_manager.ex`); T128 adds auto-roll to `default_crontab/0`. Wide events are NOT Postgres-persisted (ring buffer / JSONL file / OTLP — no DB sink), so "partition-drop for wide events" has no table to apply to. Remaining high-churn rows (notifications, RunRecords, ADR-046 transcripts) go through the opt-in row-sweep `Samen.Retention.SweepWorker` — adequate at current volume, and the `:shred` action is per-subject, which partition-drop cannot express.

## 1. Adopt candidates (ranked)

### 1. Public status page on the fleet substrate (G11 close)
- **Need**: the single literally-open line of G11 — a publicly-viewable, masked/token-blind status surface (per-app up/degraded/unreachable, uptime + incident history) for operators' products; every generated app + the cockpit inherit it.
- **Source**: Health (`findings/103-health.md`) — AGPL-3.0, **patterns only, clean-room**; its status-page feature and push/pull duality. Supporting: AetherS3's candid component-level readiness reporting (`findings/098-aethers3.md`, MIT).
- **Mode**: adapt (feature, not transport — samen has LiveView + two-plane masking; skip Health's SSE/Datastar, Bandit-no-Ecto stack, YAML config, ICMP raw sockets).
- **Build**: a public (unauthenticated, rate-limited, fail-secure) samen_web surface rendering fleet-derived status: mode-A probe results + mode-B staleness labels + `/readyz` component detail for the embedded app; uptime history persisted token-blind (app_id/slug + bounded enums only — never tenant identity); operator controls for what is published (masked-by-default, publish-is-opt-in per app); generator emits the route. Do NOT rebuild probing — mode A pull, `stale_after_s`, and `Fleet.Attention` already provide dead-man + flood-vs-stale semantics (correction #1).
- **Effort**: M. **Gap**: G11 (`docs/saas-gap-roadmap.md:64` "public status page still open"). **Evidence missing**: no `status_page`/`StatusPage` anywhere in `samen_web/lib` or `samen_core/lib`; `Samen.Web.Readiness` is a probe, not a page.

### 2. Real `Storage.S3` + AetherS3 as the keyless local/CI target (WS-E follow-on close)
- **Need**: files substrate that actually stores bytes on S3-compatible storage, CI-provable with zero cloud credentials (T88/T89/T91 keyless-buildable rule).
- **Source**: AetherS3 (`findings/098-aethers3.md`) — **MIT, importable as a fixture** (docker-compose service; never a samen dependency). Craftplan (`findings/055-craftplan.md`, AGPL) independently shows the waffle+MinIO local-dev shape — MinIO is the fallback fixture if AetherS3's S3-API coverage (SigV4, multipart, range) proves insufficient; AetherS3 preferred (MIT, BEAM-native, honest-limitations README).
- **Mode**: import (fixture) + adapt (the adapter code is samen's own).
- **Build**: implement `put/get/delete/presign_get` in `Samen.Files.Storage.S3` per the module's own stated plan — SigV4 over OTP `:httpc`, web-dep-free (ADR-026 ratified: no ex_aws/req/finch in the tree; the design decision is already made). Add an AetherS3 docker-compose fixture + an opt-in CI tier (mirror the `SAMEN_MULTINODE=1` posture) exercising real byte round-trip + presign + the fail-honest unconfigured path; keep `{:error, :not_configured}` semantics.
- **Effort**: M (fixture wiring alone is S; SigV4 + adapter + red-paths is the M).
- **Gap**: WS-E follow-on "real `Storage.S3` + `Scanner` impls" (`docs/saas-gap-roadmap.md:157,652`) — named in the roadmap but **no backlog T-item exists** (grep of `_orch/plan/backlog.yaml`: only T88's Object-Lock runbook). **Evidence missing**: `samen_core/lib/samen/files/storage/s3.ex` is an explicit fail-honest skeleton — `put/3` "NEVER returns `{:ok,_}` because no byte is ever actually stored".

### 3. KMS master-key rotation choreography (rotate = key-ring + resumable re-wrap)
- **Need**: turn secrets-rotation.md §3's hand-planned "unwrap with OLD, wrap with NEW, write back" migration into first-party mechanism, so master-key compromise/migration is a drill, not an outage risk.
- **Source**: Logflare key-ring `default/retired/fallback` + `do_migrate/0` (`findings/104-logflare.md`, Apache-2.0); Wanderer primary+fallback decrypt window (`findings/097-wanderer.md`, MIT); Tymeslot `credential_reencryption` resumable Oban workers + stale-key-row queries (`findings/059-tymeslot.md`, **AGPL — clean-room pattern only**).
- **Mode**: adapt. ADR-003 rejected Cloak itself — only the rotation choreography transfers, applied to `Samen.Kms` (per-subject DEKs are never rotated, ADR-003: destroyed not rotated; this is strictly the master/wrap layer).
- **Build**: key-ring in the adapters (current master + retired masters held **unwrap-only**, exactly ADR-001 §2.1's spec); a rotate operation (operator-plane, E3-approvals-gated — NOT app-initiated, per the ADR-044 §4.5 self-takeover lesson); a chunked, resumable Oban re-wrap worker over the wrapped-DEK store with a stale-key-version query + progress attestation; `km_version` (already in the attestation type, `kms.ex`) reports which master wraps each subject; a verifier/red-path proving a retired master can unwrap but never wrap, and that `SAMEN_KMS_KEY_ID` cutover with un-rewrapped DEKs is refused/loud, not a silent fail-closed outage. Update secrets-rotation.md §3 to point at the mechanism.
- **Effort**: M. **Tier**: opus (touches the vault trust kernel; adversarial gate mandatory).
- **Gap**: WS-L real-infra hardening; ADR-001 §2.1 (designed, unimplemented); `docs/runbooks/secrets-rotation.md` §3 ("if the adapter supports it" — it doesn't). **Evidence missing**: no rotate/rewrap callback in `Samen.Kms` (`kms.ex:91-134`); `FileBacked` single `master.key`; repo-wide grep for rotation code hits only fleet-credential and session paths.

## 3. Explicit discards

- **Sequin watermark-coordinated backfill + Postgrex replication-slot tap**: value lives in owning the WAL transport — samen deliberately delegates that to ClickPipes/PeerDB (`docs/cdc-analytics-tier.md` §1, §6) and keeps its guarantee at `Samen.Cdc.Projection` (column-level default-deny). Hand-rolling a slot processor re-litigates a shipped design for zero guarantee gain. Study-only if a first-party mirror transport is ever ADR'd.
- **Sequin Broadway per-key-ordered sink pipelines**: canonical OTP answer to a throughput problem samen does not have (fan-out is discrete Oban jobs; no measured backlog). Study, revisit when throughput demands; would live in samen_web/adapter package only (INV-4).
- **Logflare Adaptor sink registry**: already built in substance — `Samen.WideEvent.Sink` behaviour + 3 adapters + telemetry fan-out + per-sink retention (correction #2). Single-chokepoint emit is deliberate; no registry needed.
- **Logflare AlertQuery in-product cron alert engine**: G11's alerting shipped deliberately as metrics-egress + `docs/runbooks/alerts.md` (Prometheus-side catalog with event-based fallbacks) — the honest seam for a foundry with no hosted pager. An in-product engine is a real future product surface but maps to no named gap; the shape (stored query + Oban cron + threshold + notify through existing sinks, fail-honest on unconfigured target) is recorded here for when it does.
- **libcluster_postgres as a new item**: BEAM clustering is only needed for cross-node PubSub (not Oban — correction #3) and is already planned (K4/T91). Downgraded to an annotation.
- **Supabase Realtime partition-drop retention**: aud_event already partitioned with gated detach; wide events have no DB table; row-sweep retention handles the rest and is the only shape compatible with per-subject `:shred`. Pattern noted for future volume (annotation), no item.
- **Supabase Realtime per-tenant rate counters**: overlaps billing-metering's proposed insert-only usage-metering ledger (their Osmotic item) and ai-governance's budget item; ADR-047 budgets + Automation Health/Breaker already exist. Ceded.
- **Supabase Realtime as a component / RLS-authz seam / gen_rpc / forked Phoenix**: raw-JSON-to-clients violates INV-1/7; LiveView+PubSub in-process covers samen's realtime; RLS seam = study-only if tenant-facing subscriptions ever ship (route channel-join through Ash policies + OrgScope at one subscribe chokepoint).
- **Plural Console pull/reverse-tunnel fleet stance**: value is a stance samen already ruled on — ADR-044 honest degradation is settled, and the app-initiated directive pull is an explicit operator-confirmed "not built, settled decision" (ADR-044 §7.5, ruling 2026-08-06). Validation, not action. prom_ex: convenience dep over already-emitted `:telemetry`; hand-built metrics + `metric_labels` verifier stand; note-only. Multi-channel notification fan-out: a future `samen_slack`/`samen_teams` adapter-package shape, no current gap.
- **ServiceRadar**: pure validation of the Ash-brain-plus-satellites posture samen already holds (ADR-037). Discard. Rustler/NIF precedent noted for a hypothetical compiled evaluator — nothing on the roadmap.
- **Health pull-mode DNS/TCP/SMTP synthetic probe subsystem**: mode-A HTTP pull covers the practical outside-in need for registered apps; a general synthetic-monitoring subsystem (L effort, raw sockets, its own storage) is a monitoring product, not foundry substrate.
- **AetherS3 `/ready` vs `/ready/cp` split**: samen's `/readyz` already reports per-component (`:repo`/`:kms`/`:oban`) fail-closed; the CP split earns its keep only with a consensus layer samen doesn't have.
- **vutuv blue/green deploy script**: T91's Fly rolling-deploy recipe is the deploy story; vutuv's invariants list (backward-compatible migrations, health-gated cutover, single-flight lock) is already embodied in K1/K4 + rollback.md. One-line crib for a future non-Fly deploy doc; no item.
- **GitBlixt Swarm+Caddy PaaS / per-MR preview envs**: real architecture work with no named gap; idea-bank only.

## 4. Annotation recommendations

- **T91 (L5 Fly deploy BLOCK, credential-gated)**: when wiring K4's clustering for production PubSub, evaluate **libcluster_postgres** (Supabase Realtime's production strategy, `findings/052-supabase-realtime.md`) alongside `dns_cluster` — node discovery through the one piece of infra samen already requires, no DNS/K8s dependency; verify the hex package's license at adoption (repo states Apache-2.0). Also record explicitly (from T90's proof) that **Oban needs no BEAM clustering** — clustering is for PubSub/LiveView only; this keeps a future operator from over-provisioning.
- **T88/T92 runbooks (`backup-cadence.md`, restore path)**: add GitBlixt's two restore-safety lines (`findings/085-gitblixt.md`, AGPL — doc content, no code): (1) any backup-encryption envelope key is shown once at enable-time with an explicit off-server-storage warning; (2) restore REQUIRES carrying over the KMS key material / `SECRET_KEY_BASE` or vaulted columns are unrecoverable — state it as a named precondition, not a surprise.
- **T128 (aud_event partition auto-roll)**: annotate with the Supabase Realtime partition-drop retention precedent (`findings/052-supabase-realtime.md`) — if ADR-046 transcripts or automation RunRecords ever reach volumes where row-sweep retention hurts, daily-partition + drop is the O(1) pattern, compatible with crypto-shred only for `:delete`-class (token-only) rows, never `:shred`-class.
- **Wide-event observability guide**: record that a webhook/Slack operator-alert sink is a fourth `Samen.WideEvent.Sink` adapter away (Logflare Adaptor precedent, `findings/104-logflare.md`) — no registry work required; any such sink stays fail-honest on unconfigured target.
