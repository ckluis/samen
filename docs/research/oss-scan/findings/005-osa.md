# 005 — OSA (Optimal System Agent)

## What the project is

OSA is a local-first coding/general-purpose agent: an **Elixir/OTP engine** (`lib/optimal_system_agent/`, app `optimal_system_agent`, Elixir ~> 1.17) paired with a **Rust ratatui TUI**, communicating over HTTP + SSE on `127.0.0.1:9089`. Apache-2.0, ~784 commits, v1.0.118, active in 2026 (43 stars — small but real). Built by the MIOSA team on a "Signal Theory" framing: every inbound message is classified into a 5-tuple `(Mode, Genre, Type, Format, Weight)` that routes work across a three-tier model ladder (utility 0.00–0.35 / specialist 0.35–0.65 / elite 0.65–1.00) spanning 27 LLM providers with automatic mid-stream fallback chains.

Feature surface: 82 built-in tools (deferred-loaded, discoverable via `tool_search`); multi-layer memory (SQLite+ETS long-term with relevance scoring, episodic per-session, typed "vault" fact store, filesystem skills with auto-learning); MCP as **both client and server** (user/project/local config scopes); pluggable sandbox backends (MIOSA, E2B, Vercel, Docker, host) behind a dangerous-command guard; 18 sub-agent roles with ETS mailboxes running parallel/pipeline/debate/review-loop patterns up to 16-agent bounded fan-out; a 6-step context-compaction pipeline; workspace-trust gating of repo-local config; durable goals that survive context resets. Module tree confirms breadth: `agent, budget, context_mesh, mcp, memory, permissions, sandbox, security, signal, skills, swarm, teams, tools, verification, workspace`, etc. Deps are plain-Elixir (req, mint, bandit/plug, ecto_sqlite3/postgrex, phoenix_pubsub without Phoenix, burrito for single-binary) — no Ash, no Phoenix web.

It is a developer tool (a Claude Code-class terminal agent), not a SaaS substrate. There is no tenancy, no PII model, no policy layer in samen's sense — "permissions" means interactive ask/auto-edit/plan/overdrive modes.

## What samen could adopt

- **Context-compaction pipeline for the ADR-047 agent loop.** What: OSA's 6-step pipeline — micro-compact old tool results, strip/merge tool args, structured 8-section compression, 413-recovery collapse, post-compact reinjection of critical context — plus priority budget allocation (critical unlimited / high 40% / medium 30% / low rest). Why it fits: samen's durable multi-step loop (ADR-047) retains transcripts under an erasure envelope but has no long-horizon compaction story; long agent runs will hit context limits, and a staged, deterministic compaction is testable/sabotage-able in samen's style. Constraint: every compaction/summarization pass must route through the masking chokepoint (compaction is itself EG2 egress). Effort: **M**.
- **Complexity-scored model-tier routing.** What: classify each AI request to a weight and route cheap/fast vs full-reasoning models; fallback chain on rate-limit. Why it fits: samen already has budgets/cost caps and a provider behaviour; a router in the AI kernel choosing model-by-task-weight cuts cost across CRM/support/analytics AI surfaces without touching the chokepoint contract. Fallback must stay fail-honest (exhausted chain returns `{:error, ...}`, never silent degradation). Effort: **M**.
- **MCP client (not just server) in Elixir.** What: OSA is a working Apache-2.0 reference for an Elixir MCP *client* — discovery, scoped config (user/project/local), tool invocation. Why it fits: samen ships an MCP server but agents cannot consume external MCP tools; if that ever lands, it must sit inside the EG2 governed-egress class (tool defs/args/results scrubbed), and OSA's `mcp/` dir is the closest Elixir-native prior art to crib transport/protocol plumbing from. Effort: **L** (governance dominates the code).
- **Deferred tool loading + tool search.** What: exclude tool definitions from prompts until matched by a search step. Why it fits: samen's tool defs are governed egress — fewer defs in-context means smaller scrub surface, lower cost, and better tool-choice accuracy as `mix samen.gen.agent` output grows. Effort: **S**.
- **Workspace-trust pattern for untrusted config.** What: OSA refuses to honor repo-local `.osa/settings.json` until the directory is explicitly trusted (hostile-repo defense). Why it fits: samen's automation engine executes tenant-authored automations; the "config is untrusted input until explicitly trusted/reviewed" stance maps to tenant automation definitions and is cheap to state as an invariant + verifier. Effort: **S**.
- **Durable goals with stall auto-pause.** What: goal tracking that survives context resets and pauses (rather than spins) on stall. Why it fits: samen's Automation.Run/agent RunRecord already has bounded outcomes; an explicit stall-detection → pause → operator-notification path strengthens the honest-degradation story. Effort: **S/M**.

## What to ignore and why

- **The trust/execution model wholesale.** OSA runs shell commands, edits files, and browses on the host with interactive permission modes ("overdrive" = yes-to-everything). Samen's AI plane is the structural opposite: AI writes do not exist, side effects go through E3 approvals, egress is chokepoint-masked. Nothing in OSA's permission layer should replace that.
- **Sandbox backends (E2B/Vercel/Docker/host) and erlexec PTY shells.** Samen agents don't execute arbitrary code; adopting code-execution sandboxes would be a new product decision, not a pattern import.
- **Rust TUI, burrito single-binary packaging, warm local daemon.** Samen is a hosted LiveView SaaS substrate; local-first delivery mechanics are irrelevant.
- **Swarm/teams/16-agent fan-out, "soul"/personality modules.** ADR-047 deliberately locked raw spawns out (AST lock) and kept a single governed loop; multi-agent debate patterns would need their own ADR and today would just widen the egress surface. Signal-Theory branding is marketing scaffolding, not mechanism.
- **SQLite+ETS memory stack and filesystem skills as-is.** Samen's grounding is the catalog + pgvector inside Postgres with erasure-envelope compliance; a second memory store outside the vault/crypto-shred perimeter would break the destruction oracle. The *idea* of typed fact extraction may inform G22 (agent-grounding packaging), but the storage design cannot be imported.
- **27-provider matrix.** Samen's fail-honest, one-adapter-per-package posture (samen_anthropic) is the point; breadth-first provider support contradicts INV-4 discipline for no current benefit.
