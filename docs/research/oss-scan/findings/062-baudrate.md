# 062 — Baudrate

## What the project is

Baudrate is an ActivityPub-federated bulletin board system (threads, hierarchical boards, DMs, polls, moderation queue) built on **Elixir 1.15+ / Phoenix 1.8 / LiveView 1.2 / PostgreSQL 15+**, with Rust NIFs (Rustler) for untrusted HTML/feed parsing and Tailwind+DaisyUI for UI. Active (pushed 2026-08-16, ~1,187 commits, 12 stars, not archived), AGPL-3.0, single maintainer (hiroshiyui). Notably it is a fellow AI-assisted repo — CLAUDE.md/AGENTS.md/GEMINI.md plus `.claude/skills/` and `.codex/skills/` are committed — and it carries an unusually disciplined `doc/adr/` set (22 ADRs), a SysOp guide, Ansible deployment, and Wallaby browser tests. No Ash, no Oban: plain Ecto contexts with facade modules and authorization enforced at the context boundary (ADR-0002/0016).

Stack highlights vs samen: same Phoenix/LiveView/Postgres/Hammer-7/nimble_totp/req base, but hand-rolled contexts instead of Ash, a hand-rolled DB delivery queue instead of Oban, and Rust NIFs where samen deliberately stays NIF-free.

## What samen could adopt

1. **SSRF-safe, DNS-pinned single egress client** (ADR-0007). One `HTTPClient` for ALL outbound HTTP: HTTPS required, resolves the host, rejects private/loopback/link-local/reserved IPs, then **pins the connection to the validated IP and sets the Host header itself**, closing the DNS-rebinding TOCTOU gap; response size capped; even non-federation POSTs (Web Push) must use it. Why it fits: samen already worships chokepoints (`Samen.Delivery.Chokepoint`, AI egress chokepoint) but its webhook delivery to tenant-supplied URLs and any future link-preview/feed fetching are classic SSRF vectors the digest does not show a rebinding-proof answer for. This is exactly a "one place to audit" INV-style invariant, and it composes with a `samen.verify.*` tier (AST-lint that no module calls `Req` directly outside the chokepoint — samen already does this style of lock for AI raw-spawn). Effort: **M** (client + IP-pinning + verifier tier).
2. **Operator "sudo mode" — step-up re-verification for privileged surfaces** (ADR-0009). Admin routes check a `verified_at` timestamp; older than 10 min ⇒ redirect to a re-verify page accepting TOTP or WebAuthn; 5 failures lock verification without dropping the session; the privileged live_session boundary forces a full page load so the cookie is re-read. Why it fits: samen's operator plane and especially the **reveal-grant flow** are ideal step-up points — "second-party approval + fresh second factor" is strictly stronger than approval alone, and it slots into the existing identity spine. The redirect-loop and websocket-vs-plug pitfalls are already documented in the ADR. Effort: **S/M**.
3. **WebAuthn/FIDO2 second factor via `wax_` (+`cbor`, QR via `eqrcode`)** (ADR-0009). Samen's spine has TOTP + vaulted recovery codes only. Hardware-key support is table stakes for the security-first positioning samen sells, and Baudrate proves the wax_/LiveView integration shape (including coexistence with TOTP and role-mandated enrollment: 2FA *mandatory* for admin/moderator roles — an idea samen could apply to operator-org memberships). Effort: **M**.
4. **First-run claim gate: setup wizard + `INSTALLATION_KEY`** (ADR-0021). Fresh instance ⇒ whoever hits `/setup` first becomes admin; gate it with a pre-shared env key, answer 503 on all routes until setup completes, duplicate the gate in LiveView `mount/3` (websocket bypasses the plug), and **never** enforce via a `runtime.exs` raise (bricks a configured instance during a transient DB outage). Why it fits: `mix samen.gen.app` emits running products that will be deployed to public hosts; the deploy-to-setup race window applies verbatim to every generated app. Effort: **S** (generator template + plug + mount guard + red-path test).
5. **Rate-limiter failure-mode doctrine + `RealIp` fail-closed** (ADR-0012). Deliberately asymmetric: the Hammer/ETS limiter **fails open** (a crashed mitigation must not take the site down) while `RealIp`/`trusted_proxies` **fails closed** (unset ⇒ loopback only, `[]` ⇒ trust nobody — `x-forwarded-for` is attacker-writable). Plus a `RateLimiter` behaviour with a `Sandbox` test adapter. Why it fits: samen has Hammer on auth+webhook ingress but the digest records no trusted-proxy/real-IP posture, and "written-down failure modes per control" is exactly samen's fail-honest ethos. Effort: **S**.
6. **Progressive per-account login delay instead of hard lockout** (ADR-0008 tail). 5s/30s/120s at 5/10/15+ failures per hour, layered on per-IP limits — avoids the "attacker locks out the victim" DoS of hard lockouts. Drop-in policy tweak for samen's login flow. Effort: **S**.
7. **Session-token hygiene details** (ADR-0008). Samen already has server-side sessions with listing/revocation/org-cap eviction; Baudrate adds three refinements worth cherry-picking: store only **SHA-256 hashes** of tokens (DB dump yields no usable sessions), **dual token + 24h rotation** bounding stolen-cookie lifetime, and the documented `phx-trigger-action` pattern for cookie writes from LiveView. Effort: **S** each; verify first which samen already does (only the eviction/listing behavior is attested in the digest).
8. **Total-i18n discipline as the G24 playbook** (ADR-0019). Samen's G24 (i18n/tz/currency) is an open gap. Baudrate's rules are the useful part: no bare user-visible strings ever (including `title`/`aria-label`/flash/feed metadata), gettext interpolation only (never Elixir interpolation into msgids), shared `translate_role/1`-style enum helpers, locales kept in sync in the same change, and a fixed per-locale terminology table. This converts G24 from "add gettext" into an enforceable convention samen could back with a verifier (bare-string lint). Effort: **L** (retrofit across samen_web + UI kit), but the *doctrine* is S to write down now so new surfaces don't deepen the hole.
9. **Bounded hostile-fetch walking** (ADR-0007 tail) — if/when samen agents or enrichment fetch attacker-influenced URLs (link unfurls in chat, agent web tools): ≤N hops, ≤M distinct hosts, visited-URI cycle guard, and rate limits keyed on the **target** host as well as the sender, so many hostile senders cannot combine against one victim. Effort: **S** as a design rule recorded in the AI-plane ADRs.

## What to ignore and why

- **ActivityPub federation itself** (WebFinger, HTTP Signatures, actor keys, inbox/outbox, media proxy): the raison d'être of Baudrate, irrelevant to a multi-tenant SaaS foundry. The only transferable residue is the egress-client pattern, captured above.
- **DB-backed delivery queue instead of Oban** (ADR-0013): right call for a one-job-type single-node BBS, wrong for samen, which has Oban pinned, ash_oban integration, same-transaction enqueue patterns, and multi-node :peer proofs. Nothing to unwind.
- **Rust NIFs for untrusted parsing** (ADR-0005, rustler/mdex/image): samen deliberately avoids NIFs (simple_sat chosen precisely for no-NIF); adding a Rust toolchain to the foundry contradicts its portability posture. If samen ever needs HTML sanitization, revisit — but as an adapter package, never in core (INV-4).
- **TotpVault/KeyVault AES-256-GCM with config-held keys** (ADR-0010): samen's vault is strictly stronger (per-subject keys in external KMS, crypto-shred, verifier parity). Nothing to learn except the confirmation that config-keyed encryption is the floor, not the ceiling.
- **Soft deletion, ETS settings caches, context facades, Tailwind/DaisyUI pipeline**: samen already has better-governed equivalents (ash_archival with cascade + restore, first-party UI kit + token CSS, Ash domains).
- **License**: AGPL-3.0 vs samen's MIT — every adoption above must be a clean-room reimplementation from the ADR's *ideas*; no code or doc text can be copied.
