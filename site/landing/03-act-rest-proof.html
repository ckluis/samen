Billing, the unglamorous correct part

A seam is only proven by vendors that disagree at the most awkward layer, inbound webhook authentication. Postmark uses Basic-Auth, SES uses SNS with RSA certificate chains, and Resend uses Svix HMAC with its own replay window. All three pass one shared, non-vacuous conformance suite, and a sabotage proves the suite can fail.

13Sabotage & mutation

A test that can't fail is a bug.

Each guarantee ships with a sabotage: a committed patch that breaks exactly that behaviour. The harness applies it, demands that the named tests fail (not just that something breaks), reverts, and checks the tree is restored byte for byte. Then a mutation gate asks the converse: what break did nobody think to sabotage?

{{SABOTAGES}}committed sabotages, replayed on every PR where they touch the diff and in full every night. counted from the tree
  • {{MUT_CORPUS_MUTANTS}} mutants across {{MUT_CORPUS_TARGETS}} targets, enumerated from the AST, each run against only its owning tests
  • A survivor fails the build until a test kills it or a ledger row proves it can't matter
  • {{VERIFIERS}} verifiers check structure the tests can't: no PII columns, catalog parity, fleet wire…

13Proof
Close ✕

Proving the proofs

A test suite can be large and still prove nothing. The sabotage count is the number that carries weight, because each one is a demonstration that a specific test notices a specific break.

A sabotage, mechanically

  1. The patch carries a header: the app, the test files, and the literal names of the tests that must fail
  2. Apply it to a clean tree
  3. Run the named tests: they must fail, by name; "something else broke" doesn't count
  4. Revert, then check every touched file's SHA-256 against the original
  5. New sabotages must anchor: they have to attack code the change actually added, or a double sweep rejects them

Agents add sabotages with scripts/sabotage new, which refuses one that can't flip, breaks the build instead of a test, or names its test with string interpolation the harness can't find.

The mutation gate

Sabotages prove the guarantees someone thought to claim. The mutation gate enumerates four operator families (equality, relational, boolean operators, boolean literals) from the AST and splices each mutant at an exact line and column. A watch-list of {{MUT_WATCH_MODULES}} chokepoint modules ({{MUT_WATCH_MUTANTS}} mutants) runs on PRs; the full corpus ({{MUT_CORPUS_MUTANTS}} mutants) runs as a soak. A compiler refusal isn't a kill; only a named test failure is.

The verifiers

{{VERIFIERS}} mix samen.verify.* tasks check what tests can't express, for example: no plaintext PII in any tier, no PII or card-number columns, catalog and vault-declaration parity, same-org foreign keys, the API contract, the AI prompt masking and agent coverage, the fleet wire, the replay schema.

14CI for agents

Verdicts, not logs.

This codebase is written by AI agents, so its CI is built for them: cheap, fast and mechanical. quick during a round, pr before a pull request, full nightly. Every call fits a single tool call, ends in one verdict line, and resumes where it stopped.

0.4seconds for quick when nothing changed, because every step is cached by the content it reads. A failure is never cached. measured
